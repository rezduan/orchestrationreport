## 2. Findings

### R29-01 — LOW — Incorporated §11.85 still justifies K21's meaning by object absence, the pattern R27-04/R28-04 removed elsewhere

**Where:** §11.85 (incorporated by reference, so current text), "K21's meaning checked", third bullet:
> "H5, H6a, H6b, H7 and H10a alone: true, because nothing of C's object survives."

**Evidence:** §11.86's corrected text (R27-04) rejects exactly this reasoning: "was 'because C's object is not at the branch end', false when C's object reappears under another kind — for example C turns text p into a symlink to 'target' and the branch turns it back into a regular file whose bytes are 'target': same blob, class 6." Revision 29's own §11.85 class 6–7 row now says "the blob itself may be the same".

**Counterexamples:**
- **H10a (class 6):** R27-04's own case. C's blob ("target") is at the branch end as a regular file.
- **H5 (class 1):** Pre is a regular file with blob X. C turns p into a symlink whose target bytes are X (same oid; content(Pre) = (text, X) ≠ content(Post) = (symlink, X)). The branch restores Pre, so End = Pre and blob X is present.
- In both cases "nothing of C's object survives" is false at blob level, while K21's meaning ("no C-opaque content change survives unchanged") stays true by content.

**Impact:** no outcome or caveat effect; K21's verdicts stand. But it is a presence/absence justification in the current text that does not follow from the states, so R28-04 is only partly carried through. The §11.128 scan used fixed strings ("C's object is not", "bytes are not") and missed this phrasing.

**Smallest correction:** replace the clause with "true, because content(End) ≠ content(Post): by content, C's result does not appear as C left it (C's blob may reappear under another kind)".
- Optionally, FX-K21j's "C's binary change is gone" could become "C's kind change does not survive (kind(End) = text)". That is optional: the existing wording is defensible as a statement about the change, not the bytes.
