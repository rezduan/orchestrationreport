## Findings

### HIGH

**R7-01: State 4 accepts a removal that the integration itself never applied. This gives a false MERGED in ancestry-merge mode.**

- **Section:** §1.7.3 (j_inc, state 4, the "Why Tip" rationale) and §1.8.1.
- **Evidence:**
  - j_inc is defined as "Σ min(S_R, max(0, Tn − Tip))".
  - State 4 reads "sufficient iff **j_inc = 0** ∧ b = B".
  - The rationale says "Removals are judged against the integration point because the target cannot lose a line it never had."
  - N-9 reviews Tip only for ancestry-direct.
- **Counterexample** (`git merge -s ours`, or a manual conflict resolution that keeps target-side lines):
  - Setup: T and C's base both contain line L in file f. C removes L, so Pre=1 and Post=0. P = merge(P^1, P^2 = C) keeps P^1's f unchanged.
  - Graph checks: C ⊑ P^2 and C ⋢ P^1, so the line is ancestry-merge with Tb = P^1, Tip = P and End = C.
  - Content arithmetic:
    - Tb(L)=1, Tip(L)=1, Tn(L)=1.
    - S_R = min(1, 1−0) = 1, so J = 1 and K = B = 0.
    - j_abs = 0 and j_inc = min(1, max(0, 1−1)) = 0.
  - State 4 is therefore sufficient.
  - PR: blob(P^1,f) = blob(P,f), so paths_reverted = 0 and K19 does not fire.
  - Events: u_I is NULL and u_C is non-NULL, so K15 does not fire. There are no later records, so K18 and K26 do not fire.
  - Output on Φ-fresh: **MERGED K23, recommend=yes, caveats=-**. CV1 needs basis=added and CV2 needs j_inc>0, so neither fires. C's change is not in T and never was.
- **Asymmetry:** additions are checked against Tb (k uses Tn − Tb). The same `-s ours` merge of an additive C therefore gives K22. Revision 6's "absent relative to Tb" rule returned AMBIGUOUS here, so this is a regression introduced by the R6-01 fix.
  - For squash, pid equality with S^1→S means the removal did land.
  - For ancestry-direct, Tip = C, so it lands by construction.
  - Only ancestry-merge is unsound.
- **Impact:** a false-positive MERGED with recommend=yes and no caveat. This is exactly the overclaim that B-08 and the content check exist to prevent.
- **Smallest correction:** add a landing condition to state 4, and report it for state 3:
  - define j_land = Σ min(S_R, Tb) − Σ min(min(S_R, Tb), max(0, Tb − Tip));
  - require j_land = 0, meaning every target-held copy that C removes is gone at Tip.
  - This keeps FX-K23ab/ac (where Tb=0 makes the requirement vacuous) and the "Tb=2, Pre=1" example. It rejects the counterexample above.
  - Add a fixture FX-K22i (`merge -s ours` of a removal-only C, expecting K22) and correct the rationale text and N-9.

- **Counterexample:** set `remote.origin.url = .` (or the repo's own absolute path) with the OMS refspec, then run `git fetch origin`.

- **Impact:** a false freshness/T basis is reachable with ordinary configuration, without any forgery.
- **Smallest correction:** add an R-row (INSUF, `nonstandard-origin-url`) when norm(remote.origin.url) is a local path, `file://` or `.`. Also add a limitation L-15: "origin identity (canonical vs fork) is not verified". Optionally, the owner pins the expected origin URL.

**R7-08: The freshness grammars are internally inconsistent.**

- **RA vs WF.** WF accepts `fetch origin --prune` and `fetch origin -p`. RA does not, because src "must not start with `-`" and options are only allowed before `origin`. The same reflog message is accepted by F and rejected by R.
- **F12 is unreachable even if P-12 is adopted.** P-12 admits `--all` only "with a single remote", so with two remotes F11 (step 11) fires first and F12 (step 12) never does. FX-F12a's if-adopted expectation "R6/F12/Cb7" is therefore wrong.
- **No fc-row → FHSTAT mapping.** No normative table maps each fc row to its FHSTAT token; F17 has two tokens and the selection rule is only partly stated.
- **Cb is not total once G-F opens.** The Cb table has no R8 × F-POS row (Cb6 covers only R6 and NONE).
- **Correction:** align RA and WF, define the F12 trigger independently of WF, and add the mapping table and the missing Cb row.

**R7-09: The source of configuration values is ambiguous.**

- §1.6.1 says inputs are "taken from snap0 bytes", while C05 reads `config --list`.
- If the helper parses config bytes itself, a parser differential (subsection case, escapes, continuation lines) could misjudge OMS or the URL.
- **Correction:** specify that values come from git's `config --get-all` / `--list -z` output, guarded by the snapshot.

**R7-10: The argv grammar is under-specified.**

- It does not say whether an option value may begin with `-` or `--`. For example, `--repo --now` could be A02 or A08.
- It does not say whether `merge-status` counts as a positional.
- PV-15's totality claim is therefore not established.

**R7-11: Minor items.**

- **Event kind.** The event kind is undefined when e ∈ U ∩ Rv. This is contrived but possible through a conflict-resolved merge. Define precedence, for example revert first.
- **Clock sampled before snap0.** A fetch that completes between the clock sample and snap0 yields CONTRA `future`. This fails closed, but the reason is misleading and is not covered by D02.
- **CV1 with J=0.** CV1 fires when J=0 and prints "removed_lines_absent=0/0", which is harmless noise.
