### 1.2 Inputs

**Argument model**
- argv[0] is the program name and never a positional.
- `--` ends option parsing.
- A value-taking option consumes the next element verbatim, even if it begins with `-`.
- Any other element beginning with `-` is an unknown option (A08). Everything else is positional.
- Options:
  - `--repo <path>`
  - `--now <TS>`
  - `--trace-argv <path>`
  - `--expect-origin <url>` [P-25 · PDB: not accepted → A08; if adopted: accepted, see R10 row]

**Phase A rows** (first match wins, in this order):

| Order | Row | Condition | Result |
|---|---|---|---|
| 1 | A08 | Unknown option; value-taking option as last element; `--opt=value`; `--now` or `--trace-argv` repeated | bad-input |
| 2 | A06 | `--repo` absent or repeated | bad-input |
| 3 | A07 | Positional count ≠ 1 | bad-input |
| 4 | A01 | C fails `^[0-9a-f]{40}$` | bad-input |
| 5 | A05 | `--now` fails TS syntax, is not a calendar instant, or is outside 1970-01-01T00:00:00Z … 9999-12-31T23:59:59Z | bad-input |
| 6 | A02 | `--repo` not absolute, has a `.`/`..` component, or ≠ its realpath | bad-input |
| 7 | A03 | `<repo>` or `<repo>/.git` not a real directory | integrity-refused |
| 8 | A04 | `st_uid(.git)` ≠ euid | unsafe-ownership |

**Clocks**
1. **Monotonic time** is used only for C09 (60 s per call) and C08 (300 s total).
2. **Wall-clock `now`** is integer seconds UTC. Without `--now`, it is floor(time.time()), sampled **once, immediately after snap0a**. With `--now`, it is the given value, and the system clock is not read for `now`.
3. **Stored timestamps** (reflog ts, FETCH_HEAD mtime) come from other processes' clocks.

**Comparisons**
- Integer seconds throughout.
- FETCH_HEAD is future iff floor(mtime_ns/10⁹) > now.
- 24 h means 0 ≤ now − observed_at ≤ 86400.
- A stored time later than `now` gives CONTRA `future`. **This is not a claim that a race occurred.**
- A write after snap0a produces D02.
- Missing data: R1/F01/F09. Malformed: R2/F02/F07. Inconsistent: R3.

**Test-only inputs:** `--now`, `--trace-argv`, and a library-only harness interface ([harness]) with phase hooks, git-result substitution and `time.time` injection.

### 1.4 Preflight

**Configuration.**
- Read once with `config --list --show-scope -z`. Records are `scope\0key\nvalue\0`, split at the first `\n`. git lowercases section and key names; subsections keep their case.
- Only the `local` and `command` scopes are visible (because of `GIT_CONFIG_NOSYSTEM` and `GIT_CONFIG_GLOBAL=/dev/null`). `command` is the helper's own pins and is excluded from checks.
- The `worktree` scope is refused (C04), and `include` is refused (C05).

### 1.6 Freshness model

#### 1.6.1 Inputs

- snap0a bytes and stats; S0r.RAW; local configuration; `now`.
- TR = `logs/refs/remotes/origin/development`.
- OR = every file under `logs/refs/remotes/origin/`.
- FETCH_HEAD and its mtime.

#### 1.6.2 Reflog grammar

```
^([0-9a-f]{40}) ([0-9a-f]{40}) [^<\n]* <[^>\n]*> ([0-9]+) ([+-][0-9]{4})\t([^\n]*)$
```

- cmdline = the message before the first `": "`, or the whole message.
- The last line of a file is its newest entry.

#### 1.6.3 R rows

**OMS:** `remote.origin.fetch` is exactly one value, `+refs/heads/*:refs/remotes/origin/*`, and no other remote's fetch destination lies under `refs/remotes/origin/`.

**RA**

```
RA         = fetch-form / pull-form
fetch-form = "fetch" *(SP fopt) [SP "origin" *(SP (fopt / src))]
pull-form  = "pull"  *(SP popt) [SP "origin" *(SP (popt / src))]
fopt       = "--prune" / "-p"
popt       = "--tags" / "--rebase" / "--no-rebase" / "-r" / "--ff-only"
src        = 1*(ALPHA / DIGIT / "." / "_" / "/" / "-")   ; must not begin with "-" or "."
```

- A bare form (no `origin`) is accepted only if origin is the only remote.
- **Rejected:**
  - any other remote, `.`, or a URL;
  - a `src` containing `:`, `+`, `*`, `^` or `~`;
  - any option not listed above;
  - `--all` / `--multiple` [P-12 · PDB: rejected; if adopted: allowed with a single remote];
  - `update by push` [P-20 · PDB: rejected].
- A command line proves nothing about the remote.

**OU — origin URL policy (R11Δ: renamed steps; SP0 moved first; IPv6 by value; totality fixes)**

The steps run in order, and the first decisive step sets `origin_url_class`.

| Step | Condition | Result |
|---|---|---|
| **OU0** | `remote.origin.url` absent, or more than one value | FAIL `absent` |
| **OU1** | Local-scope key present (lowercased): `url.*.insteadof`, `url.*.pushinsteadof`, `remote.origin.uploadpack`, `remote.origin.proxy`, `remote.origin.vcs`, `http.proxy`, `http.*.proxy`, `http.curloptresolve`, `http.*.curloptresolve`, `core.gitproxy` | FAIL `rewritten` (key existence and semantics: UR-18) |
| **OU2** | u contains `\` | FAIL `malformed` |
| **OU3** | u matches `^[A-Za-z][A-Za-z0-9+.-]*::` | FAIL `transport-helper` |
| **OU4** | u matches `^[A-Za-z][A-Za-z0-9+.-]*://` | → SC1 |
| **OU5** | u matches `^(?:[^@/:\[\]]+@)?(\[[^\]]+\]\|[^/:\[\]]+):(.+)$` and the first `:` comes before any `/` | → SP0 |
| **OU6** | otherwise | FAIL `local-path` |

**Scheme URL**

| Step | Rule | On failure |
|---|---|---|
| **SC1** | Lowercase the scheme; it must be one of {https, http, ssh, git} | FAIL `scheme` |
| **SC2** | Authority = text after `://` up to the first `/`, `?` or `#`, or end of string. Must be non-empty. | FAIL `malformed` |
| **SC3** | If the authority contains `@`, userinfo is everything up to the **last** `@`. Userinfo containing `[` or `]` is invalid. Remove the userinfo. | FAIL `malformed` |
| **SC4** | Split host and port: see below | FAIL `malformed` |

**SC4 detail**
- If the remainder starts with `[`: the literal runs to the first `]`; what follows must be empty or `:`PORT; the literal must contain `:`. Then go to HS4.
- Otherwise, if the remainder contains `:`: the part after the last `:` must be a PORT, and no other `:` may appear. The host is what precedes it.
- **PORT (R11Δ) = 1–5 digits whose value is 1–65535, applied identically in both branches.** An empty host or invalid PORT → FAIL `malformed`.
- Non-bracketed host → HS1.

**scp form**

| Step | Rule | Result |
|---|---|---|
| **SP0** (R11Δ, R10-04, evaluated first) | Host (group 1) unbracketed and exactly one character | FAIL `local-path` |
| **SP1** | Path (group 2) must be non-empty | else FAIL `malformed` |
| **SP2** | Bracketed host whose content contains `:`: if the content parses as IPv6 (HS4 rules) → HS4; else it must match `^[^:]+:PORT$`, and the host part → HS1; else FAIL `malformed`. Bracketed host without `:`: strip the brackets → HS1. Unbracketed host → HS1. | — |

**Host checks**

| Step | Rule | Result |
|---|---|---|
| **HS1** | Lowercase, then strip one trailing `.`. If every dot-separated label matches `^(0x[0-9a-f]*\|[0-9]+)$` → HS3. Otherwise the host must match `^[a-z0-9]([a-z0-9-]*[a-z0-9])?(\.[a-z0-9]([a-z0-9-]*[a-z0-9])?)*$` and be ≤ 253 characters → HS5. | else FAIL `malformed` |
| **HS3** | **R11Δ (R10-06):** more than 4 labels → FAIL `malformed`. 1–4 labels follow inet_aton rules: `0x` prefix = hex (`0x` alone → malformed); leading `0` on a multi-digit label = octal (digits 8/9 → malformed); otherwise decimal. The last label fills the remaining bytes (32 / 24 / 16 / 8 bits for 1 / 2 / 3 / 4 labels). Overflow → malformed. | Value in 127.0.0.0/8 or 0.0.0.0/8 → FAIL `local-host`; otherwise **pass** |
| **HS4** | **R11Δ (R10-05):** parse to a **128-bit value** (RFC 4291, `::` compression, embedded dotted IPv4). Zone ids (`%`) or parse failure → FAIL `malformed`. Reject by **value** (see below). | rejected → FAIL `local-host`; otherwise **pass** |
| **HS5** | `localhost`, or a name ending `.localhost` | FAIL `local-host`; otherwise **pass** (`network-form`) |

HS4 rejects these values:
- `::1` (loopback);
- `::` (unspecified);
- `::ffff:0:0/96` (IPv4-mapped) whose low 32 bits lie in 127.0.0.0/8 or 0.0.0.0/8;
- `::/96` (IPv4-compatible) whose low 32 bits lie in 127.0.0.0/8 or 0.0.0.0/8 (`::` and `::1` are already covered above).

Spelling does not matter: `[0:0:0:0:0:0:0:1]`, `[0::1]`, `[::ffff:7f00:1]` and `[::7f00:1]` are all local-host.

**Determinism [R].** The steps are ordered, every step either decides or names exactly one next step, and every predicate is total. Every u therefore reaches exactly one class: network-form, absent, rewritten, malformed, transport-helper, scheme, local-path or local-host.

**What OU establishes, and what it does not.** Passing OU means only that the **repository-local** configuration names origin with a network-form URL, the host is not a recognised loopback, unspecified or `.localhost` value, and no OU1 key is present locally. It does **not** establish any of the following (L-16):
- that the host is public, reachable, trustworthy or canonical;
- name resolution;
- global or system configuration;
- environment variables at the time of the fetch;
- SSH host aliases;
- that the URL has not changed since the fetch.

### 1.7 Patch identity, anchoring, landing and content — R11Δ (R10-01, R10-02)

#### 1.7.1 Claims

| Evidence | What it shows |
|---|---|
| Patch-id equality | Net-diff equivalence under the pinned diff |
| Entry equality | Identical (mode, type, oid) |
| Line counts | Net per-file counts with **no provenance**. Identical text lines cannot be told apart, so no claim is ever made about *which* copy of a line is C's. |
| **Landing** (R11Δ) | Means **C's surviving change is reflected in Tip**. It is established per relevant path, either by **state equality** (entry(Tip,p) = entry(End,p)), or, for squash text paths only, by **patch identity plus a carried-by-unit check** (§1.7.3). Neither line counts nor patch identity is ever used **alone**. |

#### 1.7.2 DIFF and pid

```
DIFF(A,B) := git --attr-source=4b825dc642cb6eb9a060e54bf8d69288fbee4904 diff -U3 --no-relative
             --no-ext-diff --no-textconv --no-color --binary --full-index --diff-algorithm=myers
             --no-renames --ignore-submodules=none --submodule=short --src-prefix=a/ --dst-prefix=b/
             -O/dev/null <A> <B>
pid(A,B)  := DIFF(A,B) | git patch-id --verbatim
```

0 lines → NULL. Exactly one line matching `^[0-9a-f]{40} [0-9a-f]{40}$` → its first field. Anything else → C11.

#### 1.7.3 Anchoring and landing (R11Δ)

**States**

| Name | Definition |
|---|---|
| Pre | parent0(C) |
| Post | C |
| End | I.end |
| Tb | I.base (the target before integration) |
| Tip | I.tip |
| Tn | T |
| Bu | Branch-side unit base: Pre (direct); seg_base (squash: B_X for a first-integration match, X_v for a chained match); the single member of `merge-base --all P^1 P^2` (ancestry-merge; 0 → K28, > 1 → K29) |

**Relevant paths (R11Δ).** A path p ∈ paths(C) is **relevant** iff C has surviving content at p. That means at least one of:
- (i) a text line with S_A(L) + S_R(L) > 0 at p (§1.7.4 quantities);
- (ii) p is opaque (§1.7.4) with entry(End,p) = entry(Post,p) ≠ entry(Pre,p);
- (iii) a mode change, mode(Post,p) ≠ mode(Pre,p), with mode(End,p) = mode(Post,p).

Paths with no surviving content take no part in anchoring or landing. They are accounted for as superseded (§1.7.4).

**Step 1 — Fork-relative anchoring (R11Δ, replaces the R10 rule)**
1. Fk := `merge-base --all Bu Pre`.
   - |Fk| = 0 or > 1 → **K34** (fork-base-undetermined).
   - Otherwise Fk is that single commit.
2. C is **anchored** iff entry(Bu,p) = entry(Fk,p) for every relevant p.
3. Otherwise → **K32** (base-not-anchored).

**Behaviour [R]**

| Situation | Result |
|---|---|
| Bu ⊑ Pre (the usual case: no back-merge after C; direct mode) | Fk = Bu, so the equality is **trivially true**. **That is not evidence that C landed.** Landing comes only from Step 2. |
| Earlier branch commits touched C's paths (C0 then C on f) | No effect. Fk is the fork point, and entry(Fk,f) is compared with entry(Bu,f), not with Pre. This removes the R10-02 false block. |
| An unrelated back-merge after C (target changes on other paths only) | Bu = the back-merged target commit, Fk = the fork, and the entries are equal on C's relevant paths. **Anchored.** |
| A back-merge whose target changes touched one of C's relevant paths | Entries differ → **K32**. This is the remaining false-block cost (L-20). It also catches the R9-01 back-merge constructions, where the absorbed target change pre-empts C's change. |

**Step 2 — Landing (only if anchored)**

Every relevant p is classified into exactly one of: **landed**, **result-differs**, **unverifiable**, **not-carried**. Let b = entry(Bu,p), t = entry(Tb,p), e = entry(End,p), r = entry(Tip,p).

**Type guard (all modes).** If any of entry(Pre,p), entry(Post,p), b, t, e or r has type `tree`, p is **unverifiable**.

**ancestry-direct**

Tip = End = C, so r = e and p is **landed** (state equality). `landing=by-construction`.

**ancestry-merge**

| Condition | Class |
|---|---|
| r = e | **landed** (state equality: the merge result equals the branch end at p) |
| r ≠ e ∧ t = b | **result-differs** |
| r ≠ e ∧ t ≠ b | **unverifiable** |

`landing=by-path-entry`. Line counts are never used for merges.

**squash** (`landing=by-patch-identity`; requires pid(seg_base, X) = pid(S^1, S) and the GitLab-pair predicates [UR-16])

| Condition | Class |
|---|---|
| r = e | **landed** (state equality) |
| p opaque, or C's surviving change at p includes a mode change, and r ≠ e | **unverifiable** (no counting for these) |
| p text, r ≠ e, and the **carried-by-unit** check below holds | **landed** |
| p text, r ≠ e, otherwise | **not-carried** |

**Carried-by-unit check (text paths), for every line L at p:**
- **Additions:** S_A(L) ≤ max(0, End(L) − Bu(L)).
- **Removals:** min(S_R(L), Bu(L)) ≤ max(0, Bu(L) − End(L)).

Why carried-by-unit establishes landing for squash [R, UR-16]:
- Patch-id equality means S's diff has the same per-file hunks as the unit's diff Bu → End. Applying it to Tb = S^1 changes each line count at p by exactly End(L) − Bu(L). So Tip(L) = Tb(L) + (End(L) − Bu(L)).
- **Additions:** the check guarantees Tip(L) ≥ Tb(L) + S_A(L). Tip holds at least C's surviving added copies of L beyond the target's pre-integration count.
- **Removals:** the check guarantees Tip(L) ≤ Tb(L) − min(S_R(L), Bu(L)). The removals of lines the unit base held were applied. A removal of a line the unit base never held (a branch-local line) needs nothing carried.
- This uses counts **over the unit's diff** (a structural object). It is combined with patch identity, and it never uses Tn. **It establishes count-level reflection of identical text, not which copy of a line is C's** (L-4).

**Why both checks are needed and neither restates the other:**

| Case | Anchoring | Carried check | Outcome |
|---|---|---|---|
| R10-01 (no back-merge) | trivially true | catches it: End(L) − Bu(L) = 0 < S_A = 1 | not-carried |
| R9-01 A/B (a back-merge absorbed the target's equivalent change) | catches it | fails to catch it: the removal's req = min(S_R, Bu(L)) = 0 is vacuous | K32 |

Each check catches cases the other passes. §11 has the derivations.

**Result of Step 2** (only if anchored):

| Condition | Row |
|---|---|
| any result-differs | **K30** |
| else any unverifiable | **K31** |
| else any not-carried | **K33** |
| else | landed (continue to events and content) |

**paths_unlanded** (R11Δ, R10-12):
- numerator = #result-differs + #unverifiable + #not-carried;
- denominator = #relevant paths;
- the four classes are disjoint, and each relevant path has exactly one class;
- **0/0 is permitted.** It means no relevant path, in which case content state 1 or 2 decides (K20 or K21), never MERGED.

**K30's meaning.** The merge result at p differs from the branch end while the target side was unchanged. Possible causes:
- C's change was dropped (`-s ours`);
- the merger added a fix-up line (an evil merge);
- a sibling commit's change at p was dropped.

The reason token is `merge-result-differs` (L-19).

**K33's meaning (R11Δ).** For squash: the target changed p, and the integration unit's net diff does not carry C's surviving change. Possible causes:
- C restored text that a predecessor on the branch removed, while the target independently removed it (R10-01);
- a predecessor's change and C's change cancel within the unit.

The reason token is `change-not-carried`.

**Withdrawn.** All count-based landing formulas of Revisions 7–9 (j_miss and related), and the Revision 10 claim that `Bu ⊑ Pre` establishes landing.

#### 1.7.4 Content (current-state) checks

These run after anchoring, landing and events. They compare C's surviving change with Tn. **Net counts, no provenance.**

- **Opaque path:** in Pre or Post, the path is a symlink, gitlink, tree, or a blob with a NUL in its first 8000 bytes. Compared by entry.
- **Text path:** drop whitespace-only lines and compare byte-exact. X(L) is the count of L in blob(X, p); ⊥ counts as 0.
- **Mode-only changes** contribute nothing to the quantities below. They are checked by landing (§1.7.3).

| Quantity | Definition |
|---|---|
| A, R | max(0, Post − Pre), max(0, Pre − Post) |
| S_A, S_R | min(A, max(0, End − Pre)), min(R, max(0, Pre − End)) |
| superseded | Σ(A − S_A) + Σ(R − S_R) + opaque paths with entry(End) ≠ entry(Post) |
| k / K | Σ min(S_A, max(0, Tn − Tb)) / ΣS_A [B-18] |
| j_abs / J | Σ{S_R(L) : Tn(L) = 0} / ΣS_R |
| j_inc / J | Σ min(S_R, max(0, Tn − Tip)) / ΣS_R |
| b / B | B = opaque paths with entry(End) = entry(Post); b = members of B with entry(Tn) = entry(Post) |

**Content state** (first match):

| # | Condition | State | content_basis |
|---|---|---|---|
| 1 | ΣA + ΣR + #opaque = 0 | unassessable (**K20**) | `-` |
| 2 | K + J + B = 0 | superseded [P-06 · PDB; if rejected → insufficient] (**K21**) | `-` |
| 3 | K > 0 | sufficient iff k = K ∧ b = B (j_abs, j_inc reported, not required [UR-14]) | `added` |
| 4 | K = 0, J > 0 | sufficient iff j_inc = 0 ∧ b = B [P-07 · PDB; if rejected: insufficient] | `removed` |
| 5 | otherwise | sufficient iff b = B | `opaque` |

Insufficient → **K22**.

**Zero relevant paths (R10-09).** If C has no relevant path, landing is vacuous, and content state 1 (K20, e.g. a mode-only or whitespace-only C whose mode change was undone) or state 2 (K21) decides. MERGED never results.

### 1.8 Integration algorithm

#### 1.8.1 Present C

```
if np(C) ≥ 3:                                  K02   [P-16 · PDB: K02; if rejected: proceed]
P := oldest X ∈ FP with C ⊑ X
if P = C:      I := (ancestry-direct, base=parent0(C), tip=C, end=C, integrating=C, merge=-,
                     seg_base=-, lineage_root=C, landing=by-construction)
elif np(P) ≥ 3:                                K05
elif np(P) = 2:
     require C ⊑ P^2 ∧ C ⋢ P^1                 else raise C12
     I := (ancestry-merge, base=P^1, tip=P, end=P^2, integrating=P, merge=P, seg_base=-,
           lineage_root=C, landing=by-path-entry)
else:          raise C12
→ FINALIZE(I)
```

If P = C and np(C) = 2, C's change is diff(C^1, C) (N-19).

#### 1.8.2 Absent C

| Row | Condition |
|---|---|
| K03 | np(C) = 2 |
| K04 | np(C) ≤ 1 ∧ paths(C) = ∅ |
| K06 | NB := `merge-base --all C T`; \|NB\| = 0 |
| K07 | \|NB\| > 1 |

**M1 (endpoints)**
- refs := `for-each-ref --contains C refs/remotes/origin/`, minus `refs/remotes/origin/{development,HEAD}` [P-04 · PDB: remote-tracking refs only; if adopted: plus `refs/heads/`].
- E := `rev-list C <refs…> --not T`.
- ord := rank in a parents-before-children Kahn order on E (smallest OID first among ready nodes), counted from 0.

**Endpoint check.** For each X ∈ E in ascending ord, let n := |`merge-base --all X T`|. The first X with n ≠ 1 decides:
- n = 0 → **K27**;
- n > 1 → **K08** [P-02 · PDB: K08; if rejected: drop X and continue].

Otherwise B_X is that single merge base.

**M2 (target-side candidates)**
- RANGE := `rev-list T --not NB`.
- SSHAPE := GitLab pairs with M ∈ FP ∩ RANGE.
- SOTHER := non-merge commits of RANGE that are not the S of any SSHAPE pair.
- PMAP_S: pid(parent0(S), S) → pairs, ordered by pos(M).
- PMAP_O: pid → commits, ordered by OID.
- NULL pids are dropped.

**M3–M4 (first-integration matches)**
- For X ∈ E: p := pid(B_X, X).
- (S, M) ∈ PMAP_S[p] is kept iff B_X ⊑ S^1 and the pair predicates hold. It is added to V with **seg_base = B_X**.
- Each S′ ∈ PMAP_O[p] gives a **shape hit** (X, B_X, S′).

**M5 (chaining)**
- For X2 ∈ E in ascending ord, and for each v ∈ V with X_v ⊑ X2 and X_v ≠ X2, in descending (pos(M_v), ord(X_v)): accept (S2, M2) ∈ PMAP_S[pid(X_v, X2)] iff M_v ⊑ S2^1, pos(M2) > pos(M_v), and v is the maximal previous entry.
- An accepted pair is added to V as (X2, **seg_base = X_v**, S2, M2).

**M6 (covering).** (X, base, …) covers C iff C ⊑ X ∧ C ⋢ base. Here base = seg_base for V entries and B_X for shape hits.

**M7 (selection), R11Δ (R10-11)**
1. Cmin := the covering V entries with minimal pos(M).
2. If Cmin has more than one distinct X → **K25** [P-24 · PDB: K25; (a): max brank, then min ord(X), then OIDs; (b): min ord(X), then OIDs; if rejected: K25]. Here brank = 0 if seg_base ∉ E, else 1 + ord(seg_base).
3. If Cmin has one distinct X but more than one seg_base:
   - compute Step-1 anchoring (§1.7.3) for each candidate;
   - if the candidates do not all have the same anchoring result (anchored / K32 / K34) → **K25**;
   - otherwise select the minimum (OID(seg_base), OID(S)).
4. If Cmin has a single entry, select it.
5. I := (squash, base=S^1, tip=M, end=X, integrating=S, merge=M, **seg_base**, lineage_root=S, landing=by-patch-identity).

**No covering V entry**

| Row | Condition |
|---|---|
| K10 | a shape hit covers C |
| K11 | refs = ∅ |
| K12 | cand ≠ ∅ |
| K13 / K14 | otherwise |

cand := `rev-list --no-merges --full-history T --not NB -- paths(C)` ∪ {merges G ∈ RANGE with non-empty `diff-tree --cc --name-only -z` on paths(C)} \ {S_v, M_v : v ∈ V}.

#### 1.8.3 FINALIZE (R11Δ)

**Compute first:** AN (Bu, Fk and anchoring), LD (per-path classes; only if anchored), EV (§6), PR, CK.

**Then decide, in this order:**
1. K28, K29 (ancestry-merge Bu count)
2. **K34** (Fk undetermined)
3. **K32** (not anchored)
4. K30, K31, **K33** (landing)
5. K15, K16, K17, K18, K26 (events)
6. K19
7. K20, K21, K22
8. K23 or K24

**Definitions used here**
- **PR** := #{p ∈ paths(C) : entry(I.base,p) ≠ entry(I.tip,p) ∧ entry(T,p) = entry(I.base,p)}.
- **Diagnostics:**
  - `drift` := #{p ∈ paths(C) : entry(T,p) ≠ entry(End,p)};
  - `later_commits` := `rev-list --count T --not I.tip -- paths(C)`;
  - `c_paths_in_unit` := |paths(C) ∩ paths(IU)|.

Any C row raised during the computations preempts every K row.

**REFID**
1. Strip `refs/remotes/origin/`. (Under P-04, strip `refs/heads/` and prefix `local/`.)
2. Replace each character outside `[A-Za-z0-9._/-]` with `?`.
3. If the result is ≤ 24 characters and unique among the listed refs, use it. Otherwise use the first 7 characters + `~` + the first 16 hex digits of SHA-256(full refname).

This is collision-resistant, not collision-free.

**Denominators**

| Field | Ratio |
|---|---|
| `added_lines_present` | k / K |
| `removed_lines_absent` | j_abs / J |
| `removed_lines_increased` | j_inc / J |
| `binary_present` | b / B |
| `paths_reverted` | n / #{p ∈ paths(C) : entry(I.base,p) ≠ entry(I.tip,p)} |
| `paths_unlanded` | (#result-differs + #unverifiable + #not-carried) / #relevant (disjoint classes; 0/0 permitted) |
| `drift` | n / \|paths(C)\| |
| `c_paths_in_unit` | n / \|paths(C)\| |

**Presence rules.** Fields not listed are `-`. Every classified line carries: the freshness fields, `origin_identity`, `origin_url_class`, `commit`, `snapshot=full`, `caveats`, `recommend`.

| Field | Has a value on |
|---|---|
| `refs` | Rows reached after M1 (K08, K27, K10–K14, K25, and FINALIZE rows reached through M7) when non-empty; otherwise `-` |
| `via`, `attribution`, `integrating`, `landing` | Every FINALIZE row (K15–K24, K26, K28–K34) |
| `merge` | Every FINALIZE row except ancestry-direct |
| `segment_base`, `segment_end`, `covering` | FINALIZE rows with via=squash; `covering` also on K25 |
| `paths_unlanded` | **R11Δ:** K30, K31, K33, and K15–K24/K26 (all modes); `-` on K28, K29, K32, K34 |

On failure lines, `provisional` is set only on D01 and D02. Exit code: 0 for classified lines, 2 for failure lines. Paths, commit text, stderr and raw input are never printed.

## 6. Revert and event-ordering specification

**6.1 Patches**
- u_I = pid(I.base, I.tip); u_C = pid(parent0(C), C); r_I = pid(I.tip, I.base); r_C = pid(C, parent0(C)).
- U = {u_I, u_C} \ {NULL}; Rv = {r_I, r_C} \ {NULL}.
- If U ∪ Rv = ∅ → K15.

**6.2 Records.** For each commit Q ∈ `rev-list T --not I.tip` (≤ 5,000, else C08):
- e = pid(parent0(Q), Q) if np(Q) ≤ 1, else pid(Q^1, Q).
- A NULL e means no record. A pid failure → C11.
- Kind: **revert** if e ∈ Rv (this takes precedence when e is also in U); **reapply** if e ∈ U.

**6.3 Lineage** [P-13 · PDB: as stated; if rejected: ignore out-of-lineage reverts]
- A record qualifies iff I.lineage_root ⊑ Q.
- A revert with I.lineage_root ⋢ Q → K16.

**6.4 Event identity and carrier rules (R11Δ, R10-10)** [P-14 · PDB: no deduplication, so every record is its own event]

If P-14 is adopted, exactly two collapses apply, and nothing else is ever collapsed:
- **CR1 (GitLab-pair carrier).** Records for Q_M and Q_S, where (Q_S, Q_M) is a GitLab pair and both have the same kind and the same e, form one event with representative Q_S.
- **CR2 (`--no-ff` carrier).** A record for a merge Q_M (np = 2) and exactly one record Q_X with Q_X ⊑ Q_M^2, Q_X ⋢ Q_M^1, the same kind and the same e — and no other record of either kind in Q_M^2 \ Q_M^1 — form one event with representative Q_X.

**6.5 Ordering** [P-15 · PDB: total order required]
- e₁ precedes e₂ iff rep(e₁) ⊑ rep(e₂) and rep(e₁) ≠ rep(e₂). Timestamps are never used.
- No total order → K17.
- has_revert := at least one revert event exists.

**6.6 Decision order.** These run after anchoring and landing: K15 → K16 → K17 → K18 → K26 [P-22] → K19.

**6.7 Detection boundary**

| Situation | Result |
|---|---|
| Exact revert | K18 |
| Exact revert then reapply | K26 (PDB) |
| Unrelated change identical to an inverse | revert |
| Partial or drift revert | not an event; backstops are K19, K22, CV2 |
| Semantic revert | not detected |
| Revert outside lineage | K16 |
| No total order | K17 |

Absence of a detected revert never proves that there is none.

## 11. Adversarial re-derivations (author's, on paper; not independent)

### 11.1 R10-01 squash counterexample (FX-K33a) under the R11 rules

1. **States.**
   - F0: f = {…, L}.
   - Branch: C0 (removes L from f; edits g), then C (re-adds L in f). C is the tip of `refs/remotes/origin/b`.
   - Target: R (removes L from f, F0 → R), then the GitLab squash: S with S^1 = R; M = merge(R, S).
   - Later, Z adds L elsewhere in f. T = Z.
2. **M1.** E = {C0, C}; NB = F0; B_X = F0 for both endpoints; refs = {b}.
3. **M2–M4.**
   - pid(F0, C) is the g change only (f nets to zero over F0 → C).
   - S's diff vs S^1 = R is the g change only (the 3-way merge keeps R's f).
   - Same pid, GitLab pair, F0 ⊑ R = S^1 → V entry (C, seg_base = F0, S, M).
4. **M6–M7.** Covers C (C ⊑ C; C ⋢ F0). Cmin = {that entry}. I = squash; Tb = R, Tip = M, End = C, Bu = F0.
5. **Anchoring.** Fk = merge-base(F0, Pre = C0) = F0 → trivially anchored. **This is no evidence; landing decides.**
6. **Relevant paths.** paths(C) = {f}. S_A(L) = min(1, max(0, End(L) − Pre(L))) = min(1, 1 − 0) = 1, so f is relevant.
7. **Landing (squash, f is text).**
   - r = entry(M, f) = R's f (no L); e = entry(C, f) (has L); r ≠ e.
   - Carried check: End(L) − Bu(L) = 1 − 1 = 0 < S_A(L) = 1 → **not-carried**.
8. **Decision.** No differs, no unverifiable, one not-carried → **K33**. Z's later L is never consulted.
9. **Counterexample search on the rule itself.** Could the carried check pass while C's change is not in Tip? Under UR-16, Tip(L) = Tb(L) + End(L) − Bu(L), so passing guarantees Tip(L) ≥ Tb(L) + S_A(L). Tip therefore gains ≥ S_A copies of L relative to the target's pre-state. The residual is only that identical text cannot be told apart (L-4). **If UR-16 is disproved, this inference fails, and the squash text path must fall back to state equality alone** (§2.4).

**Stop-condition check (brief: "landing cannot be established without relying on line counts or patch identity alone").** The squash text rule uses neither alone: it requires patch identity (to fix Tip − Tb = End − Bu per line) **and** counts over the unit's own diff, and it applies only where state equality failed. Merge and direct landing use entry equality only. The author's judgement is that the stop condition is not met; the rule's soundness is explicitly conditional on UR-16, and the fallback if UR-16 fails is stated. The reviewer is asked to test this judgement (§13 item 2).
