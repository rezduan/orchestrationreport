## 2. Findings

### HIGH

**R10-01: In squash mode, the `Bu ⊑ Pre` disjunct does not establish landing. A false MERGED rests only on a coincidental line count (reopens the R9-01 B class).**
- **Section:** §1.7.3, §1.7.1, PV-17, §1.9 item (3), CV1.
- **Evidence:**
  - §1.7.3: "When Bu ⊑ Pre, the branch-side unit Bu → End contains C itself, so C's change is part of what the unit carries."
  - Squash landing: "Anchoring makes C's change part of the segment's diff on C's paths, and S applies that diff to S^1."
  - §1.7.1: landing "is never established by counts".
- **Counterexample (first-integration squash, no back-merge):**
  1. Target F0 has line L in f. A branch forks at F0.
  2. C0 removes L and edits g. C re-adds L, so A={L} and paths(C)={f}. C is the tip, so X=C.
  3. Independently, target commit R removes L.
  4. GitLab squashes onto R. The 3-way merge (base F0, theirs equal to base at f) keeps R's f, so S changes only g.
  5. Later, target commit Z adds L elsewhere in f.
  6. Matching: NB=F0, B_X=F0, and pid(F0,C) equals pid(S^1,S) (both are the g change only), so there is a V entry with seg_base=F0.
  7. Anchoring: F0 ⊑ Pre=C0, so C is anchored. Landing is `by-patch-identity`.
  8. Other checks pass: PR excludes f because entry(S^1,f)=entry(M,f), and Z is not a revert.
  9. Content: S_A(L)=1, Tb(L)=0, Tn(L)=1, so k=K and the result is **MERGED K23**, with CV1 saying "checked structurally … anchored to this commit's parent".
  10. Reality: M never contained C's L. The only L present is Z's. This is the R9-01 B harm reached through the other disjunct.
- **Asymmetry:** the ancestry-merge analogue fails closed, because step 3 makes e=b with surviving content K31.
- **Two packet claims are false here:**
  - Step 3: "Anchoring makes b's content equal to Pre's" holds only under the entry disjunct.
  - FX-K31d calls e=b with S_A>0 "inconsistent by definition; harness-injected". C0-removes-L / C-re-adds-L builds it naturally.
- **Same vacuity in the packet's own fixtures:** FX-K23ac′-s (and ac, ab) claim `landing=by-patch-identity` for a removal of branch-local lines, which never appear in the segment diff.
- **Impact:** PV-17 and §1.9 (3) are false for squash. MERGED can rest on L-4 coincidence, which is exactly what K32 was introduced to stop.
- **Smallest correction:**
  - For squash (and, harmlessly, for all modes), add a "carried by the unit" refusal. For each added line, require min(S_A, max(0, End−Bu)) = S_A. For each opaque path with surviving content, require entry(Bu,p) ≠ entry(End,p). Otherwise the result is K31.
  - Branch-local removals (P-07 cases) are unaffected.
  - Correct the §1.7.3 rationale, the step-3 sentence, the FX-K31d status, and CV1's "anchored to this commit's parent".
  - Add the counterexample as a BINDING fixture.

**R10-02: K32 false blocks are far wider than L-20/UR-19 state. Owner question UR-19 is posed on an understated premise.**
- **Section:** §1.7.3 anchoring; L-20; N-20/N-21; UR-19; FX-K23ag/ah, K23g.
- **Evidence:**
  - L-20: K32 "whenever the back-merged target changes touched one of C's paths".
  - N-21: "A back-merge that changes *other* paths leaves C anchored."
- **Counterexample:**
  1. Branch: C0 edits f, then C edits f.
  2. The branch then back-merges an unrelated target change on path h. FX-K23ag is exactly this, plus the earlier C0.
  3. B_X is the back-merged target commit, which is not ⊑ Pre. entry(B_X,f) is the fork content, but entry(Pre,f) carries C0's edit.
  4. Result: **K32**, although the back-merge never touched f.
- The same happens with any chained seg_base on a side line (FX-K23g) whenever an earlier branch commit touched C's paths, even if the side line Y never touched them.
- Multi-commit MRs editing the same file are the norm: RC-1..RC-4 are four commits in one MR.
- **Impact:** N-21 is false. FX-K23ag/ah/g are correct only under an unstated "no earlier branch commit touched C's paths" condition. An owner approving UR-19 would accept a cost much larger than the one described.
- **Smallest correction:**
  - Anchor against the fork, not against Pre. Let F := the unique merge-base(Bu, Pre); zero or several members → K28/K29-style refusal. Anchored iff entry(Bu,p) = entry(F,p) for every p ∈ paths(C). F = Bu when Bu ⊑ Pre.
  - This still blocks FX-K32a–d: entry(H,f) ≠ entry(F0,f).
  - Combine it with the R10-01 check.
  - Restate L-20 and N-21, and re-pose UR-19.
  - Add a fixture: earlier branch commit on f, plus an unrelated back-merge, expected MERGED.
