## 2. Findings

### R21-01 — MEDIUM — The UR-22 interim is a third rule, not "the stricter of A and B", and its B\*/superseded rule brings back the CV3/K21 claim R18-01 called false

**Sections:** §11.78, §2.3 UR-22, §1.7.3 survival key, §1.7.4 superseded / B\*, §11.85 (dd), FX-K31t, §11.61.

**Evidence**
- §11.78: "The **interim** takes, in every history, the stricter of A and B (H1 K22, H3 K21, H4 K21)".
- The same table, row H4: Interim **K21**, A MERGED, B MERGED.
- §2.3: "K21 when the only survivors are kind-only".
- §11.78: "superseded counts every content-replaced change, so CV3 stays true".
- FX-K31t (in force, §7): "No CV3 (not superseded)".
- §9.0000000, R18-01: "a later branch edit dropped them → false MERGED + **false CV3**".

**Counterexamples**
- **(a) H4 / FX-K21d.** Both options return MERGED and the interim returns K21. The stricter of A and B there is MERGED, so the interim cost is not attributable to either option, and §11.78's sentence is false.
- **(b) Non-text → text, mostly surviving.** The squash and target are untouched, as in FX-K22j but without Z:
  - C turns binary bin5 into text t1 (50 lines) and adds Lg to g.
  - A later branch commit edits only line 50, so End = Tn = t2.
  - Interim: bin5 ∈ B, b = B, state 3 from g → MERGED, superseded = 1 → **CV3**: "1 of this commit's changes were replaced on its own branch before integration".
  - 49 of C's 50 lines are present at End, Tip and Tn.
  - Under both UR-22 options (and in R19–R20) superseded = 0 and there is no CV3.
- **(c) H4 with the same shape alone:** the result is K21 `superseded-in-branch`, labelled a "kind-only" survivor although most of C's text survives.

**Impact**
- No false MERGED.
- On a MERGED line, the interim emits a CV3 that neither option emits, and that the author's own earlier finding (R18-01) called false.
- K21's reason is misleading for non-text → text paths.
- The owner is told the interim cost is "the stricter of A and B" when H4 is an extra cost of the interim rule itself.
- FX-K22j (Bo) now prints `superseded=1` where R20 printed 0. "No binding fixture moves" is true only for outcomes.

**Smallest correction** (pick one):
- (i) Keep the rule and restate it everywhere as "stricter than both options; in H4 it blocks MERGED where both options would return it". Drop "kind-only" for non-text → text. Reword CV3 and K21 so that "replaced" reads "changed again on its own branch (replaced or edited)", which stays true in (b) and in delete/re-add histories (R21-02).
- (ii) Make the interim the actual combination: B = B_A, B\* = B_B, superseded = the union of A's and B's non-survivors. H1 → K22, H3 → K21, H4 → MERGED (both options agree), with no CV3 in (b).

Either way, correct FX-K31t's "not superseded" note, §11.61's CV3 statement and residual (dd), which also needs the CV3 change.

### R21-02 — MEDIUM — Kind survival cannot tell an edit from delete-and-re-add; §11.78 omits this history and the UR-22 option texts omit its cost

**Sections:** §11.78 (H5–H7), §2.3 UR-22 Options A and B.

**Evidence**
- H6: "branch deletes p (End = ⊥) | relevant (⊥ ≠ Pre)".
- H7 covers re-adding "an opaque entry of a **third** kind" only.
- Option A: "Consistent with the survival key's stated rationale".

**Counterexamples**
- **Option A.** C's only change: text p → binary v0. The branch deletes p, then re-adds an unrelated binary v5. The squash lands and Tn = End.
  - Kind survives → p ∈ B, b = B → **MERGED, basis opaque, no CV3**, although nothing C made remains except the coincidence of kind.
  - The interim gives K21 (B\* = ∅, superseded = 1). Option B gives K21.
- **Option B (the R19–R20 rule).** The same hazard exists for binary → text: C writes t1, the branch deletes p, then re-adds unrelated text t9 → MERGED with no CV3.
- **H6 holes.** H6's "relevant (⊥ ≠ Pre)" is false when Pre = ⊥ (C added a binary): End = Pre, so p is not relevant. A restore-then-re-change history is also missing.

**Impact**
- This is the main semantic cost of each UR-22 option, and the owner is not shown it.
- The interim handles it correctly, through its content-based superseded and B\*.
- This tension with R21-01 is why R21-01's option (i) wording ("changed again") is preferable to dropping the content-based superseded.

**Smallest correction**
- Add H9 (delete, then re-add with the same kind as Post) and H10 (restore, then re-change) to §11.78.
- Split H6 into Pre ≠ ⊥ and Pre = ⊥.
- State the cost under each UR-22 option in §2.3.
