**Clocks (R9Δ, R8-10).** Three kinds of time are kept separate:

1. **Monotonic elapsed time** (`time.monotonic`). Used only for the per-call 60 s limit (C09) and the 300 s total limit (C08). Never compared with any stored timestamp.
2. **Wall-clock `now`.** Integer seconds UTC: floor of `time.time()`, or the `--now` value. Sampled **once, immediately after snap0a completes**. snap0a is the first `snap_files()` call (§1.5).
3. **Stored timestamps.** Reflog `ts` (integer seconds, written by whichever process updated the ref) and FETCH_HEAD `mtime` (written by the filesystem). These are other processes' wall-clock values.

**Comparisons:**
- Reflog ts are compared to `now` as integers.
- FETCH_HEAD counts as future iff `floor(mtime_ns/10⁹) > now`.
- 24 h means `0 ≤ now − observed_at ≤ 86400`.

**What timestamps can and cannot show:**
- A stored timestamp later than `now` gives CONTRA `future` (R5, R3, F03, F08), and freshness fails closed.
- **A future stored timestamp does not by itself show a race.** It can come from a race, a backward wall-clock step (NTP), clock skew between writers, or editing.
- A concurrent write after snap0a changes snap1, so it is reported as D02, not as `future`.
- A backward clock step after a legitimate write is reported as `future` and fails closed. This is L-17.
- Missing timestamps are covered by R1, F01 and F09. Malformed ones by R2, F02 and F07. Inconsistent ones by R3.
- No monotonicity of wall clocks is assumed.

**Test-only inputs:** `--now`, `--trace-argv`, and a harness callback interface available only as a library import.

**OU — origin URL policy (R9Δ).**

Inputs (local-scope configuration only):
- u = the single value of `remote.origin.url`. If it is absent or multi-valued, OU fails.
- The presence of any `url.<x>.insteadOf` or `url.<x>.pushInsteadOf` key.
- The presence of `remote.origin.uploadpack`.

The steps are evaluated in order. The first failure sets reason `nonstandard-origin-url`, and the diagnostic class is recorded in `origin_url_class`.

| Step | Check | If true |
|---|---|---|
| U1 | Any insteadOf / pushInsteadOf key, or `remote.origin.uploadpack`, is present | FAIL(`rewritten`) — the effective URL may differ from u |
| U2 | u contains `::` | FAIL(`transport-helper`). Remote-helper syntax (`gcrypt::`, `ext::`, …) can serve local data. |
| U3 | u matches `^[A-Za-z][A-Za-z0-9+.-]*://` | **Scheme URL.** Go to S1. |
| U4 | u matches `^(?:[^@/:]+@)?(\[[^\]]*\]\|[^/:\[\]]+):(.+)$` **and** the first `:` comes before any `/` | **scp form.** Host = group 1. Path = group 2, which must be non-empty. Go to H1. |
| U5 | Otherwise | FAIL(`local-path`). This covers `.`, `..`, relative and absolute paths, and `C:\…`. |

**Scheme URL (from U3):**
- **S1.** Lowercase the scheme. If it is not in {`https`, `http`, `ssh`, `git`}, FAIL(`scheme`). This catches `file`, `ftp`, `rsync` and every other scheme.
- **S2.** authority = the text after `://` up to the first `/`, or the end of the string. If it is empty, FAIL(`malformed`). This catches `https:///r`.
- **S3.** Strip userinfo: everything up to and including the **last** `@` in the authority.
- **S4.** Split host and port:
  - If the remainder starts with `[`: the host is up to the matching `]`. What follows must be empty or `:` + 1–5 digits. Otherwise FAIL(`malformed`).
  - Otherwise: if it contains `:`, the part after the **last** `:` must be 1–5 digits (the port), and no other `:` may appear. Otherwise FAIL(`malformed`).
  - A port, if present, must be 1–65535. Otherwise FAIL(`malformed`).
- Then go to H1.

**Host checks (scheme and scp forms):**
- **H1 — normalise.**
  - Strip `[` and `]`, lowercase, and strip **one** trailing `.`.
  - The result must be non-empty and at most 253 characters, and must be **either**:
    - a DNS-style name matching `^[a-z0-9]([a-z0-9-]*[a-z0-9])?(\.[a-z0-9]([a-z0-9-]*[a-z0-9])?)*$`, or
    - a bracketed IPv6 literal (bracketed input only).
  - Otherwise FAIL(`malformed`).
- **H2 — scp extras.**
  - A one-character host (a drive letter) → FAIL(`local-path`).
  - A host starting with `.` → FAIL(`local-path`). (H1 already excludes it.)
- **H3 — numeric host.**
  - If the host is made only of digits, dots and `x`/`X` hex markers, parse it with **inet_aton rules**: 1–4 parts; each part decimal, octal (leading 0) or hex (0x); last-part widening as in inet_aton.
  - If it cannot be parsed → FAIL(`malformed`).
  - If it parses to an address in 127.0.0.0/8 or 0.0.0.0/8 → FAIL(`local-host`).
  - This catches `127.1`, `0x7f.1`, `2130706433` and `0.0.0.0`.
- **H4 — IPv6 literal.**
  - Parse it with RFC 4291 rules, including an embedded dotted IPv4. If it cannot be parsed → FAIL(`malformed`).
  - Reject `::1`, `::`, and IPv4-mapped (`::ffff:a.b.c.d`) or IPv4-compatible forms whose IPv4 part is in 127/8 or 0/8 → FAIL(`local-host`).
- **H5 — local names.** If the host is `localhost` or ends with `.localhost` → FAIL(`local-host`). This includes `LOCALHOST` and `localhost.` after H1 normalisation.
- **H6.** Otherwise OU **passes** with class `network-form`.

**What OU establishes, and what it does not.**
- Passing OU means only this: *the repository-local configuration names origin with a network-form URL, the host is not a recognised loopback or local name, and no repository-local rewriting is configured.*
- It does **not** establish:
  - that the host is public, reachable, trustworthy or canonical;
  - that a DNS name resolves to a non-local address (`/etc/hosts`, the machine's own hostname, a split-horizon DNS);
  - that the user's **global or system** configuration did not rewrite the URL;
  - that SSH host aliases in `~/.ssh/config` did not redirect the connection;
  - that the URL was the same when the reflogged fetch ran.

  See L-16.

### 1.7 Patch identity, landing and content — R9Δ (R8-01, R8-02, R8-03)

#### 1.7.1 Claims (R9Δ)

- **Patch-id equality** means net-diff equivalence under the pinned diff.
- **Blob equality** means byte-identical file content at a path.
- **Line counts** are net per-file counts with **no provenance**. Counts never establish that a particular line is C's.

**Landing** (R9Δ) is defined **structurally**: by construction, by patch identity, or by per-path blob equality. **It is never defined by counts.**

#### 1.7.3 States and the structural landing rule (R9Δ)

**States:**

| Symbol | Commit |
|---|---|
| Pre | parent0(C) |
| Post | C |
| End | I.end |
| Tb | I.base |
| Tip | I.tip |
| Tn | T |
| **Bu** (R9Δ) | The branch-side base of the integration unit: Pre (direct), B_X (squash), or the single member of `merge-base --all P^1 P^2` (ancestry-merge) |

**Landing by mode (R9Δ, normative):**

| Mode | `landing` value | Rule | Why this establishes landing [R] |
|---|---|---|---|
| ancestry-direct | `by-construction` | Always landed. | Tip = C, so C's change *is* the integrated state. |
| squash | `by-patch-identity` | Landed, given the M3–M5 match: pid(base, X) = pid(S^1, S) with the GitLab-pair predicates. | The segment's diff and S's diff have identical hunks: same paths, lines and context, ignoring line numbers [UR-16]. S applies to S^1 every change the segment made from base to X. C's surviving content lies in that segment. A change of C that nets to zero over the segment (e.g. a branch-local line added and later removed) is not in the diff, and has nothing to land. |
| ancestry-merge | `by-path-blob` | Per-path check below. | Compares whole-file bytes. A count coincidence cannot pass. |

**Ancestry-merge per-path check.**
- Let Bu = merge-base(P^1, P^2):
  - if there are 0 such commits → **K28**;
  - if there are more than 1 → **K29**.
- For each p ∈ paths(C), let b = blob(Bu, p), t = blob(P^1, p), e = blob(P^2, p), r = blob(P, p). ⊥ counts as a distinct value.
- **In scope:** p is in scope iff e ≠ b, meaning the branch changed p between Bu and End. Paths with e = b have nothing to land; any change of C at p was undone on the branch, and §1.7.4 `superseded` reports that.
- An in-scope p is **landed** iff r = e (the merge result equals the branch's end state at p). Otherwise it is unlanded:
  - **not-landed** if t = b. The target had not changed p, so a clean merge would yield r = e. Since r ≠ e, the merge demonstrably dropped or altered the branch's change. Examples: `-s ours`, or a hand resolution.
  - **unverifiable** if t ≠ b. Both sides changed p. The merge result can legitimately differ from e, and the allowlist has no way to recompute a three-way merge.
- **Result:**
  - any not-landed path → **K30** (not-landed);
  - else any unverifiable path → **K31** (merge-content-unverifiable);
  - else landed.
- `paths_unlanded = (#not-landed + #unverifiable) / #in-scope`.

**Review proposals evaluated, and why counts were replaced (R9-01, R9-02, R9-03).**

**R8-01's req cap: `req = min(S_R, Tb, max(0, Bu − End))`.**
- The cap does fix R8-01's squash and merge examples, where the branch's net removal is 0.
- It stays count-based. In ancestry-merge it cannot tell *which* copy was removed:
  - Bu holds two copies of L0, at A and B. The branch removes A (C) and adds a different line elsewhere.
  - The hand-resolved merge keeps A and deletes the target's B instead. Then Tb − Tip = 1, req = 1, landed = 1, so j_miss = 0, yet C's removal did not land.
- The per-path rule gives r ≠ e → K30.

**R8-02's `a_miss = Σ(S_A − min(S_A, max(0, Tip − Tb)))`.**
- It fixes the `-s ours` plus later coincidental line case, because it measures at Tip, not Tn.
- It fails on the additions twin of R8-03:
  - C adds L at A. A sibling commit C′ adds L at B, so End has 2 copies.
  - The merge keeps only B's copy, so Tip − Tb = 1, and a_miss for C = 0, falsely.
- The per-path rule gives r ≠ e → K30.

**R8-03's conservative attribution: `landed = max(0, min(req, (Tb − Tip) − (min(Tb, NetU) − req)))`.**
- This is sound in the single-line cases examined, but it remains a per-line count heuristic over aggregates.
- Proving it correct across all multiset interactions (several lines, several siblings, moves within a file) is not established on paper.
- The per-path rule needs no such proof.

**Decision:** the count-based landing formulas (`j_miss`, `a_miss` and the attribution variant) are **withdrawn**. Landing is the structural rule above.
- The cost: an ancestry merge in which **both** sides changed one of C's paths becomes AMBIGUOUS (K31) even when the merge was correct. See N-15.
- Squash and direct integrations are unaffected. They are the common modes in the target project [M: squash on 3/3 measured MRs].

#### 1.7.4 Content (current-state) checks, after landing (R9Δ)

These run only after landing is established. They compare C's surviving change with the **current** target Tn. **They are net line counts with no provenance.**

Per p ∈ paths(C):
- Opaque paths (gitlink, symlink, or a NUL byte in the first 8000 bytes of Pre or Post) are compared by OID.
- Text lines: drop whitespace-only lines and compare byte-exact. X(L) is the count of line L in blob(X, p).

| Quantity | Definition |
|---|---|
| A, R | max(0, Post − Pre), max(0, Pre − Post) |
| S_A, S_R | min(A, max(0, End − Pre)), min(R, max(0, Pre − End)) |
| superseded | Σ(A − S_A) + Σ(R − S_R) + opaque paths with OID(End) ≠ OID(Post) |
| k / K | Σ min(S_A, max(0, Tn − Tb)) / ΣS_A — additions still counted beyond the pre-integration level (B-18) |
| j_abs / J | Σ{S_R(L) : Tn(L) = 0} / ΣS_R |
| j_inc / J | Σ min(S_R, max(0, Tn − Tip)) / ΣS_R — copies added since integration, capped per line |
| b / B | B = opaque paths with OID(End) = OID(Post); b = members of B with OID(Tn) = OID(Post) |

**Content state** (first match wins):

| # | Condition | State | content_basis |
|---|---|---|---|
| 1 | ΣA + ΣR + #opaque = 0 | unassessable | `-` |
| 2 | K + J + B = 0 | superseded [P-06 · PDB; if rejected → insufficient] | `-` |
| 3 | K > 0 | sufficient iff k = K ∧ b = B. j_abs and j_inc are reported, not required [UR-14]. | `added` |
| 4 | K = 0, J > 0 | sufficient iff j_inc = 0 ∧ b = B [P-07 · PDB; **if rejected:** always insufficient] | `removed` |
| 5 | otherwise | sufficient iff b = B | `opaque` |

Insufficient gives content-missing (K22). These checks are a current-state backstop. Because there is no provenance, a later edit that removes C's line while adding an identical one elsewhere still passes (L-4).
