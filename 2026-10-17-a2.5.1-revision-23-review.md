### R23-01 — MEDIUM — provenance claims survive outside CV3; PV-33 (4) is violated
**Where:** §1.7.4 (K22 bullet and the non-textual-End bullet); §11.77 "Rule (R21Δ)"; L-25.

**Evidence:**
- §1.7.4: "A relevant path without S(i) has no surviving C line and never triggers this rule."
- §1.7.4: "C-text path with a non-textual End: S_A(L) = S_R(L) = 0 … (no text change survived)."
- §11.77: "A relevant path without S(i) never triggers it: none of C's lines survives there, so there is nothing to count."
- L-25: "survival class S(i) (a C line survives) … A relevant path without a surviving C line is not affected."
- PV-33 (4) requires that no "§11 explanation attributes a net line-count change to a particular copy".

**Counterexample:**
- FX-K23bb. f has no touched line, so no S(i), yet the packet itself says "C's own L is still present".
- FX-K23bc. "C's L was present at End and in Tip". Under §1.7.4, f "has no surviving C line".
- The container case contradicts "no text change survived" (residual (j); §11.61 was corrected for exactly this).

**Impact:**
- The rationale for the K22 → MERGED movement still rests on the copy claim that R22-01 withdrew.
- The packet contradicts itself between the normative rule text and its own fixtures.
- §11.92's "other text searched" missed these lines, and PV-33 (4) is marked B while violated.

**Smallest correction:**
- Replace each phrase with a count statement, for example: "a relevant path without S(i) has, by net line counts, no surviving line change of C (which copy is not established, L-4); the rule does not apply" and "(by definition no line change is counted at a non-textual End)".
- Make the same change in §11.77 and L-25. Extend PV-33 (4) to §1 text.

### R23-03 — MEDIUM — "outcomes without injected failures do not depend on order" is false for genuine failures
**Where:** §1.7.3 "Order guarantees" ("Consequences: the outcome of a run without injected failures does not depend on this order …"); L-30 ("Unaffected: outcomes without injected failures …"); UR-23's interim text; residual (kk).

**Counterexample (MERGED vs TOOL_FAILURE across conforming implementations):**
- An absent C has a covering V entry.
- RANGE also contains a non-merge commit G (in SOTHER) whose tree object is corrupt or missing (a real repository fault; no harness).
- PMAP construction is explicitly "unspecified (no order and no short-circuit rule)". An implementation that builds PMAP_O lazily, only when no covering V entry exists, never computes pid(parent0(G), G) and returns MERGED.
- An eager implementation computes it, and its DIFF fails, giving C10.
- The same holds for a natural > 60 s call (C09) inside cand's `--cc` loop after a member is already found (K12 vs C09), or inside the K10 hit tests (K10 vs C10).

**Impact:** classified results on real repositories are not determined by the specification, and RT-02-style reproducibility across implementations is not guaranteed. The determinacy claim is narrower than stated. It is not a false MERGED, because a MERGED reached by skipping the call is still supported.

**Smallest correction:**
- Restate the scope as: unaffected "on runs where no git call fails, times out or exceeds a limit".
- Add to L-30, UR-23 and residual (kk) that a genuine failure inside those computations may or may not be reached, so the outcome can differ (MERGED/K10/K12 vs C08/C09/C10).

### R23-04 — LOW — the list of unspecified pre-FINALIZE iterations is incomplete; PV-30 overclaims "position"
**Where:** §1.7.3 "Order guarantees" ("Before FINALIZE, calls follow §4's sequential control flow: … decide()'s K01–K07 checks … the IA1 endpoint check … then IA2"); PV-30 R23Δ ("its position follows §4's sequential flow"); §11.89 rows C12, K05 and K25 (IA7 step 3).

**Counterexamples:**
1. For a present C, P := "oldest X ∈ FP with C ⊑ X" (`oldest_fp_container`) is an iterating search of up to 20,000 `--is-ancestor` calls. Linear from the oldest, linear from the newest, and binary search are all admissible. The order of these calls, and whether an argv-keyed injection on `merge-base --is-ancestor C <X>` is reached, are unspecified, but they are not listed.
2. The C12 test `C ⊑ P^2 ∧ C ⋢ P^1` has no stated short-circuit rule, so the §11.89 row ("the last `--is-ancestor` call of that test") is not determinate.
3. IA1's Kahn order needs parent data for every X ∈ E. How it is read, and in what order, is unspecified.
4. §11.89's K25 (IA7 step 3) row says "the last AN call". If the last candidate's AN reads are answered from the cache, or need no call (np(C) = 0, or Ht = Pre), the last call *issued* belongs to an earlier candidate or to relevance.

**Impact:** more of the same overclaim as R22-03. No fixture outcome moves.

**Smallest correction:** add `oldest_fp_container`, the C12 conjunction and IA1's parent reads to the unspecified list, and to L-30 and UR-23. Reword PV-30 as "position only where the canonical order applies, or in the straight-line steps of §4". In the K25 step-3 row, say "the last call issued (possibly earlier, if reads are cached)".

### R23-08 — LOW — FX-C09, FX-C11 and FX-S11d do not name an injected call; L-30's fixture constraint is unchecked for them

- §1.7.3 requires injection "only on a call … reached on every admissible order", and the failure-mapping bullet says "Every TF-injection fixture names the exact git call or hook".

**Counterexample:** a patch-id substitution keyed on a SOTHER commit's pid may be skipped by a lazily built PMAP_O (R23-03). The run is then MERGED, not C11.

**Fix:** name a call reached on every order, for example pid(B_X, X) for the first X ∈ E, the EV u_I call, or `git version`.

### R23-09 — LOW — CV3's count unit misdescribes C-opaque text results
**Evidence:** CV3 reads "By net line counts per file, and per non-text file, <superseded> …". In FX-K23az, bin5 is *text* at Post and End. It is counted once because it is C-opaque (Pre binary), not because it is a "non-text file". The sentence "<n> … no longer appear … part or all of such a change may still be present" is also self-contradictory on a plain reading, and is held together only by the "by net line counts" qualifier.

**Fix:** "per file (net line counts) and, for a file that was not text before or after this commit, as one change" (the P-21 PDB).
