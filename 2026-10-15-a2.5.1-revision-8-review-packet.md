## 1. Normative specification

### 1.1 Scope and terms

**Scope [B-01, B-02].** A read-only helper and isolated adversarial fixtures. It replaces A2.5 Observe step 4 only.

- The helper emits one output line, including a `caveats` field.
- Observe prints that line, then the §1.10 wording for `recommend`, then the fixed text of each caveat token, in token order.
- Observe derives nothing itself.

**Non-goals**
- D2–D5 and A2.6.
- Deployment, production or completion status.
- Merge-request or author attribution.
- Writing to any repository.
- Changes to memory, status or NEXT.

- **Proving that `origin` is the canonical upstream** (P-25, L-15).

**Terms**

### 1.2 Inputs — R8Δ (R7-10, R7-11)

**Argument model**
- `argv[0]` is the program name. It is never a positional.
- The remaining elements are scanned left to right:
  - `--` ends option parsing. Every later element is positional.
  - An element in the option set is an option. A **value-taking option consumes the next element as its value, verbatim, even if that element begins with `-`**.
  - Any other element beginning with `-` is an unknown option (A08). This includes `--opt=value` forms.
  - Every other element is positional.
- **Option set:**
  - `--repo <path>`
  - `--now <TS>`
  - `--trace-argv <path>`
  - `--expect-origin <url>` [P-25 · PDB: **not accepted** — under the PDB it is an unknown option, A08]

**Phase A rows.** Evaluated in table order; the first match wins.

| Order | Row | Condition | Result |
|---|---|---|---|
| 1 | A08 | Unknown option; a value-taking option as the last element (no value); `--opt=value`; or `--now`/`--trace-argv` repeated | bad-input |
| 2 | A06 | `--repo` absent, or given more than once | bad-input |
| 3 | A07 | Number of positionals ≠ 1 | bad-input |
| 4 | A01 | C fails `^[0-9a-f]{40}$` | bad-input |
| 5 | A05 | `--now` invalid: TS syntax, not a calendar instant, or out of range | bad-input |
| 6 | A02 | `--repo` not absolute, contains `.`/`..`, or ≠ its realpath | bad-input |
| 7 | A03 | `<repo>` or `<repo>/.git` not a real directory | integrity-refused |
| 8 | A04 | `st_uid(.git)` ≠ euid | unsafe-ownership |

Example: `--repo --now X` gives repo value `--now`, which fails A02 (not absolute). It is not A08.

**Clock (R8Δ, R7-11).**
- `now` is sampled **once, immediately after snap0a completes** and before preflight.
- It is stored as integer seconds UTC (floor of system time), or the `--now` value if given.
- Consequence: any reflog or FETCH_HEAD write that completed before its snap0a read has a timestamp ≤ `now` (on a monotonic clock). A write after snap0a changes snap1, which gives D02, so a race shows up as `snapshot-changed` and not as a misleading `future`.
- Comparisons:
  - reflog ts: integer seconds;
  - FETCH_HEAD: `floor(mtime_ns/10⁹)` is future iff it is greater than `now`;
  - 24 h: `0 ≤ now − observed_at ≤ 86400`.

**Test-only inputs** (Observe never passes these):
- `--now` and `--trace-argv`;
- a harness callback interface that exists only as a library import: phase hooks and git-result substitution.

### 1.4 Preflight — R8Δ (R7-09)

**Configuration source (R8Δ).**
- Every configuration value the helper uses comes from **one** call: `config --list --show-scope -z`, issued in preflight.
- Each record is `scope\0key\nvalue\0`. The helper splits the key from the value on the first `\n` and uses git's own key normalisation.
- The helper **never parses `.git/config` bytes itself.** The snapshot guards those bytes: a change between snap0 and snap1 gives D02.
- Records with scope `command` are the helper's own `-c` pins and are excluded from refusal checks.

**Phase C rows**

| Row | Condition | Result |
|---|---|---|
| C01 | `git version` does not match `^git version 2\.43\.[0-9]+$` | unsupported-version |
| C02 | absolute-git-dir ≠ realpath; bare; or git's ownership refusal | preflight |
| C03 | object format ≠ sha1 | object-format |
| C04 | Integrity refusal | integrity-refused |
| C05 | Configuration refusal | config-refused |
| C06 | Target absent | target-missing |
| C07 | Target is symbolic | symbolic-target |

**C04 integrity refusals:**
- `shallow`, `info/grafts`, `objects/info/alternates`, `objects/info/http-alternates`;
- `refs/replace/*`;
- `config.worktree`, `commondir`;
- non-empty `info/attributes`;
- `extensions.*` outside {`objectFormat=sha1`, `refStorage=files`}.

**C05 configuration refusals:**
- `include.*`, `includeIf.*`;
- `diff.*.command`, `.textconv`, `.binary`, `.funcname`, `.xfuncname`, `.wordRegex`, `.cachetextconv`;

- `uploadpack.*`, `protocol.*`.

`url.*.insteadOf` and `pushInsteadOf` are handled by F04, not refused. The denylist cannot cover future configuration keys; the 2.43.x version pin bounds that risk.

### 1.5 Snapshot model — R8Δ (R7-05)

**File records:** (relpath, kind ∈ {absent, regular, dir}, st_dev, st_ino, size, mtime_ns, ctime_ns, sha256) [P-17 · PDB: include ctime/inode].
- Opened with `O_NOFOLLOW`, inside realpath(`.git`), regular files ≤ 4 MiB.
- A symlink, FIFO, device, oversize or unreadable file in scope is a read failure.

**Scope:**
- `config`, `packed-refs`, `FETCH_HEAD`, and the C04 files;
- everything under `refs/heads/`, `refs/remotes/origin/`, `refs/replace/`, `logs/refs/remotes/origin/`, recursive and sorted.

**Ref record:** S0r = (T, RAW, H).
- RAW = exact output of `for-each-ref --format='%(objectname) %(refname)' refs/heads/ refs/remotes/origin/`.
- H = SHA-256(RAW).
- F16 reads tracking-ref values from S0r.RAW.
- Ref equality compares (T, H).

**`snapshot=` field (R8Δ: this states the comparison scope, not equality)**

| Value | Meaning |
|---|---|
| `full` | The comparison covered file records **and** ref records. On D00 they were equal; on D02 they differed. |
| `files-only` | S0r was never taken, so only file records were compared (equal on D00, different on D02). |
| `none` | No comparison was made (phase A, B01). |
| `final-unreadable` | The final snapshot could not be read (D01). |

**Invariants**
- **I-1.** Every classified (K) line has `snapshot=full`. An implementation that reaches a K result without S0r emits C14.
- **I-2.** `files-only` lets only a TOOL_FAILURE provisional result stand. It never lets a K result stand.
- **I-3.** Every line whose snapshot is not `full` carries CV4, and no such line claims stability.

**S0r is explicit.** `phaseC` returns `(prov, S0r)` and never raises. A failure carries S0r as it stood when the failure occurred: NONE if `snap_refs` had not completed.

**Snapshot value by row (R8Δ, completed):**

| Row(s) | When it can occur | Snapshot value |
|---|---|---|
| C01–C07 | before `snap_refs` | `files-only` |
| C10 | raised by preflight, `resolve_target` or `snap_refs` | `files-only` |
| C10 | raised later | `full` |
| C08, C09, C13, C14 | before or after `snap_refs` | `files-only` or `full`, by phase |
| C11, C12, C15 | classification only | `full` |

**Detects [R]:**
- torn reads;
- change-then-restore via ctime [UR-12].

**Residuals:**
- the object store;
- anything outside the snapshot scope;
- coarse ctime ticks;
- privileged clock manipulation;
- transient states restored within one tick.

No atomicity is claimed.

### 1.6 Freshness model — R8Δ

#### 1.6.1 Inputs

Inputs come from snap0 bytes and stats, S0r.RAW, and the preflight configuration records (§1.4):
- TR = `logs/refs/remotes/origin/development`;
- OR = all files under `logs/refs/remotes/origin/`;
- FETCH_HEAD and its mtime_ns;
- configuration: `remote.*.url`, `remote.*.fetch`, insteadOf/pushInsteadOf presence;
- `now`.

#### 1.6.2 Reflog grammar (unchanged)

```
^([0-9a-f]{40}) ([0-9a-f]{40}) [^<\n]* <[^>\n]*> ([0-9]+) ([+-][0-9]{4})\t([^\n]*)$
```

cmdline = the message before the first `": "`. The newest entry is the last line.

#### 1.6.3 R rows — target reflog (R8Δ: R7-02, R7-08)

**OMS — origin mapping is standard.**
- `remote.origin.fetch` is exactly `+refs/heads/*:refs/remotes/origin/*`, with one value, and
- no other remote's fetch destination lies under `refs/remotes/origin/`.

**OU — origin URL is a network URL (R8Δ, R7-02).** Let u = norm(remote.origin.url). OU holds iff exactly one value exists and u is one of:

| Form | Requirement |
|---|---|
| (a) scheme URL | `https://` / `http://` / `ssh://` / `git://`, then a host that is non-empty, contains no `/`, and is not `localhost`, `127.0.0.1` or `::1` |
| (b) scp form | `host:path`, where host is non-empty, contains no `/` or `\`, is not one character long (excludes Windows drive letters), is not `localhost`, and does not start with `.` |

**OU fails** for `.`, `..`, any path with or without `/`, `file://…`, and an empty or local host. OU establishes only that origin is *not a local repository*. It does **not** establish that origin is the canonical upstream (see P-25 and L-15).

**RA — accepted cmdline, closed grammar (R8Δ: options are now accepted after `origin`; WF ⊂ RA):**

```
RA         = fetch-form / pull-form
fetch-form = "fetch" *(SP fopt) [SP "origin" *(SP (fopt / src))]
pull-form  = "pull"  *(SP popt) [SP "origin" *(SP (popt / src))]
fopt       = "--prune" / "-p"
popt       = "--tags" / "--rebase" / "--no-rebase" / "-r" / "--ff-only"
src        = 1*(ALPHA / DIGIT / "." / "_" / "/" / "-")   ; must not begin with "-" or "."
```

- **Bare forms** (no `origin` token) are accepted only when origin is the only configured remote.
- **Rejected:**
  - any other remote, `.`, or a URL;
  - any `src` containing `:`, `+`, `*`, `^` or `~`;
  - options not listed above;
  - `--all` / `--multiple` [P-12 · PDB: rejected; **if adopted:** accepted only with a single remote];
  - `update by push` [P-20 · PDB: rejected].
- Parsing a command line does not prove the remote's state.

| 7 | R8 | OMS fails | INSUF (nonstandard-origin-mapping) |

#### 1.6.4 F rows — FETCH_HEAD (R8Δ, R7-08)

**Definitions**
- norm(u): strip userinfo, then one trailing `/`, then one trailing `.git`. Comparison is byte-exact and case-sensitive.
- Origin lines: lines whose norm(url) = norm(remote.origin.url).
- D: origin lines `branch 'development'`.
- D\*: all lines `branch 'development'`, whatever their remote.
- **WF** [P-08 · PDB: as stated]: the RA fetch-forms with **zero `src` tokens**. Examples: `fetch`, `fetch origin`, `fetch --prune origin`, `fetch origin --prune`, `fetch -p`, `fetch origin -p`. Bare forms require a single remote. `--all` forms: see P-12.
- **LAST / ts\* / Enew** [P-08]:
  - OR⁺ = the non-empty OR files.
  - LAST = the last lines of OR⁺.
  - If LAST = ∅, then ts\* and Enew are undefined.

#### 1.7.3 Candidate-unit content (R8Δ)

Per p ∈ paths(C), using `ls-tree` and `cat-file blob` only.
- ⊥ means the path is absent.
- Opaque paths (gitlink, symlink, or a NUL byte in the first 8,000 bytes of Pre or Post) are compared by OID only.
- Text: split on `\n`, drop lines that are only whitespace, compare byte-exact. X(L) is the count of line L in blob(X, p).
- **All counts are net per file. Totals sum over paths.**

**States**

| Symbol | Commit |
|---|---|
| Pre | parent0(C) |
| Post | C |
| End | I.end |
| Tb | I.base (the target before integration) |
| Tip | I.tip (the target state that integrated C) |
| Tn | T (the target now) |

**Quantities** (per line L)

| Quantity | Definition | Meaning |
|---|---|---|
| A, R | max(0, Post − Pre), max(0, Pre − Post) | Lines added / removed by C |
| S_A, S_R | min(A, max(0, End − Pre)), min(R, max(0, Pre − End)) | Survive to the integrated branch state |
| superseded | Σ(A − S_A) + Σ(R − S_R) + opaque paths with OID(End) ≠ OID(Post) | — |
| k / K | Σ min(S_A, max(0, Tn − Tb)) / ΣS_A | Additions present beyond the pre-integration count |
| **req** R8Δ | min(S_R, Tb) | Removals the target could apply (it held those copies) |
| **landed** R8Δ | min(req, max(0, Tb − Tip)) | Of those, copies actually removed at the integration point |
| **j_miss** R8Δ | Σ(req − landed) | Target-held removals that did **not** land at integration |
| j_abs | Σ { S_R(L) : Tn(L) = 0 } | Removed lines with zero copies in T now |
| j_inc | Σ min(S_R, max(0, Tn − Tip)) | Copies added to T since integration, capped per line at S_R |
| J | ΣS_R | — |
| B / b | B = opaque paths with OID(End) = OID(Post); b = members of B with OID(Tn) = OID(Post) | — |

**Checking j_miss against the review's j_land [R].**
- The review proposed j_land = Σmin(S_R, Tb) − Σmin(min(S_R, Tb), max(0, Tb − Tip)). That equals Σ(req − landed) = j_miss term by term.
- Spot checks:

| Case | Values | req | landed | j_miss | Result |
|---|---|---|---|---|---|
| R7-01 counterexample (`-s ours`) | Tb = 1, Tip = 1, S_R = 1 | 1 | 0 | **1** | fails, as required |
| Branch-local removal | Tb = 0 | 0 | 0 | 0 | vacuous |
| Duplicate held by the target | Tb = 2, Pre = 1, S_R = 1, Tip = 1 | 1 | 1 | 0 | passes |
| Target removed the line independently before integration | Tb = 0 | 0 | 0 | 0 | the removal is already reflected |

- **Mode reconciliation:**

| Mode | Values | Outcome |
|---|---|---|
| ancestry-direct | Tb = Pre, Tip = Post: landed = min(min(R, Pre), Pre − Post) = R (since R = Pre − Post ≤ Pre) | j_miss = 0 by construction |
| squash | Tip = M, and tree(M) = tree(S), where S's diff equals the segment diff (pid) | Removals in the segment normally land. If the target held fewer copies than the segment removed, req caps them. j_miss > 0 only if M's merge result kept a target-held copy: a real non-landing, correctly reported |
| ancestry-merge | — | The case R7-01 exposed; now caught |

**Additions.** k checks additions against Tb and Tn, so an addition that did not land, or did not survive, fails k = K. No separate landing quantity is needed. Additions and removals are therefore both required to be reflected.

**Content state.** First match wins. The additions threshold is exactly k = K [B-18].

| # | Condition | State | content_basis |
|---|---|---|---|
| 1 | ΣA + ΣR + #opaque = 0 | unassessable | `-` |
| 2 | K + J + B = 0 | superseded [P-06 · PDB as stated; **if rejected:** merged into "insufficient" → K22] | `-` |
| 3 | K > 0 | sufficient iff k = K ∧ b = B ∧ **j_miss = 0**. j_abs and j_inc are reported, not required [UR-14]. | `added` |
| 4 | K = 0, J > 0 | sufficient iff **j_miss = 0 ∧ j_inc = 0** ∧ b = B [P-07 · PDB as stated; **if rejected:** state 4 is always insufficient → K22] | `removed` |
| 5 | otherwise | sufficient iff b = B | `opaque` |

Insufficient → content-missing.

**j_miss is normative, not PROPOSED.** It closes a known false-MERGED path (safety invariant). It is stricter than R7 in states 3 and 4, and it does not weaken k = K. See N-10.

### 1.8 Integration algorithm — R8Δ (R7-05)

#### 1.8.1 Present C (unchanged)

```
if np(C) ≥ 3:                                  K02   [P-16 · PDB: K02; if rejected: proceed as for np ≤ 2]
P := oldest X ∈ FP with C ⊑ X
if P = C:      I := (ancestry-direct, base=parent0(C), tip=C, end=C, integrating=C, merge=-, anchor=C)
elif np(P) ≥ 3:                                K05
elif np(P) = 2:

     I := (ancestry-merge, base=P^1, tip=P, end=P^2, integrating=P, merge=P, anchor=C)
else:          raise C12
→ FINALIZE(I)
```

#### 1.8.2 Absent C

**M1 (endpoints)**
- refs = `for-each-ref --contains C refs/remotes/origin/`, minus development and HEAD [P-04 · PDB: remote-tracking only; **if adopted:** plus `refs/heads/`].
- E = `rev-list C <refs…> --not T`.
- ord: a parents-before-children Kahn order on E (smallest OID first among ready nodes), counted from 0. X ⊑ Y with X ≠ Y implies ord(X) < ord(Y).

**Endpoint merge bases (R8Δ: one rule, R7-05).** For X ∈ E in **ascending ord**, compute n = |merge-base --all X T|. **The first X with n ≠ 1 decides:**

| Row | Condition | Result |
|---|---|---|
| K27 | n = 0 | AMBIGUOUS (no-common-history) |
| K08 | n > 1 | AMBIGUOUS (multiple-merge-bases) [P-02 · PDB K08; **if rejected:** that X is dropped from E and the scan continues] |

§4 implements exactly this.

**M2** (unchanged)
- RANGE = rev-list T --not NB.
- SSHAPE = GitLab pairs with M ∈ FP ∩ RANGE.
- SOTHER = non-merge commits of RANGE, excluding SSHAPE S commits.
- PMAP_S and PMAP_O map pid → entries; NULL pids are dropped.

**M3–M4** (unchanged)
- p = pid(B_X, X).
- A pair is kept iff B_X ⊑ S^1 and the pair predicates hold.
- Shape hits are h = (X, b = B_X, S′).

**M5 (chaining)**
- Take X2 in ascending ord.
- For each v with X_v ⊑ X2, X_v ≠ X2, in descending (pos(M_v), ord(X_v)): accept (S2, M2) ∈ PMAP_S[pid(X_v, X2)] iff
  - M_v ⊑ S2^1,
  - pos(M2) > pos(M_v), and
  - v is the maximal previous match.

**M6** (unchanged). (X, b, …) covers C iff C ⊑ X ∧ C ⋢ b. This applies to V entries and to shape hits.

**M7**
1. Cmin = the covering V entries with minimal pos(M), i.e. the earliest integration.
2. If Cmin has a single distinct X, choose by (OID(base), OID(S)).
3. If Cmin has more than one distinct X → **K25** [P-24 · PDB: K25; **if adopted (a):** max brank, then min ord(X), then OIDs; **(b):** min ord(X), then OIDs; **if rejected:** K25].
4. I = (squash, base S^1, tip M, end X, integrating S, merge M, segment (base, X), anchor S). This is K09.

| Row | Condition | Result |

## 6. Revert and event-ordering specification — R8Δ (R7-11)

**6.1 Patches.**
- u_I = pid(I.base, I.tip), u_C = pid(parent0(C), C).
- r_I = pid(I.tip, I.base), r_C = pid(C, parent0(C)).
- U = {u_I, u_C} \ {NULL}; Rv = {r_I, r_C} \ {NULL}.
- K15 applies when U ∪ Rv = ∅.

**6.2 Records.** For each E ∈ `rev-list T --not I.tip` (≤ 5,000, else C08):
- e = pid(parent0(E), E) if np(E) ≤ 1; otherwise pid(E^1, E).
- NULL means no record. A failure raises C11.
- **Kind (R8Δ):**
  - if e ∈ Rv, the kind is **revert**, even when e ∈ U as well. This precedence is fail-closed.
  - else if e ∈ U, the kind is **reapply**.

**6.3 Lineage** [P-13 · PDB: as stated; **if rejected:** out-of-lineage revert records are ignored]
- A record qualifies iff I.anchor ⊑ E.
- A revert with anchor ⋢ E → K16.

**6.4 Identity / dedup** [P-14 · PDB: none]
- Each record is its own event.
- If P-14 is adopted, only D1 and D2 collapse records.

**6.5 Ordering** [P-15 · PDB: total order required]
- Order is by ancestry of representatives; timestamps are never used.
- No total order → K17.
- has_revert = at least one revert event exists.

**6.6 Decision order.** K15 → K16 → K17 → K18 → K26 [P-22] → K19.

**6.7 Boundary.**

| Situation | Result |
|---|---|
| Exact revert | K18 |
| Revert then reapply | K26 (PDB) |
| Identical-inverse unrelated change | Revert |
| Partial or drift revert | Not an event; backstops K19, K22 (now including j_miss), CV2 |
| Semantic revert | Not detected |
| Outside lineage | K16 |
| No total order | K17 |

The absence of a detected revert never proves no revert happened.
