## 1. Normative specification

### 1.1 Scope and terms

**Scope [B-01, B-02].** A read-only helper plus isolated adversarial fixtures. It replaces A2.5 Observe step 4 only. The helper emits one output line, including a `caveats` field (R7Δ, R6-05). Observe prints the line, the §1.10 wording for `recommend`, and the fixed caveat text for each caveat token, in token order. Observe derives nothing itself.

**Non-goals:**
- D2–D5 and A2.6;
- deployment, production or completion status;
- attributing a change to a merge request or an author;
- writing to any repository;
- memory, status or NEXT changes;
- semantic revert detection;
- local `.git` forgery (outside the threat model).

**Terms**

| Term | Definition |
|---|---|
| T | Object id of `refs/remotes/origin/development`, resolved once. Never local `development`. |
| X ⊑ Y | `merge-base --is-ancestor X Y`: exit 0 = true, 1 = false, any other exit → C10. |
| present(X) | X ⊑ T. |
| np(X) | Parent count of X, from a strict parse of `cat-file commit X`. |
| parent0(X) | X^1, or the empty tree `4b825dc642cb6eb9a060e54bf8d69288fbee4904` when np(X) = 0. |
| paths(C) | `diff-tree -r --no-renames --name-only -z parent0(C) C`, NUL-split, sorted bytewise. |
| FP | `rev-list --first-parent T`, newest to oldest. pos(X) is the index from the oldest end. |
| P | When present(C): the oldest X ∈ FP with C ⊑ X. |
| GitLab pair (S, M) | M ∈ FP, np(M) = 2, S = M^2, np(S) = 1, S^1 = M^1, tree(S) = tree(M). [M] 3/3 in the target project. |
| I | Integration evidence: (via, base, tip, end, integrating, merge, segment, anchor). |
| CU | Candidate unit (parent0(C), C) over paths(C). The only unit whose content is assessed. |
| IU | Integration unit (I.base, I.tip). Used for revert matching and diagnostics only. |

### 1.2 Inputs — R7Δ (R6-14)

**Argument grammar.** Only the separate-argument form is accepted; `--opt=value` is not.

**Phase A rows.** Evaluation order is fixed and the first match wins. The order is the table order, not the numeric order.

| Order | Row | Condition | Result |
|---|---|---|---|

| 2 | **A06** R7Δ | `--repo` absent, or given more than once | bad-input |
| 3 | **A07** R7Δ | number of positional arguments ≠ 1 | bad-input |

| 5 | A05 | `--now` invalid: fails `TS` syntax; not a real calendar instant (month 13, Feb 30, hour 24, second 60); outside 1970-01-01T00:00:00Z … 9999-12-31T23:59:59Z; or given more than once | bad-input |

`--trace-argv` given more than once is caught by A08 (a repeated non-repeatable option counts as unknown usage).

**Clock (R7Δ).**
- `now` is sampled **once**, immediately after phase A succeeds and before snap0a.
- It is held as integer seconds UTC: floor of the system time, or the `--now` value.
- **Precision:**
  - Reflog `ts` values are integer seconds and are compared directly.
  - FETCH_HEAD mtime is compared as `floor(mtime_ns / 10^9)`. It is "future" iff that value is greater than `now`; the same second is not future.
  - The 24 h check is integer arithmetic: `0 ≤ now − observed_at ≤ 86400`.

**Test-only inputs.** Observe never passes these:
- `--now` and `--trace-argv`;
- a harness callback interface that exists only when the helper is imported as a library: phase hooks (after-snap0, after-classify, between-snap0-files) and git-result substitution. It has no CLI exposure.

### 1.5 Snapshot model — R7Δ (R6-03, R6-09)

**File records:** (relpath bytes, kind ∈ {absent, regular, dir}, st_dev, st_ino, size, mtime_ns, ctime_ns, sha256) [P-17 · PDB: include ctime and inode].
- `O_NOFOLLOW`; each path must resolve inside realpath(`.git`); regular files ≤ 4 MiB.
- A symlink, FIFO, device, oversized or unreadable entry in scope is a read failure.

**Scope:**
- `config`, `packed-refs`, `FETCH_HEAD`, and the C04 files;
- everything under `refs/heads/`, `refs/remotes/origin/`, `refs/replace/` and `logs/refs/remotes/origin/`, recursive and sorted.

**Ref record (R7Δ, R6-09).** `S0r` = (T, RAW, H), where:
- RAW is the exact byte output of `for-each-ref --format='%(objectname) %(refname)' refs/heads/ refs/remotes/origin/`;
- H = SHA-256(RAW).

Freshness (F16) reads tracking-ref values **from RAW** in S0r. No separate read is made. Equality compares (T, H).

**Snapshot completeness.** Every output line carries `snapshot=`:

| Value | When | Meaning |
|---|---|---|
| `full` | S0r and S1r both taken and equal, file records equal | Equal within the full scope; **not proof of stability** |
| `files-only` | S0r never taken (failure before or inside `snap_refs`); file records equal | Ref-level state not compared |
| `none` | phase A failure or B01 | No comparison made |
| `final-unreadable` | D01 | Final snapshot unreadable; stability not claimed |

D02 carries `full` or `files-only`: the scope of the comparison that found the difference.

**Invariants (R7Δ):**
- **I-1.** Every classified line (a K result) has `snapshot=full`. A K result can only be produced after S0r exists. An implementation that reaches a K result without S0r emits C14.
- **I-2 (restated, R6-03).** A `files-only` comparison may let **only a TOOL_FAILURE provisional result** stand (any C row, whatever phase it came from). It never lets a K result stand.
- **I-3.** No line with `snapshot` ≠ `full` may be described as having verified stability. Such a line always carries caveat token `CV4` (§1.10).

**S0r is explicit (R7Δ).**
- `phaseC` returns `(prov, S0r)`.
- Every failure raised inside phase C carries the S0r value current at the moment it was raised: `NONE` if `snap_refs` had not completed, otherwise the record.
- §4 never relies on a side effect to learn whether S0r was taken.

**Which snapshot value each C row can produce:**
- C01–C07 occur before `snap_refs`, so always `files-only`.
- C10 from `snap_refs` itself gives `files-only`; C10 from a later git call gives `full`.
- C08, C09, C13, C14 can occur before `snap_refs` (preflight) or after it, giving `files-only` or `full` by phase.
- C11, C12 and C15 occur only in classification, so always `full`.

**Control flow** (§4):
- B01: the initial file snapshot is unreadable.
- An exception in phase C becomes a provisional C row, and the final snapshot is still attempted.
- D01: the final snapshot is unreadable.
- D02: the snapshots differ; this overrides every provisional result.
- D00: the snapshots are equal; the provisional result stands.

**Detects [R]:** torn reads (snap1 re-reads every file), and change-then-restore within scope via ctime [UR-12].

**Residuals:** the object store; anything outside scope; changes within one ctime tick on a coarse filesystem; privileged clock manipulation; transient states that git calls observed and that were restored within one ctime tick. No atomicity or race-freedom is claimed.

### 1.6 Freshness model — R7Δ

#### 1.6.1 Inputs

All taken from snap0 bytes, stats and S0r.RAW:
- TR = `logs/refs/remotes/origin/development`;
- OR = every file under `logs/refs/remotes/origin/`, which includes TR;
- FETCH_HEAD and its mtime_ns;
- config: `remote.origin.url` (all), `remote.origin.fetch` (all), every `remote.*.url` and `remote.*.fetch`, and whether insteadOf / pushInsteadOf is present;
- `now` (§1.2).

#### 1.6.2 Reflog grammar

```
^([0-9a-f]{40}) ([0-9a-f]{40}) [^<\n]* <[^>\n]*> ([0-9]+) ([+-][0-9]{4})\t([^\n]*)$
```

- Fields: old, new, ts (integer epoch seconds), tz (ignored).
- cmdline = the message up to the first `": "`, or the whole message if there is none.
- The last line of a file is its newest entry.

#### 1.6.3 R rows — target reflog (R7Δ, R6-08)

**Origin mapping is standard (OMS)** iff both hold:
- `remote.origin.fetch` is exactly one value, `+refs/heads/*:refs/remotes/origin/*`;
- no other remote's `remote.<name>.fetch` value has a destination under `refs/remotes/origin/`.

**Accepted cmdlines (RA, closed grammar)** [P-12, P-20 noted inline]:

```
RA        = fetch-form / pull-form
fetch-form= "fetch" *(SP fopt) [SP "origin" *(SP src)]
pull-form = "pull"  *(SP popt) [SP "origin" *(SP src)]
fopt      = "--prune" / "-p"
popt      = "--tags" / "--rebase" / "--no-rebase" / "-r" / "--ff-only"
src       = 1*(ALPHA / DIGIT / "." / "_" / "/" / "-")   ; must not start with "-" or "."
```

- **Bare forms** (no `origin` token) are accepted only when `origin` is the **only** configured remote.
- **Rejected** (→ R6): a remote other than `origin` (including `.` and any URL); any `src` containing `:`, `+`, `*`, `^` or `~` (explicit destination or refspec); any option not listed; `--all` and `--multiple` [P-12 · PDB: rejected]; `update by push` [P-20 · PDB: rejected].
- **What acceptance establishes [R]:** only that the local reflog records an update by a fetch or pull of the configured `origin` remote through the standard mapping. Parsing a command line **does not prove the remote's state**; that rests on local evidence (L-7, L-8).

| Order | Row | Condition | Class |
|---|---|---|---|
| 1 | R1 | TR absent or empty | NONE |
| 2 | R2 | any malformed line | CONTRA(malformed) |
| 3 | R3 | some earlier line has ts > the last line's ts | CONTRA(non-monotonic) |
| 4 | R4 | last new ≠ T | CONTRA(newest-not-T) |
| 5 | R5 | last ts > now | CONTRA(future) |
| 6 | R6 | last cmdline ∉ RA | INSUF(newest-unaccepted, v = ts) |
| 7 | **R8** R7Δ | cmdline ∈ RA but OMS fails | INSUF(nonstandard-origin-mapping) |
| 8 | R7 | otherwise | POS(ts) |

Future timestamps in TR are caught by R5 (the newest line) or R3 (an earlier line later than the newest). FETCH_HEAD and other OR files are covered by F03 and F08.

#### 1.6.4 F rows — FETCH_HEAD (R7Δ: R6-06, R6-11, P-08 tags)

**Definitions:**
- **norm(u):** (a) strip userinfo; (b) remove one trailing `/`; (c) remove one trailing `.git`. Byte-exact, case-sensitive.
- **Origin lines:** norm(url) = norm(remote.origin.url).
- **Dev lines D:** origin lines of the form `branch 'development'`.
- **Any-dev lines D\*:** every line of the form `branch 'development'`, whatever its URL.
- **WF** [P-08 · PDB: as listed]: `fetch`, `fetch origin`, `fetch --prune`, `fetch --prune origin`, `fetch origin --prune`, `fetch -p`, `fetch -p origin`, `fetch origin -p`. Bare forms count only when origin is the only remote. `--all` forms [P-12 · PDB: excluded].
- **ts\* and Enew (R7Δ, R6-06)** [P-08]:
  - Let OR⁺ be the OR files that contain at least one line.
  - Let LAST be the set of the last lines of the files in OR⁺. All OR files are known to be well-formed by this point (F07 is evaluated first).
  - If LAST = ∅, then ts\* and Enew are **undefined** and only F09 can fire.
  - Otherwise ts\* = max{ l.ts : l ∈ LAST } and Enew = { l ∈ LAST : l.ts = ts\* }.

**Evaluation order (deterministic).** One pass, in this order:

| Step | Row | Check | On failure |
|---|---|---|---|
| 1 | F01 | FETCH_HEAD absent or empty | NONE / `none`; stop |
| 2 | F02 | a line fails `^([0-9a-f]{40})\t(not-for-merge)?\t(branch\|tag\|remote-tracking branch) '([^'\n]*)' of ([^\n]+)$` | CONTRA / `malformed`; stop |
| 3 | F03 | floor(mtime_ns/10⁹) > now | CONTRA / `future`; stop |
| 4 | F04 | insteadOf / pushInsteadOf present | go to step 4a |
| 5 | F05 | `remote.origin.url` not single-valued | go to step 4a |
| 4a | **F23** R7Δ (R6-11) | (reached only from F04 or F05) some line in D\* has sha ≠ T | NEG / `negative-conflict-unattributed` [P-23 · PDB: NEG]; stop |
| 4b | F04 / F05 | (reached only from F04/F05 with no mismatching D\* line) | INSUF / `inadmissible-insteadof` or `inadmissible-remote-url`; stop |
| 6 | F06 | refspec not OMS [P-08] | record fc if none yet; continue |
| 7 | F07 | any OR file malformed [P-08] | record fc; ts\*/Enew undefined; **skip steps 8–15** |
| 8 | F09 | LAST = ∅ [P-08] | record fc; ts\*/Enew undefined; **skip steps 9–15** |
| 9 | F08 | ts\* > now [P-08] | CONTRA / `future`; stop (**CONTRA overrides any fc**) |
| 10 | F10 | Enew cmdlines not all identical [P-08] | record fc |
| 11 | F11 | Enew cmdline ∉ WF [P-08] | record fc |
| 12 | F12 | `--all` form with more than one remote (reachable only if P-12 adopted) [P-08, P-12] | record fc |
| 13 | F13 | a non-origin line present [P-08] | record fc |
| 14 | F14 | duplicate `branch '<n>'` names among origin lines [P-08] | record fc |
| 15 | F15 | content link: for each e ∈ Enew with new ≠ 0{40}, the origin line `branch '<name>'` (name = e's ref minus `refs/remotes/origin/`) must exist once with sha = e.new [P-08] | record fc |
| 16 | F16 | completeness: excluding development and HEAD, origin branch lines must be in bijection with the tracking refs listed in S0r.RAW, with equal values [P-08] | record fc |
| 17 | F17 | \|floor(mtime_ns/10⁹) − ts\*\| > W [P-08, P-11 · PDB two-sided; UR-1 · W = 120 s provisional]. Evaluated only when ts\* is defined. Diagnostic `uncorroborated-no-reflog` when ts\* < mtime_s − W. | record fc |

**"Corroborated" = no fc recorded.** Only the first fc is kept.

**Development decision** (after step 17; evaluated in this order):

| Row | Condition | Class / fetch_head |
|---|---|---|
| F19 | corroborated ∧ some D.sha ≠ T | NEG / `negative-conflict` [B-12 under P-08's definition of corroboration] |
| F21 | not corroborated ∧ some D.sha ≠ T | NEG / `negative-conflict-uncorroborated` [P-01 · PDB: NEG] |
| F20 | corroborated ∧ \|D\| = 0 | NEG / `negative-dev-absent` [P-10 · PDB: NEG] |
| F22 | corroborated ∧ \|D\| = 1 ∧ D.sha = T ∧ **G-F CLOSED** | INSUF / `unverified-association` |
| F18 | corroborated ∧ \|D\| = 1 ∧ D.sha = T ∧ **G-F OPEN** | POS(ts\*) / `ok` (unreachable in R7) |
| — | otherwise (not corroborated, no mismatching D) | INSUF / the fc row and its token |

**FROW selection (R7Δ).** The single FROW reported is:
- the terminal row if F evaluation stopped (F01, F02, F03, F08, F23, F04, F05);
- else the development-decision row if one matched (F18–F22);
- else the fc row.

**Every input therefore has exactly one FROW.**

**What the corroboration checks would establish if G-F opened [R; UR-8, UR-10, UR-1, UR-7, UR-9].** They establish nothing positive while CLOSED. They are unverified as an association proof. mtime is used only in F03 and F17, only as the file's last-write time; it is never a line timestamp and never becomes observed_at [B-11].

#### 1.6.6 Gate G-F (R7Δ, R6-12)

#### 1.7.3 Candidate-unit content (R7Δ)

**Path kinds and line counting.** Per p ∈ paths(C), using `ls-tree` and `cat-file blob` only:
- ⊥ marks an absent path.
- **Opaque** (gitlink, symlink, or a NUL byte in the first 8,000 bytes of Pre or Post) paths are compared by OID.
- **Text lines:** split on `\n`; drop lines that are all whitespace; otherwise byte-exact.
- X(L) is the count of line L in blob(X, p).

**States:**

| State | Commit |
|---|---|
| Pre | parent0(C) |
| Post | C |
| End | I.end |
| Tb | I.base (target before integration) |
| Tip | I.tip (target state that integrated C) |
| Tn | T (target now) |

`Tip` is new in R7.

**Quantities** (per line L, summed over paths):

| Quantity | Definition | Meaning |
|---|---|---|
| A(L) | max(0, Post − Pre) | added by C |
| R(L) | max(0, Pre − Post) | removed by C |
| S_A | min(A, max(0, End − Pre)) | additions surviving to the integrated branch state |
| S_R | min(R, max(0, Pre − End)) | removals surviving to the integrated branch state |
| superseded | Σ(A − S_A) + Σ(R − S_R) + opaque paths with OID(End) ≠ OID(Post) | — |
| k / K | Σ min(S_A, max(0, Tn − Tb)) / ΣS_A | additions present beyond the target's pre-integration count (unchanged) |
| **j_abs** R7Δ | Σ { S_R(L) : Tn(L) = 0 } | removed lines with **zero copies** in T now |
| **j_inc** R7Δ | Σ min(S_R, max(0, Tn − Tip)) | copies of removed lines **added to T since the integration point**; a count fact, not provenance |
| J | ΣS_R | — |
| B / b | B = opaque with OID(End) = OID(Post); b = members of B with OID(Tn) = OID(Post) | — |

**Why Tip and not Tb or Pre [R].**
- Removals are judged against the integration point because the target cannot lose a line it never had. In the R6-01 counterexample, L0 had 0 copies in Tb, Tip and Tn, so j_inc = 0 and j_abs = 1. No false "present again".
- Measuring against Pre (the reviewer's suggestion) can mislead when the target independently held extra copies. Example: Tb = 2, Pre = 1, C removes 1, Tip = 1, Tn = 1. Then Pre − Tn = 0, which reads as "not removed", although nothing changed since integration.
- j_inc measures only change since integration, so it is 0 here. **j_inc does not claim the reappearance came from a revert or from C's line**; CV-2 wording reflects that.

**Content state** (first match wins; additions threshold exactly k = K [B-18]):

| # | Condition | State | content_basis |
|---|---|---|---|
| 1 | ΣA + ΣR + #opaque = 0 | unassessable | `-` |
| 2 | K + J + B = 0 | superseded [P-06 · PDB: as stated] | `-` |
| 3 | K > 0 | sufficient iff k = K ∧ b = B. **j_abs/j_inc are reported, not required** [UR-14] | `added` |
| 4 | K = 0, J > 0 | sufficient iff **j_inc = 0** ∧ b = B [P-07 · PDB: as stated] | `removed` |
| 5 | otherwise | sufficient iff b = B | `opaque` |

Insufficient → content-missing.

**P-07 change (flagged).** State 4 in R6 required "removals still absent relative to Tb". R7 requires "no copies added since integration". This is **less closed** than R6 for branch-local removals: they now become MERGED where R6 made them AMBIGUOUS. R6's result there was shown false (R6-01). See §11 (N-1).

### 1.8 Integration algorithm — R7Δ (R6-07, R6-15, R6-17)

#### 1.8.1 Present C (C ⊑ T) (unchanged)

```
if np(C) ≥ 3:                                  K02   [P-16 · PDB: K02]
P := oldest X ∈ FP with C ⊑ X
if P = C:      I := (ancestry-direct, base=parent0(C), tip=C, end=C, integrating=C, merge=-, anchor=C)
elif np(P) ≥ 3:                                K05
elif np(P) = 2:
     require C ⊑ P^2 ∧ C ⋢ P^1                 else raise C12
     I := (ancestry-merge, base=P^1, tip=P, end=P^2, integrating=P, merge=P, anchor=C)
else:          raise C12
→ FINALIZE(I)
```

Rows K06–K12 and K25–K27 apply only when ¬present(C).

#### 1.8.2 Absent C (C ⋢ T)

| Row | Condition | Result |
|---|---|---|
| K03 | np(C) ≥ 2 | unsupported-merge-input |
| K04 | np(C) ≤ 1 ∧ paths(C) = ∅ | empty-commit |
| K06 | NB := merge-base --all C T; \|NB\| = 0 | no-common-history |
| K07 | \|NB\| > 1 | multiple-merge-bases |

**M1 — endpoints:**
- `refs` := `for-each-ref --contains C refs/remotes/origin/`, minus `refs/remotes/origin/{development,HEAD}` [P-04 · PDB: remote-tracking only; if adopted, `refs/heads/` is added].
- `E := rev-list C <refs…> --not T`.
- **ord (R7Δ, R6-07):** the rank of X in a **parents-before-children** topological order of E. Kahn's algorithm runs on the subgraph induced by E, with edges parent → child. A node becomes ready once all its parents *that lie in E* have been emitted. Among ready nodes, the one with the smallest OID (ascending bytewise) is emitted first. ord counts from 0.
- Consequence: X ⊑ Y with X ≠ Y and both in E implies ord(X) < ord(Y).

**Endpoint merge bases (R7Δ, R6-15).** For each X ∈ E, B_X := merge-base --all X T:

| Row | Condition | Result |
|---|---|---|
| K08 | \|B_X\| > 1 for some X | multiple-merge-bases [P-02 · PDB: K08] |
| **K27** R7Δ | \|B_X\| = 0 for some X (an endpoint with no history in common with T, for example from a merged unrelated history) | AMBIGUOUS(no-common-history) |

K27 replaces R6's C12 for this case.

**M2 (unchanged):**
- RANGE := `rev-list T --not NB`.
- SSHAPE := GitLab pairs with M ∈ FP ∩ RANGE.
- SOTHER := non-merge commits of RANGE, minus every SSHAPE S.
- PMAP_S / PMAP_O: pid → pairs by pos(M) / commits by OID; NULL pids dropped.

**M3–M4 (unchanged):**
- p := pid(B_X, X).
- A pair is kept iff B_X ⊑ S^1 and the pair predicates hold. V entries are (X, base = B_X, S, M).
- **Shape hits** are h = (X, b = B_X, S′) for S′ ∈ PMAP_O[p].

**M5 (chaining; ord as above):**
- For X2 ∈ E in ascending ord, consider each v ∈ V with X_v ⊑ X2 and X_v ≠ X2 (so ord(X_v) < ord(X2) and v was already settled), in descending (pos(M_v), ord(X_v)).
- p := pid(X_v, X2). Accept (S2, M2) ∈ PMAP_S[p] iff all three hold:
  - M_v ⊑ S2^1;
  - pos(M2) > pos(M_v);
  - no v′ ∈ V has X_v′ ⊑ X2, M_v′ ⊑ S2^1 and a greater (pos(M_v′), ord(X_v′)).
- An accepted pair adds the match (X2, base = X_v, S2, M2) to V.

**M6 (covering; R7Δ, R6-17):** a match or hit (X, b, …) **covers** C iff C ⊑ X ∧ C ⋢ b. The same predicate applies to V entries and to shape hits.

**M7 — selection (R7Δ, R6-07):**
1. Cmin := the covering V entries with minimal pos(M), i.e. the earliest integration. Choosing the earliest integration point is normative: it is the first point at which C's change entered T, and §6 examines events after it.
2. Within Cmin:
   - If every element has the same X (End), choose the one with the smallest (OID(base), OID(S)). Base choice does not affect content: End, Tb, Tip and Tn are equal.
   - If Cmin contains **more than one distinct X** → **K25** AMBIGUOUS(integration-selection-ambiguous) [P-24 · PDB: K25].
     - If P-24 is adopted with option (a) "prefer the latest base": choose max brank, then min ord(X), then OIDs.
     - If adopted with option (b) "prefer the earliest endpoint": choose min ord(X), then OIDs.
     - brank(v) := 0 if base_v ∉ E, else 1 + ord(base_v).
3. I := (squash, base = S^1, tip = M, end = X, integrating = S, merge = M, segment = (base, X), anchor = S); `covering` = \|covering\|. This is branch point **K09**.

**Totality vs semantics (R7Δ).** Every tie-break above is total over its domain, but totality does not establish semantic correctness. Where the semantics are a policy (distinct End within Cmin), the PDB fails closed (K25).

**No covering V entry:**

| Row | Condition | Result |
|---|---|---|
| K10 | a shape hit covers C (M6 predicate) | unsupported-integration-shape [B-14] |
| K11 | refs = ∅ | unreachable |
| K12 | cand ≠ ∅ | touched-without-equivalent |
| K13 / K14 | otherwise | LIVE / STALE_REFERENCE |

cand := `rev-list --no-merges --full-history T --not NB -- paths(C)` ∪ {merges G ∈ RANGE with non-empty `diff-tree --cc` on paths(C)} \ {S_v, M_v : v ∈ V}.

**Local-only C (R7Δ, R6-16).** When refs = ∅, C itself is still in E. A local-only C can therefore still be K23/K24 (through X = C), K10 or K12. K11 applies only if no earlier row fires.

#### 1.8.3 FINALIZE

FINALIZE computes EV (§6), PR and CK first, then decides K15–K26 in the order shown in §4. A failure while computing any of them raises the corresponding C row.

- **PR:** count of p ∈ paths(C) with blob(I.base) ≠ blob(I.tip) and blob(T) = blob(I.base), compared by OID; reported as `paths_reverted = n/N`.
- **Diagnostics:** `drift`, `later_commits`, `c_paths_in_unit`.

**REFID (R7Δ, R6-16).**
1. Strip the `refs/remotes/origin/` prefix. If P-04 is adopted, local refs are stripped of `refs/heads/` and prefixed `local/`.
2. Replace any character outside `[A-Za-z0-9._/-]` with `?`.
3. If the result is ≤ 24 characters **and** no other ref in the list sanitises to the same string, emit it.
4. Otherwise emit the first 7 sanitised characters, then `~`, then the first 16 hex digits of SHA-256 of the full refname (24 characters in all).

The result is deterministic and collision-resistant: the probability of a collision is about 2⁻⁶⁴ per pair. It is not collision-free (N-5).

## 6. Revert and event-ordering specification — R7Δ

**6.1 Patches.** u_I = pid(I.base, I.tip); u_C = pid(parent0(C), C); r_I = pid(I.tip, I.base); r_C = pid(C, parent0(C)). Each is a separately computed patch-id of a git-generated diff.
- U := {u_I, u_C} \ {NULL}; Rv := {r_I, r_C} \ {NULL}.
- K15 applies when U ∪ Rv = ∅.

**6.2 Records.** For each E in `rev-list T --not I.tip` (≤ 5,000, else C08):
- e := pid(parent0(E), E) if np(E) ≤ 1, else pid(E^1, E).
- Root commits use the empty tree; octopus commits use the first-parent view.
- A NULL e means E is not a record. A pid failure raises C11.
- **revert** iff e ∈ Rv; **reapply** iff e ∈ U.
- Comparison is exact 40-hex patch-id equality under `--verbatim`.

**6.3 Lineage** [P-13 · PDB: as stated]:
- A record qualifies iff I.anchor ⊑ E.
- A revert record with anchor ⋢ E → K16.
- A reapply record with anchor ⋢ E stays an event.

**6.4 Identity and dedup** [P-14 · PDB: none]:
- Event = (rep, kind). Under the PDB every record is its own event.
- If P-14 is adopted, only D1 (GitLab pair carrier) and D2 (`--no-ff` carrier) collapse events.
- Nothing else collapses events.

**6.5 Ordering** [P-15 · PDB: total order always required]:
- e₁ precedes e₂ iff rep(e₁) ⊑ rep(e₂) and rep(e₁) ≠ rep(e₂). Timestamps are never used.
- Not totally ordered → K17.
- The final kind is the kind of the maximal event.
- `has_revert` = at least one event is a revert.

**6.6 Decision order (R7Δ).**
1. K15
2. K16
3. K17
4. K18 (final event is a revert)
5. **K26** (has_revert, final event is a reapply) [P-22 · PDB: K26; if P-22 is adopted, continue with CV5]
6. K19

**6.7 Detection boundary.**

| Situation | Result |
|---|---|
| Exact full revert of IU or CU, incl. `revert -m 1` | K18 |
| Exact revert, then exact reapply, totally ordered | **K26** under the PDB; MERGED + CV5 only if P-22 is adopted |
| Unrelated change identical to the inverse | treated as a revert |
| Partial revert | not an event; backstops K19 / K22; a re-added removal under state 3 is surfaced by CV2 (L-12) |
| Drift revert | not an event; backstops as above |
| Similar non-identical change | not an event; the content check decides |
| Semantic revert | not detected |
| Revert outside lineage | K16 |
| No total order | K17 |

## 11. New defects and uncertainties found during correction (R7Δ)

- **N-1 (P-07 direction).** State 4 now accepts branch-local removals as sufficient. This is *less* closed than R6, deliberately, because R6's AMBIGUOUS there was false. It needs owner sign-off with P-07.
- **N-2 (usability, [M]).** SPSM's recorded reflog messages include `fetch --all --prune`. Under P-12's PDB this is rejected (R6), so freshness can never be established for SPSM until P-12 is adopted **and** the `--all` behaviour is verified (UR-8). Expect `historical` and `STALE_REFERENCE` results until then.
- **N-3 (B-08 strictness).** Under P-22's PDB, any exact revert followed by an exact re-apply is AMBIGUOUS. Real histories with a revert-and-reland pattern will never be MERGED until the owner decides P-22.
- **N-4 (P-24 cost).** K25 makes net-equivalent multi-endpoint matches (FX-K25b) AMBIGUOUS. This is fail-closed but may affect real squash histories with net-empty commit pairs.
- **N-5 (REFID).** Hashed REFIDs are collision-resistant (64-bit), not collision-free.
- **N-6 (j_inc semantics).** j_inc counts copies added since integration. It cannot tell a reversal from an unrelated addition of an identical line. CV2 says so, but consumers may still over-read it.
- **N-7 (RA strictness).** The RA option sets are closed and small. Legitimate forms such as `fetch --tags origin` or `pull --autostash` fall to R6. This fails closed; the sets can be widened after UR-8 verification.
- **N-8 (F23 breadth).** Under F04/F05, a development line from an unrelated remote with sha ≠ T blocks freshness (P-23). This is fail-closed but may block valid reflog freshness on multi-remote setups.
- **N-9 (Tip for ancestry-direct).** Tip = C and Tb = parent0(C). So j_inc measures copies added since C itself, which is consistent with the other modes. Not independently reviewed.
