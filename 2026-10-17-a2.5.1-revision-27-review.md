### R27-01 — MEDIUM — PV-33 (4) still uses Revision 26's current-text range: (bb) falls outside the binding criterion, and the criterion contradicts §0

### R27-02 — LOW — §1.7.3's S(ii) proof step uses sk, which does not decide S(ii) membership; sk also has two meanings in the current text

**Where:**
- §1.7.3: "sk(X,p) … the key that decides 'content survives' (content, or kind for a tree result)";
- "Every path with a survival class is relevant": "S(ii): sk(End) = sk(Post) ≠ sk(Pre)";
- the restated argument: "S(ii) has sk(End) = sk(Post) ≠ sk(Pre)";
- the fixture rationales FX-K31t ("Post kind text, Pre non-textual → sk = kind; sk(End) = text = sk(Post)") and FX-K31u ("Post text → sk = kind").

**Counterexample:** FX-K21d under the interim.
- p goes binary → text t1, and the branch edits it to t2.
- p is in B, and so in S(ii), because it is kind-changing and its kind survives.
- Under the line-725 definition, sk = content (the result is not a tree), so sk(End) = t2 ≠ sk(Post) = t1. The stated step "sk(End) = sk(Post)" is therefore false for an S(ii) path.
- The same gap applies under Option A for every kind-changing path, and under Option C.
- The conclusion still holds, because kind(End) = kind(Post) ≠ kind(Pre). The new (bb) states the premise correctly ("S(ii) by content or kind under the UR-22 rule in force"), so §1.7.3 and (bb) state the premise differently.
- FX-K31t and FX-K31u use sk = kind for non-text → text. That is the Revision 19–20 meaning, which line 725 no longer gives. This conflicts with the glossary's "one authoritative definition per term" and with PV-20.

**Impact:** there is no outcome effect. But this is the argument (bb) asks reviewers to attack first, and its written proof step fails for a class of members.

**Smallest correction:**
- In both §1.7.3 places, write: "S(ii): either content(End) = content(Post) ≠ content(Pre), or p is kind-changing with kind(End) = kind(Post) ≠ kind(Pre); either way entry(End,p) ≠ entry(Pre,p)."
- In FX-K31t and FX-K31u, replace "sk = kind" with "kind survives (Option B key)", or redefine sk once to match.

### R27-04 — LOW — incorporated §11.86 justifies CV3 with an object-absence claim that is false when two kinds share a blob

**Where:** §11.86, "Current target changed after integration": "Classes 1, 3, 4, 6 and 7: … With +g the result is MERGED + CV3, which is true, **because C's object is not at the branch end**."

**Counterexample (class 6):**
- Pre is the text file p. C replaces it by a symlink to "target", so Post = (120000, blob of the bytes "target").
- The branch converts p back to a regular file whose content is exactly "target". End = (100644, the same blob oid). The kind of End is text = kind(Pre) ≠ kind(Post), and End ≠ Pre, so this is class 6.
- C's blob object is therefore at the branch end. Only its kind and mode changed.
- CV3 is still true ("no longer appear … as this commit left them … do not establish that nothing of the change remains"), but the stated reason is false.
- In the current text, statements about C-opaque results should be content statements, as FX-K23av now is.

**Impact:** there is no outcome or caveat effect. It is a false presence/absence justification inside the current text, which priority 1 targets.

**Smallest correction:** write "because content(End) ≠ content(Post): by content, C's result does not appear as C left it".

**Impact:**
- There is no outcome effect.
- Two parts of the current text disagree about whether the end of the sequence on a FINALIZE run is determined, and therefore whether an injection is reachable there.

**Smallest correction:** do one of the following.
- State that EV's unordered calls are issued inside EV's slot (after the §6.1 pids, before PR), with internal order unspecified.
- Mark both §11.89 FINALIZE rows "when no unordered EV call is issued after DG (L-30)", and extend L-30's "Not determined" list accordingly.
