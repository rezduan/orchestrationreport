## 2. Findings

### HIGH

**R9-01 — §1.7.3, §1.7.4, §1.9 (CV1): structural landing is scoped to the integration unit, not to C. A base that already holds C's change gives a false MERGED.**

Evidence:
- "Paths with e = b have nothing to land; any change of C at p was undone on the branch."
- Squash: "C's surviving content lies in that segment."
- §1.7.4 drops every removal check at Tip except j_inc (Tn − Tip).

**Counterexample A (removals; ancestry-merge; uses the P-07 PDB):**
1. Target F has L in f. On the branch, C removes L.
2. The target's hotfix H removes L identically. The branch back-merges H as G.
3. The target reverts H as R, so L is back.
4. P = `merge --no-ff` (R, G). Then Bu = H, and b = e (both lack L), so f is out of scope. #in-scope = 0, giving `paths_unlanded=0/0`, which counts as vacuously landed.
5. r = t has L. EV only looks after Tip, so it finds nothing. PR = 0.
6. State 4: S_R = 1 and j_inc = max(0, Tn − Tip) = 0.
7. Result: **MERGED K23, recommend=yes**, while L, the line C removed, is present at Tip. R8's j_miss (Tb = 1, Tip = 1) gave K22, so this is a regression.

**Counterexample B (additions; no open item involved):**
1. C adds L. The target's H adds the same L, and the branch back-merges it.
2. The target removes L as R. The merge, or a squash with B_X = H, carries nothing at f, so Tip lacks L.
3. A later target commit Z adds `L` elsewhere in f. Its pid has a different context, so it is not an event.
4. k = min(1, Tn − Tb) = 1 = K.
5. Result: **MERGED**, although C's addition was never at Tip. This is R8-02's "later coincidental line" via a back-merge.

**Squash** has the same hole, since B_X is the back-merged target commit. It also has a within-path variant: the segment touches p elsewhere, but C's line is already settled in B_X.

**Impact:**
- False MERGED with recommend=yes.
- CV1 ("Landing was established …") and §1.9(2) mislead readers.
- PV-17 does not hold. R7-01 and R8-02 are re-opened.

**Smallest correction:**
1. In every mode where Bu ⋢ Pre, require blob(Bu, p) = blob(Pre, p) for every p ∈ paths(C). Otherwise fail closed, with a new K row or K31 and a reason such as `base-predates-commit`.
2. Treat #in-scope = 0, with surviving content (ΣS_A + ΣS_R + surviving opaque > 0), as unverifiable.
3. Correct the "undone on the branch" sentence.
4. Add FX fixtures for counterexamples A and B, in both merge and squash form.

### MEDIUM

**R9-02 — §1.6.3 S2: the authority ends only at `/`, so a loopback host passes.**
- Evidence: "authority = the text after `://` up to the first `/`."
- Counterexample: `https://localhost?@h.example/r` or `https://localhost#@h.example/r`. S3 strips up to the last `@`, leaving `h.example`, which passes as network-form. Under RFC 3986, and by the reviewer's reasoning for curl, the authority is `localhost`. This is [R]; the reviewer cannot verify it.
- Impact: a loopback origin can reach R7 / fresh=yes, which violates PV-18.
- Fix: end the authority at the first of `/`, `?`, `#` or `\`, or fail on any of `?#\` in the authority. Add fixtures.

**R9-03 — §1.6.3 H3: the trigger excludes hex digits, contradicting its own catch list.**
- Evidence: "made only of digits, dots and `x`/`X` hex markers … This catches … `0x7f.1`."
- Counterexample: `0x7f.1` contains `f`, so H3 is skipped. H1's DNS regex accepts it, and H5 does not match it, so it passes as network-form. `0x7f000001` behaves the same way. No fixture covers it.
- Fix: trigger H3 when every label matches `^(0x[0-9a-f]*|[0-9]+)$`, or when the last label is numeric. Add a fixture for `0x7f.1`. N-17 understates this issue.

**R9-04 — §1.6.3 U2 runs before scheme parsing, so every `::` is treated as a transport helper.**
- Counterexamples:
  - FX-R9h `https://[::1]/r` and FX-R9r `https://[::ffff:127.0.0.1]/r` are BINDING with `local-host`. Under the step order they yield `transport-helper`.
  - H4's handling of `::1`, `::` and `::ffff:` is therefore dead code.
  - Every compressed IPv6 origin is refused.
- Impact: binding fixtures contradict the normative rule (PV-18 and RT-01).
- Fix: change U2 to `^[A-Za-z][A-Za-z0-9+.-]*::`, which matches git's helper-prefix syntax.

**R9-05 — §1.6.3 "What OU establishes", CV6 text and the C05 list: repository-local redirection beyond insteadOf is not checked.**
- Evidence: "no repository-local rewriting is configured".
- Counterexample: the reviewer believes these keys exist in git 2.43; this needs verification:
  - `http.proxy`, `http.<url>.proxy`, `remote.origin.proxy`;
  - `http.curloptResolve`, which maps a host to 127.0.0.1;
  - `remote.origin.vcs`, which selects a remote helper;
  - `core.gitProxy`, a command for `git://`.
- Under any of these, a past fetch could have been served locally while u passes OU.
- Fix: add these keys to U1 (FAIL `rewritten`), or narrow the claim and the CV6 text. Add a verification item for the key list.

**R9-06 — §1.10 CV1 broadening is not propagated, so fixtures contradict the rule.**
- Evidence: CV1 now fires iff MERGED ∧ content_basis ∈ {added, removed}.
- Within Revision 9 itself: §7.1 FX-A05d is "MERGED K24 … caveats=-". The default pure addition makes it CV1.
- Incorporated from Revision 8:
  - FX-R7a: caveats=CV6.
  - FX-R7b: K24 historical, caveats=-.
  - FX-K11d: CV6.
  - FX-K16 if-rejected: "K23, CV6".
  - FX-K24c if-rejected: "K23, CV6".
  - FX-K26a/b if-adopted: "CV5, CV6".
  - K23ac: CV6, basis removed.
- Incorporated fixtures still assert the removed field: `unlanded=` on K23aa, K23ac and FX-K22h.
- Revision 8 §6.7, which is incorporated, still says "K22 (now including j_miss)".
- Impact: PV-04, PV-14 and RT-01 fail as written.
- Fix: restate every affected fixture with full caveat lists; withdraw or rewrite K23ac and decide its relation to K23ac′; drop `unlanded` from all incorporated fixtures; amend §6.7.

**R9-07 — Delta mechanism: the incorporation list is incomplete, and abbreviated restatements conflict ambiguously with Revision 8.**
- Evidence: the list names only §1.6.4 F06–F17 and its tables, §2.4 UR-6, §5, §6, §7.1–7.3, §8 and §8.3.

**R9-08 — §1.7.3 K30: false blocks beyond L-18, and the reason overclaims.**
