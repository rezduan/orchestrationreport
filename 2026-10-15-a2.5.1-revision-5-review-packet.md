### 1.5 Snapshot model (R4-03)

**File records.** Each record is the tuple (relpath bytes, kind, st_dev, st_ino, size, mtime_ns, ctime_ns, sha256), where kind ∈ {absent, regular, dir}.
- Files are opened with `O_NOFOLLOW` and must resolve inside realpath(`.git`).
- A regular file is capped at 4 MiB.
- A symlink, FIFO, device, oversize file or unreadable file inside the scope is a **snapshot read failure**.
- Directory records carry st_ino, mtime_ns and ctime_ns, so adding or removing an entry is visible.

**Scope:**
- `config`, `packed-refs`, `FETCH_HEAD`, and the C04 integrity files;
- every entry under `refs/heads/`, `refs/remotes/origin/`, `refs/replace/` and `logs/refs/remotes/origin/`, recursively, sorted by relpath bytes.

**Ref record.** Two values:
- T;
- the SHA-256 of `for-each-ref --format='%(objectname) %(refname)' refs/heads/ refs/remotes/origin/`.

The ref record can only be taken after preflight has passed.

**Equality.** Two snapshots are equal iff their serialised, sorted file-record lists are byte-identical **and** (when both ref records exist) the ref records are byte-identical.

**Control flow:** see §4. These are the outcomes it guarantees:

| Row | Situation | Result |
|---|---|---|
| B01 | Initial file snapshot unreadable | TOOL_FAILURE(snapshot-unreadable-initial). No classification is attempted. |
| — | Classification raises | The exception becomes a provisional TOOL_FAILURE (C08–C15). The final snapshot is still attempted. |
| D01 | Final snapshot unreadable | TOOL_FAILURE(snapshot-unreadable-final), `provisional=<trace>`. **Stability is not claimed.** |
| D02 | Snapshots differ | TOOL_FAILURE(snapshot-changed), `provisional=<trace>`. Overrides every provisional result, including a provisional TOOL_FAILURE. |
| D00 | Snapshots equal | The provisional result stands. |

If the initial ref record could not be taken, only the file records are compared.

**What this detects, and what it cannot [R].**
- **Torn reads are detected.** snap1 re-reads every file after classification. Any in-scope file that changed after its own snap0 read differs in snap1.
- **Change-then-restore (ABA) is detected via ctime** for files in scope. A write updates ctime, and `utime` cannot restore ctime. [U] UR-12 must confirm ctime granularity on the target filesystem.

**Residuals that are not detected:**
- changes to the object store (objects are content-addressed; pack replacement relies on integrity assumptions only);
- changes outside the snapshot scope;
- changes within one ctime tick on coarse-granularity filesystems;
- clock manipulation by a privileged user;
- transient states seen by git calls between snapshots, where the file returns to identical bytes within one ctime tick.

No atomicity or race-freedom is claimed.

### 1.6 Freshness model (R4-05, R4-07)

#### 1.6.1 Inputs

Freshness is computed only from snap0 bytes and stats:
- TR = `logs/refs/remotes/origin/development`;
- OR = every file under `logs/refs/remotes/origin/`, which includes TR;
- `FETCH_HEAD` and its mtime_ns;
- config values `remote.origin.url` (all), `remote.origin.fetch` (all), and `remote.*.url` for every remote;
- whether `url.*.insteadOf` or `url.*.pushInsteadOf` is present;
- the current tracking refs from the ref record;
- `now`.

#### 1.6.2 Reflog grammar

```
^([0-9a-f]{40}) ([0-9a-f]{40}) [^<\n]* <[^>\n]*> ([0-9]+) ([+-][0-9]{4})\t([^\n]*)$
```

- Fields are old, new, ts (UTC epoch seconds) and tz. tz is ignored.
- cmdline is the message up to the first `": "`, or the whole message if there is none.
- File order is write order. The "last line" of a file is its newest entry.

#### 1.6.3 R rows and F rows

These rows are listed with fixtures in §5.

**R (target reflog):**
- An accepted cmdline matches `^(fetch|pull)( |$)` or is exactly `update by push`.
- `update by push` is PROPOSED (P-20).

**F (FETCH_HEAD): definitions.**
- **norm(u)** applies, in order and once each:
  - (a) strip userinfo (`scheme://user[:pass]@` → `scheme://`; scp-form `user@host:` → `host:`);
  - (b) remove one trailing `/`;
  - (c) remove one trailing `.git`.

  Comparison is byte-exact and case-sensitive [B-12 context].
- **Origin lines:** lines whose norm(url) = norm(remote.origin.url).
- **Dev lines D:** origin lines of the form `branch 'development'`.
- **Whole-fetch set WF** [P-08]:
  - `fetch`, `fetch origin`, `fetch --prune`, `fetch --prune origin`, `fetch origin --prune`, `fetch -p`, `fetch -p origin`, `fetch origin -p`;
  - when exactly one remote is configured, also `fetch --all`, `fetch --all --prune`, `fetch --prune --all`, `fetch --all -p` [P-12, UR-8].
  - Any cmdline containing `--append` or a refspec argument is excluded.

**Line-to-fetch association proof (R4-05).** The FETCH_HEAD development line is **associated** with fetch event E* at reflog time ts* only when all of P1–P7 hold. These are rows F09–F17.

| Proof | Requirement | Why it is needed [R] |
|---|---|---|
| P1 (F09) | At least one OR entry exists. ts* = the maximum last-line ts across OR; Enew = those last lines. | No reflog event means no timestamp. B-10 forbids any other source. |
| P2 (F10) | Every Enew line has the same cmdline. | Different cmdlines in the same second means two fetch events, so association is ambiguous. |
| P3 (F11, F12) | That cmdline ∈ WF, including the single-remote condition for `--all` forms. | Only a whole, non-append run of origin truncates FETCH_HEAD and writes a line for every fetched branch [U13]. A partial or append run can leave stale lines from earlier runs. |
| P4 (F13, F14) | Every FETCH_HEAD line is an origin line; no `branch '<n>'` name appears twice. | Lines from another remote, or duplicates, show multiple runs or appends. |
| P5 (F15) | **Content link.** For every e ∈ Enew with `new ≠ 0{40}`, FETCH_HEAD contains the origin line `branch '<name>'` with sha = e.new. | Ties the file's contents to the values this reflog-dated fetch recorded. |
| P6 (F16) | **Completeness.** Excluding `development` and `HEAD`, the origin `branch` lines correspond one-to-one with the current tracking refs `refs/remotes/origin/*`, and each line's sha equals the current tracking value. | The file must be a complete, coherent record of one whole fetch consistent with today's refs. A stale line, a missing branch, or an un-pruned deleted branch fails, and the check fails closed. |
| P7 (F17) | **Window.** `|mtime(FETCH_HEAD) − ts*| ≤ W` (two-sided by default [P-11]). | Uses mtime only as the file's last-write time, to reject files written outside the event window. **mtime is never a line timestamp and never becomes observed_at** [B-11]. |

"Corroborated" means P1–P7 all hold. Corroboration does **not** examine the development line. Development is evaluated afterwards (F18–F21), so a corroborated mismatch is negative evidence [B-12].

**What an associated development line = T establishes [R; UR-10, UR-8, UR-1].** Assume the git 2.43 behaviour in U13 and U11 is confirmed. Then P1–P7 establish that FETCH_HEAD is the output of one whole, non-append origin fetch dated by the reflog at ts* (or of a later rewrite carrying identical values). Its development line therefore records origin's development = T at that fetch, and observed_at = ts*.

- Movement of another ref supplies only the timestamp and the link. It never by itself implies anything about development.
- **If U13 or U11 is disproved by its fixture, F18 is disabled** (F can then yield only INSUF or NEG), and every S1 fixture stays PENDING.

**Residuals (stated):**
- A refspec-less URL fetch that writes FETCH_HEAD without updating tracking refs, followed within W by `--no-write-fetch-head`, can make observed_at overstate by up to W.
- Remote state is observed up to one fetch duration before ts*. This also applies to R.
- The refspec in force at the time of the fetch is unknown.
- A deliberately crafted FETCH_HEAD plus reflog pair is local forgery, which is out of the threat model (FX-F-STALE-c demonstrates this boundary).

#### 1.7.3 Candidate-unit content

Computed per path p ∈ paths(C), using `ls-tree` and `cat-file blob` only.

- **Absent** is a distinct value ⊥.
- **Opaque paths** are compared by OID only. A path is opaque when it is a gitlink (160000), a symlink (120000), or a blob with a NUL byte in its first 8,000 bytes in either Pre or Post.
- **Text lines:**
  - split on `\n`; a non-empty final segment without a newline still counts as a line;
  - lines that are empty after stripping ASCII whitespace are dropped;
  - everything else is compared byte-exact.
  - X(L) is the count of line L in blob(X, p).

**States used:** Pre = parent0(C), Post = C, End = I.end, Tb = I.base, Tn = T.

**Change counts:**
- **Changed lines:** `A(L) = max(0, Post(L) − Pre(L))` and `R(L) = max(0, Pre(L) − Post(L))`. A line moved within the same path cancels out. A move across paths counts as removed from one path and added to the other. A rename is a deletion plus an addition.
- **Surviving lines:** `S_A = min(A, max(0, End − Pre))` and `S_R = min(R, max(0, Pre − End))`. `superseded = Σ(A − S_A) + Σ(R − S_R)`, plus opaque paths with OID(End) ≠ OID(Post).
- **Presence in the target:** `k = Σ min(S_A, max(0, Tn − Tb))`, `K = ΣS_A`, `j = Σ min(S_R, max(0, Tb − Tn))`, `J = ΣS_R`.
- **Opaque counts:** B = opaque paths with OID(End) = OID(Post); b = those of them with OID(Tn) = OID(Post).
- **Mode-only changes** contribute nothing.

**Content state** (first match wins; threshold exactly k = K [B-18]):

| # | Condition | State |
|---|---|---|
| 1 | ΣA + ΣR + #opaque = 0 | unassessable |
| 2 | K + J + B = 0 | superseded [P-06] |
| 3 | K > 0 | sufficient iff k = K ∧ b = B |
| 4 | K = 0, J > 0 | sufficient iff j = J ∧ b = B [P-07] |
| 5 | Otherwise | sufficient iff b = B |

Insufficient → content-missing.

### 1.8 Integration algorithm (R4-02)

#### 1.8.1 Present C (C ⊑ T)

```
if np(C) ≥ 3:                                  K02   (octopus input never classified) [P-16]
P := oldest X ∈ FP with C ⊑ X                  (binary search; "C ⊑ X" is monotone along FP)
if P = C:      I := (ancestry-direct, base=parent0(C), tip=C, end=C, integrating=C, merge=-, anchor=C)
elif np(P) ≥ 3:                                K05
elif np(P) = 2:
     require C ⊑ P^2 ∧ C ⋢ P^1                 else raise C12
     I := (ancestry-merge, base=P^1, tip=P, end=P^2, integrating=P, merge=P, anchor=C)
else:          raise C12                       (P ≠ C with np(P) ≤ 1 cannot be the oldest container)
→ FINALIZE(I)
```

**Predicate answers (R4-02):**
- **P = C** means C lies on T's first-parent chain. The integration point is C itself, already present.
- **P ≠ C** means C entered T through P's second parent. P is present because it is on FP.
- **K05 ("H4" in Revision 4)** is exactly: present(C) ∧ P ≠ C ∧ np(P) ≥ 3.
- **Direct ancestry is never sufficient on its own.** It only establishes I, and FINALIZE must still pass (K15–K22).
- **Squash evidence is required iff ¬present(C).**
- **No early return bypasses a check that applies.** Rows K06–K12 apply only to ¬present(C): merge bases, endpoints and shape matching are meaningless for a commit already in T's history. Every path out of §1.8.1 goes through K02, K05, C12 or FINALIZE.

#### 1.8.2 Absent C (C ⋢ T)

| Row | Condition | Result |
|---|---|---|
| K03 | np(C) ≥ 2 | unsupported-merge-input (np ≥ 3 is caught by K02 first) |
| K04 | np(C) ≤ 1 ∧ paths(C) = ∅ | empty-commit |
| K06 | NB := `merge-base --all C T`; \|NB\| = 0 | no-common-history |
| K07 | \|NB\| > 1 | multiple-merge-bases |

**Matching phases:**
- **M1 (endpoints).**
  - `refs` := `for-each-ref --contains C refs/heads/ refs/remotes/origin/`, minus `refs/remotes/origin/{development,HEAD}` [P-04].
  - `E := rev-list C <refs…> --not T`.
  - The helper orders E itself: topological order (Kahn's algorithm) with OID-ascending tie-break. `ord(X)` is X's rank.
- **K08:** any X ∈ E with \|`merge-base --all X T`\| > 1 → K08 [P-02]. \|…\| = 0 → C12.
- **M2 (target candidates).**
  - `RANGE := rev-list T --not NB`.
  - SSHAPE := GitLab pairs (S, M) with M ∈ FP ∩ RANGE.
  - SOTHER := non-merge commits of RANGE, minus every S in SSHAPE. S and M are one integration.
  - `PMAP_S[pid(parent0(S),S)]` lists pairs by pos(M). `PMAP_O[pid]` lists SOTHER commits by OID. NULL pids are dropped.
- **M3 (first-integration matches).**
  - For each X ∈ E in order, let p := pid(B_X, X), where B_X is X's single merge base.
  - Each pair in PMAP_S[p] gives a raw match (X, B_X, S, M).
  - Each commit in PMAP_O[p] gives a shape hit.
- **M4 (validation).** Keep a raw match iff B_X ⊑ S^1 and the pair predicates hold. The kept matches form V.
- **M5 (chaining).**
  - For each X2 ∈ E in order, consider v ∈ V with X_v ⊑ X2 and X_v ≠ X2, in descending (pos(M_v), ord(X_v)).
  - Let p := pid(X_v, X2). Accept (S2, M2) ∈ PMAP_S[p] iff:
    - M_v ⊑ S2^1;
    - pos(M2) > pos(M_v);
    - no v′ ∈ V has X_v′ ⊑ X2, M_v′ ⊑ S2^1 and a greater (pos(M_v′), ord(X_v′)).
  - On acceptance, V += (X2, base=X_v, S2, M2).
- **M6 (coverage).** `covering := {v : C ⊑ X_v ∧ C ⋢ base_v}`.
- **M7 (selection).**
  - Choose the covering match minimising (pos(M), −ord(base), ord(X), OID(S)).
  - I := (squash, base=S^1, tip=M, end=X, integrating=S, merge=M, segment=(base,X), anchor=S).
  - `covering` = the size of the covering set. → **K09** (branch to FINALIZE).

**When nothing covers C:**

| Row | Condition | Result |
|---|---|---|
| K10 | A shape hit (X, b, S′) with C ⊑ X ∧ C ⋢ b | unsupported-integration-shape (fast-forward squash and cherry-pick-then-merge) [B-14] |
| K11 | refs = ∅ | unreachable |
| K12 | cand ≠ ∅ (defined below) | touched-without-equivalent |
| K13 / K14 | Otherwise | LIVE candidate |

`cand` := `rev-list --no-merges --full-history T --not NB -- paths(C)`, plus each merge G ∈ RANGE with a non-empty `diff-tree --cc --name-only -z --no-ext-diff --no-textconv G -- paths(C)`, minus {S_v, M_v : v ∈ V}.

#### 1.8.3 FINALIZE

FINALIZE always computes EV (§6), PR (path reverts) and CK (content) **before** deciding. It then decides K15–K24 in order. Any failure while computing them raises the matching C row.

**Path reverts (PR):** for p ∈ paths(C), count p when blob(I.base) ≠ blob(I.tip) ∧ blob(T) = blob(I.base). Compared by OID; ⊥ is distinct. Output as `paths_reverted=n/N`, where N is the number of paths with blob(I.base) ≠ blob(I.tip).

**Diagnostics (never decide):**
- `drift`: paths(C) with blob(T) ≠ blob(End);
- `later_commits`: `rev-list --count T --not I.tip -- paths(C)`;
- `c_paths_in_unit`: \|paths(C) ∩ paths(IU)\| / \|paths(C)\|.

#### 1.8.4 Evidence table

| via | base | tip | end | anchor | attribution |
|---|---|---|---|---|---|
| ancestry-direct | parent0(C) | C | C | C | graph |
| ancestry-merge | P^1 | P | P^2 | C | graph |
| squash | S^1 | M | X | S | content-equivalent. Never names an MR, branch or author. |

### 1.9 Outcomes

| Outcome | Meaning |
|---|---|
| MERGED | Historical integration detected and no exact revert detected [B-08]. Not current presence, an unchanged state, deployment or completion. |
| LIVE | No supported integration; no foreign edit to C's paths since NB; fresh target. |
| STALE_REFERENCE | As LIVE, but the target is stale or unknown. |
| GONE | The commit object is absent locally. |
| AMBIGUOUS(reason) | Classification refused for the named reason. |
| TOOL_FAILURE(code) | Execution failure, not a classification. |

### 1.10 Recommendation

| Result | recommend | Fixed wording |
|---|---|---|
| MERGED, fresh=yes | yes | "Integrated into origin/development (observed <observed_at>, fresh); no exact revert detected; presence, deployment and completion are not established." [P-18] |
| MERGED, fresh=no, observed_at ≠ none | historical | **"Integrated as observed at <timestamp>; target is stale; later reverts are not verified."** [B-09] |
| MERGED, observed_at = none | no | Report only [B-19] |
| LIVE | yes | "No integration of this commit found in origin/development as observed at <observed_at> (fresh); this does not establish that the work is unfinished, wanted, or undeployed." [P-18] |
| AMBIGUOUS, STALE_REFERENCE, GONE | no | Report only; at most "Fetch, then re-run?" [B-17] |
| TOOL_FAILURE | (no field) | "merge-status failed: <code>". The commit is treated as unobserved. |

No outcome authorises a write, an `ev:` line, a status move, a NEXT change or a commit.

## 4. Pseudocode (R4-03)

```
main(argv):
  r := phaseA(argv)                                  # A01–A04
  if r is failure: emit(r); exit 2                   # no snapshot, no stability claim

  try:    S0f := snap_files()                        # §1.5
  except SnapshotError: emit(TF(snapshot-unreadable-initial, B01, provisional="-")); exit 2

  S0r := NONE; prov := NONE
  try:
      prov := phaseC(S0f)                            # sets S0r after preflight; returns a K result
  except HelperFailure as f: prov := TF(f.code, f.trace)          # C01–C13, C15
  except BaseException:      prov := TF(internal, C14)            # any other exception

  try:
      S1f := snap_files()
      S1r := snap_refs() if S0r ≠ NONE else NONE
  except BaseException:
      final := TF(snapshot-unreadable-final, D01, provisional=prov.trace)
  else:
      if S1f ≠ S0f or (S0r ≠ NONE and S1r ≠ S0r):
          final := TF(snapshot-changed, D02, provisional=prov.trace)
      else:
          final := prov                                           # D00
  final.recommend := recommend(final)                             # §1.10; none for TF
  emit(final); exit (2 if final is TF else 0)

phaseC(S0f):
  preflight()                                         # C01–C05
  T := resolve_target()                               # C06, C07
  S0r := snap_refs()                                  # failure raises C10
  FR := freshness(S0f, S0r, T, now)                   # §1.6; raises only C10 (config read)
  return decide(C, T, FR)

decide(C, T, FR):
  if not cat-file -e C:              return K01
  if cat-file -t C ≠ commit:         raise C15
  if np(C) ≥ 3:                      return K02
  if C ⊑ T:
      P := oldest_fp_container(C)
      if P = C:                      I := direct(C)
      elif np(P) ≥ 3:                return K05
      elif np(P) = 2:
          if not (C ⊑ P^2 and C ⋢ P^1): raise C12
          I := via_merge(P)
      else:                          raise C12
      return finalize(I, FR)
  if np(C) = 2:                      return K03
  if paths(C) = ∅:                   return K04
  NB := merge-base --all C T
  if |NB| = 0:                       return K06
  if |NB| > 1:                       return K07
  refs, E := M1(C, T)
  for X in E:
      n := |merge-base --all X T|
      if n > 1:                      return K08
      if n = 0:                      raise C12
  M2(); V, hits := M3_M4(E); V := M5(E, V)
  covering := M6(V)
  if covering ≠ ∅:                   return finalize(M7(covering), FR)      # K09
  if covers(hits, C):                return K10
  if refs = ∅:                       return K11
  if cand(C, NB, V) ≠ ∅:             return K12
  return K13 if FR.fresh = yes else K14

finalize(I, FR):
  EV := events(I)          # §6; returns UNDETERMINABLE | UNORDERED | INCOMPARABLE | (kind_final, n)
  PR := paths_reverted(I)
  CK := content(I)
  if EV = UNDETERMINABLE:            return K15
  if EV = UNORDERED:                 return K16
  if EV = INCOMPARABLE:              return K17
  if EV.kind_final = revert:         return K18
  if PR > 0:                         return K19
  if CK = unassessable:              return K20
  if CK = superseded:                return K21
  if CK = insufficient:              return K22
  return K23 if FR.fresh = yes else K24
```

Every `return` names exactly one row in §3, and every terminal row in §3 is reached by exactly one `return` or failure path. Exceptions cannot escape `main`: the final snapshot is always attempted after phase C.

## 6. Revert and event-ordering specification (R4-01, R4-06)

**6.1 Patches (R4-01).** Every pid below is a **separately computed** patch-id of a diff that git generates between the stated endpoints. No identifier is derived arithmetically from another.

| Name | Diff it is computed on | Meaning |
|---|---|---|
| u_I | DIFF(I.base, I.tip) | Forward integration unit |
| u_C | DIFF(parent0(C), C) | Forward candidate unit |
| r_I | DIFF(I.tip, I.base) | Inverse integration unit: endpoints swapped, git produces the inverse diff |
| r_C | DIFF(C, parent0(C)) | Inverse candidate unit |

U := {u_I, u_C} \ {NULL} and Rv := {r_I, r_C} \ {NULL}.

- **K15:** U ∪ Rv = ∅, so detection is impossible and the result is fail-closed.
- If only one unit yields pids, detection proceeds with those pids. For example, a mode-only C inside a larger squash: u_C is NULL, so exact reverts of C alone cannot be detected. Such a C is caught as unassessable at K20.

**6.2 Candidate records.** For each E in `rev-list T --not I.tip` (capped at 5,000, otherwise C08):
- e := pid(parent0(E), E) when np(E) ≤ 1, otherwise e := pid(E^1, E).
- A root E (np = 0) uses the empty tree.
- An octopus E uses its first-parent view.
- NULL e (empty patch) is not a record. A pid failure raises C11.
- If e ∈ Rv the record kind is **revert**; if e ∈ U it is **reapply**. A non-empty unit cannot be its own inverse, so no record has both kinds.

**Comparison** is equality of the 40-hex patch-ids under `--verbatim`. So a record matches only if its diff has the same paths, the same hunks and the same context lines as the inverse (or forward) unit, ignoring line-number offsets.

**6.3 Lineage qualification [P-13].** A record qualifies iff I.anchor ⊑ E, where the anchor is C for the ancestry modes and S for squash.
- A **revert** record with I.anchor ⋢ E means the revert was made on history that did not contain the integrated change, so its order relative to the integration cannot be established → **K16**.
- A **reapply** record with I.anchor ⋢ E is kept as an event: it is an independent application of the same change.

**6.4 Event identity and deduplication [P-14].** An event is identified by (rep, kind), where rep is a commit OID. Two records collapse into one event **only** through a proven carrier relationship.

- **D1 — GitLab carrier.** Records for E_M and E_S, where (E_S, E_M) is a GitLab pair and both have the same kind and the same e. They become one event with rep = E_S.
- **D2 — ordinary merge carrier.** A record for a merge E_M (np = 2) and exactly one record E_X such that:
  - E_X ⊑ E_M^2 and E_X ⋢ E_M^1;
  - E_X has the same kind and the same e as E_M;
  - no other record of either kind lies in E_M^2 but not in E_M^1.

  They become one event with rep = E_X.

**No other deduplication happens.** Sharing a patch-id, an integration point, a timestamp or a branch never collapses events. Two identical exact reverts in different commits are two events (FX-K18f).

**6.5 Ordering [P-15].**
- e₁ precedes e₂ iff rep(e₁) ⊑ rep(e₂) and rep(e₁) ≠ rep(e₂).
- Commit timestamps are never used.
- If every event has the same kind, order is immaterial: all reverts → K18; all reapplies → continue.
- If kinds are mixed, the events must form a total order, otherwise **K17**. The final kind is the kind of the maximal event.
- The integration itself is implicitly first. Every qualifying record descends from I.anchor.

**6.6 Decision.** `events` = the number of events after D1/D2. Then:
1. K15 (undeterminable);
2. K16 (unordered lineage);
3. K17 (incomparable);
4. K18 (final kind is revert);
5. otherwise continue to K19.

A final reapply never establishes MERGED by itself. K19–K22 still apply.

**6.7 Detection boundary.**

| Situation | Handling |
|---|---|
| Exact full revert of IU (including `git revert -m 1 P`) or of CU | **Detected** → K18 |
| Exact revert followed by exact reapply, totally ordered | **Detected** → continues to the content check |
| Unrelated change whose diff is identical to the inverse | **Treated as a revert** (fail-closed) → K18 |
| Partial revert (a subset of paths or lines) | **Not an event.** The backstops are K19 (file restored to pre) and K22 (any of C's surviving added lines removed). **Residual:** a partial revert that re-adds lines C removed, while C also added lines, is not caught. |
| Revert with context drift | Not an event; backstop as above (FX-K22b) |
| Unrelated, similar but non-identical change | Not an event. The content check decides: K22 if C's lines were removed (FX-K22g), K23 otherwise (FX-K23x). |
| Semantic or behavioural revert | Not detected |
| Revert on lineage without the anchor | K16 |
| Mixed kinds with no total order | K17 |

Absence of a detected revert never proves that no revert exists [B-08].
