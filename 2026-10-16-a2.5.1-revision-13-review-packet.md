### 1.2 Inputs

**Argument model**
- argv[0] is the program name and never a positional.
- `--` ends option parsing.
- A value-taking option consumes the next element verbatim, even if it begins with `-`.
- Any other element beginning with `-` is an unknown option (A08). Everything else is positional.
- Options:
  - `--repo <path>`
  - `--now <TS>`
  - `--trace-argv <path>`
  - `--expect-origin <url>` [P-25 · PDB: not accepted → A08; if adopted: accepted, see R10 row]

**Phase A rows** (first match wins, in this order):

|---|---|---|---|

| 7 | A03 | `<repo>` or `<repo>/.git` not a real directory | integrity-refused |
| 8 | A04 | `st_uid(.git)` ≠ euid | unsafe-ownership |

**Clocks**
1. **Monotonic time** is used only for C09 (60 s per call) and C08 (300 s total).
2. **Wall-clock `now`** is integer seconds UTC. Without `--now`, it is floor(time.time()), sampled **once, immediately after snap0a**. With `--now`, it is the given value, and the system clock is not read for `now`.
3. **Stored timestamps** (reflog ts, FETCH_HEAD mtime) come from other processes' clocks.

**Comparisons**
- Integer seconds throughout.
- FETCH_HEAD is future iff floor(mtime_ns/10⁹) > now.
- 24 h means 0 ≤ now − observed_at ≤ 86400.
- A stored time later than `now` gives CONTRA `future`. **This is not a claim that a race occurred.**
- A write after snap0a produces D02.
- Missing data: R1/F01/F09. Malformed: R2/F02/F07. Inconsistent: R3.

**Test-only inputs:** `--now`, `--trace-argv`, and a library-only harness interface ([harness]) with phase hooks, git-result substitution and `time.time` injection.

#### 1.6.2 Reflog grammar

#### 1.6.3 R rows

**OMS:** `remote.origin.fetch` is exactly one value, `+refs/heads/*:refs/remotes/origin/*`, and no other remote's fetch destination lies under `refs/remotes/origin/`.

**RA**

```
RA         = fetch-form / pull-form
fetch-form = "fetch" *(SP fopt) [SP "origin" *(SP (fopt / src))]
pull-form  = "pull"  *(SP popt) [SP "origin" *(SP (popt / src))]
fopt       = "--prune" / "-p"
popt       = "--tags" / "--rebase" / "--no-rebase" / "-r" / "--ff-only"
src        = 1*(ALPHA / DIGIT / "." / "_" / "/" / "-")   ; must not begin with "-" or "."
```

- A bare form (no `origin`) is accepted only if origin is the only remote.
- **Rejected:**
  - any other remote, `.`, or a URL;
  - a `src` containing `:`, `+`, `*`, `^` or `~`;
  - any option not listed above;
  - `--all` / `--multiple` [P-12 · PDB: rejected; if adopted: allowed with a single remote];
  - `update by push` [P-20 · PDB: rejected].
- A command line proves nothing about the remote.

**Scheme URL**

| Step | Rule | On failure |
|---|---|---|
| **SC1** | Lowercase the scheme; it must be one of {https, http, ssh, git} | FAIL `scheme` |
| **SC2** | Authority = text after `://` up to the first `/`, `?` or `#`, or end of string. Must be non-empty. | FAIL `malformed` |
| **SC3** | If the authority contains `@`, userinfo is everything up to the **last** `@`. Userinfo containing `[` or `]` is invalid. Remove the userinfo. | FAIL `malformed` |
| **SC4** | Split host and port: see below | FAIL `malformed` |

**SC4 detail**
- If the remainder starts with `[`: the literal runs to the first `]`; what follows must be empty or `:`PORT; the literal must contain `:`. Then go to HS4.
- Otherwise, if the remainder contains `:`: the part after the last `:` must be a PORT, and no other `:` may appear. The host is what precedes it.
- **PORT = 1–5 digits whose value is 1–65535, applied identically in both branches.** An empty host or invalid PORT → FAIL `malformed`.
- Non-bracketed host → HS1.

**scp form**

| Step | Rule | Result |
|---|---|---|
| **SP0** (R10-04, evaluated first) | Host (group 1) unbracketed and exactly one character | FAIL `local-path` |
| **SP1** | Path (group 2) must be non-empty | else FAIL `malformed` |
| **SP2** | Bracketed host whose content contains `:`: if the content parses as IPv6 (HS4 rules) → HS4; else it must match `^[^:]+:PORT$`, and the host part → HS1; else FAIL `malformed`. Bracketed host without `:`: strip the brackets → HS1. Unbracketed host → HS1. | — |

**Host checks**

| Step | Rule | Result |
|---|---|---|
| **HS1** | Lowercase, then strip one trailing `.`. If every dot-separated label matches `^(0x[0-9a-f]*\|[0-9]+)$` → HS3. Otherwise the host must match `^[a-z0-9]([a-z0-9-]*[a-z0-9])?(\.[a-z0-9]([a-z0-9-]*[a-z0-9])?)*$` and be ≤ 253 characters → HS5. | else FAIL `malformed` |
| **HS3** | more than 4 labels → FAIL `malformed`. 1–4 labels follow inet_aton rules: `0x` prefix = hex (`0x` alone → malformed); leading `0` on a multi-digit label = octal (digits 8/9 → malformed); otherwise decimal. The last label fills the remaining bytes (32 / 24 / 16 / 8 bits for 1 / 2 / 3 / 4 labels). Overflow → malformed. | Value in 127.0.0.0/8 or 0.0.0.0/8 → FAIL `local-host`; otherwise **pass** |
| **HS4** | parse to a **128-bit value** (RFC 4291, `::` compression, embedded dotted IPv4). Zone ids (`%`) or parse failure → FAIL `malformed`. Reject by **value** (see below). | rejected → FAIL `local-host`; otherwise **pass** |
| **HS5** | `localhost`, or a name ending `.localhost` | FAIL `local-host`; otherwise **pass** (`network-form`) |

HS4 rejects these values:
- `::1` (loopback);
- `::` (unspecified);
- `::ffff:0:0/96` (IPv4-mapped) whose low 32 bits lie in 127.0.0.0/8 or 0.0.0.0/8;
- `::/96` (IPv4-compatible) whose low 32 bits lie in 127.0.0.0/8 or 0.0.0.0/8 (`::` and `::1` are already covered above).

Spelling does not matter: `[0:0:0:0:0:0:0:1]`, `[0::1]`, `[::ffff:7f00:1]` and `[::7f00:1]` are all local-host.

**Determinism [R].** The steps are ordered, every step either decides or names exactly one next step, and every predicate is total. Every u therefore reaches exactly one class: network-form, absent, rewritten, malformed, transport-helper, scheme, local-path or local-host.

**What OU establishes, and what it does not.** Passing OU means only that the **repository-local** configuration names origin with a network-form URL, the host is not a recognised loopback, unspecified or `.localhost` value, and no OU1 key is present locally. It does **not** establish any of the following (L-16):
- that the host is public, reachable, trustworthy or canonical;
- name resolution;
- global or system configuration;
- environment variables at the time of the fetch;
- SSH host aliases;
- that the URL has not changed since the fetch.

### 1.7 Patch identity, anchoring, landing and content — R13Δ (R12-01, -05, -06, -08; R12Δ R11-01, -02, -04, -05, -09, -10, -11, -13)

#### 1.7.1 Claims

| Evidence | What it shows |
|---|---|
| Patch-id equality | Net-diff equivalence under the pinned diff (what equality implies is UR-16). It **identifies the integration** (IA3–IA5). It never establishes landing by itself. |
| Entry equality | Identical (mode, type, oid) |
| Line counts | Net per-file counts with **no provenance**. Identical text lines cannot be told apart, so no claim is ever made about *which* copy of a line is C's. |
| **Landing** (R12Δ) | For every relevant path, the integrated state Tip agrees with C's branch end End at that path. **In force (interim, UR-21 open): by state equality only**, entry(Tip,p) = entry(End,p), in every mode. **Only if the owner adopts UR-21 Option A:** **landing-textual** squash paths may also be landed by **count-level** agreement (the target-count guard plus the carried-by-unit check, §1.7.3). That evidence is count-level: it is not provenance, and it does not show that an equal count came from C rather than from an independent equivalent change. |

#### 1.7.2 DIFF and pid

#### 1.7.3 Anchoring and landing (R12Δ)

**States**

| Name | Definition |
|---|---|
| Pre | parent0(C) (the empty tree if np(C) = 0) |
| Post | C |
| End | I.end |
| Tb | I.base (the target before integration) |
| Tip | I.tip |
| Tn | T |
| Bu | Branch-side unit base: Pre (direct); seg_base (squash: B_X for a first-integration match, X_v for a chained match); the single member of `merge-base --all P^1 P^2` (ancestry-merge; 0 → K28, > 1 → K29) |
| **Ht** (R12Δ, R11-04) | **Absorbed-target base** — the newest target state the unit base has absorbed. Ht = Bu for ancestry-merge and first-integration squash (Bu ⊑ T by construction: it is a merge base with the target side). For a **chained** squash (Bu = X_v, which is not in T), Ht is the single member of `merge-base --all X_v T`; 0 or > 1 members → **K34**. For ancestry-direct, Ht = Pre. |

**State kind (R13Δ, R12-01, R12-06).** For a state X and a path p, kind(X,p) is exactly one of:
- **absent** — entry(X,p) = ⊥;
- **tree** (040000), **gitlink** (160000), **symlink** (120000);
- **binary** — a regular blob (100644/100755) with a NUL in its first 8000 bytes;
- **text** — any other regular blob, **including the empty blob** and a blob whose lines are all whitespace.

A state is **textual** at p iff its kind is text or absent. **blob(X,p)** := the oid component of entry(X,p) if kind(X,p) ∈ {text, binary}, else ⊥. Comparisons of blob(·) and entry(·) are therefore always defined (⊥ equals only ⊥). X(L), the count of line L at p, is defined **only for a textual state** (absent counts as 0) and is never computed on a non-textual state.

**C-text and C-opaque paths (R13Δ).** A path p ∈ paths(C) is **C-text** iff Pre and Post are both textual at p; otherwise it is **C-opaque**. This depends on C alone.

**Touched lines.** For a C-text path p whose End state is textual, a line L is **touched** iff S_A(L) + S_R(L) > 0 (§1.7.4). Text comparison drops whitespace-only lines and compares byte-exact.

**Relevant paths — branch-side only (R13Δ, R12-01).** Relevance is decided from **Pre, Post and End only**. Bu, Tb, Tip and Tn never affect it. A path p ∈ paths(C) is **relevant** iff one of:
- (i) p is C-text, End is textual at p, and p has a touched line;
- (ii) p is C-opaque and entry(End,p) = entry(Post,p) ≠ entry(Pre,p);
- (iii) a mode change, mode(Post,p) ≠ mode(Pre,p), with mode(End,p) = mode(Post,p) (mode(⊥) := ⊥);
- (iv) p is C-text, End is textual at p, blob(Pre,p) ≠ blob(Post,p), no line at p has A(L) + R(L) > 0 (a reorder, a whitespace-only change, or adding or deleting an empty or whitespace-only file), and entry(End,p) = entry(Post,p).

A C-text path whose End state is **not textual** has no surviving text change: a later branch commit replaced the file by a non-text object. Its counted changes are **superseded** (§1.7.4). An uncounted change whose End differs from Post is not relevant (L-23). Paths that are not relevant take no part in anchoring or landing.

**Why a surviving change can no longer drop out [R].** Rules (i)–(iv) read only Pre, Post and End. A change that survives to End (counted, uncounted, opaque or mode) satisfies one of them, whatever kind Bu, Tb, Tip or Tn has. Revision 12 classified "opaque" over all seven states, and rule (ii) then required End = Post, so a C-text path with a later branch edit and a target-side binary state fell through every rule (R12-01).

**Landing-textual (R13Δ).** A relevant path is **landing-textual** iff Pre, Post, Bu, End, Tb and Tip are all textual at p. Only a landing-textual path may ever be landed by line counts (UR-21 Option A). Every other relevant path is landed only by state equality (r = e), or by construction in direct mode.

**Step 1 — Anchoring (R12Δ)**

*Scope* [UR-19 · interim: option (a), every relevant path in every mode; option (b): only squash landing-textual paths with r ≠ e, and only if UR-21 Option A is adopted — otherwise anchoring is skipped and AN = ANCHORED; option (c): a finer design, not specified — interim applies].

1. **ancestry-direct:** AN = ANCHORED, Ht = Fk = Pre. **No git call is made** (this also covers a root C, whose Pre is the empty tree — R11-09).
2. **Other modes, np(C) = 0** (C is a root commit reached by a merge or a squash): Fk := ∅ without a git call → **K34**. (`merge-base` is never called with a tree.)
3. **Other modes:** compute Ht (chained squash: `merge-base --all X_v T`; |Ht| ≠ 1 → **K34**). If Ht = Pre, Fk := Pre. Otherwise Fk := `merge-base --all Ht Pre`; |Fk| ≠ 1 → **K34**.
4. C is **anchored** iff entry(Ht,p) = entry(Fk,p) for every relevant p in scope. Otherwise → **K32** (base-not-anchored).

**Behaviour [R]**

| Situation | Result |
|---|---|
| Ht ⊑ Pre (the usual case; direct always) | Fk = Ht, so the equality is **trivially true**. That is not evidence that C landed. |
| Earlier branch commits touched C's paths (C0 then C on f) | No effect. Fk is a fork point, and entry(Fk,f) is compared with entry(Ht,f), not with Pre. |
| **An earlier squashed segment of the same branch changed a relevant path** (chained, R11-04) | **No effect.** Ht is the target state that segment absorbed, not the segment end X_v. FX-K23al. |
| An unrelated back-merge after C's fork (target changes on other paths only) | Anchored. FX-K23ag. |
| A back-merge after C's fork whose absorbed target changes touched one of C's relevant paths — **including a target squash commit that carries the branch's own earlier segment** (FX-K25c) | Entries differ → **K32** (L-20). This happens even when r = e (FX-K23ai). |

**What anchoring does and does not do (R12Δ, R11-10, R11-11).**
- It never establishes landing. Where r = e, C's surviving state at p is in Tip whatever Bu is, so anchoring adds no landing evidence there.
- Its role is an **attribution guard**: it refuses to credit C when the unit base absorbed target changes on C's paths after C's fork (target pre-emption, the R9-01 constructions).
- Under the interim landing rule (state equality only) anchoring is not needed for soundness. Under UR-21 Option A, the target-count guard below closes the vacuous-removal hole that Revision 11 relied on anchoring to close (table below). Whether to keep anchoring universal is UR-19.

**Step 2 — Landing (only if anchored)**

Every relevant p is classified into exactly one of: **landed**, **result-differs**, **unverifiable**, **not-carried**. Let **ub** = entry(Bu,p), t = entry(Tb,p), e = entry(End,p), r = entry(Tip,p) (R13Δ: ub replaces the Revision 12 name b).

**Precedence (R13Δ, R12-05).** Mode is decided first; then, for ancestry-merge and squash only, the type guard; then the mode's table. Direct mode has no type guard.

**ancestry-direct.** Tip = End = C. Every relevant p is **landed by construction**, whatever its kinds (a file replaced by a directory, a symlink, a gitlink or a binary included). No entry comparison is made. `landing=by-construction`.

**Type guard (ancestry-merge and squash only).** If any of entry(Pre,p), entry(Post,p), ub, t, e or r has type `tree`, p is **unverifiable**.

**ancestry-merge.** `landing=by-path-entry`. Line counts are never used for merges.

| Condition | Class |
|---|---|
| r = e | **landed** (state equality: the merge result equals the branch end at p) |
| r ≠ e ∧ t = ub | **result-differs** |
| r ≠ e ∧ t ≠ ub | **unverifiable** |

**squash — interim (UR-21 open; this is Option B).** `landing=by-patch-identity` (the integration was identified by patch identity; landing itself is by state).

| Condition | Class |
|---|---|
| r = e | **landed** (state equality) |
| r ≠ e | **unverifiable** |

This mirrors ancestry-merge, where r ≠ e is never landed. Every squash path whose integrated file differs from the branch end gives K31 (cost: L-21).

**squash — only if UR-21 Option A is adopted (R12Δ, R11-01, R11-02).** Same `landing` token.

| Condition | Class |
|---|---|
| r = e | **landed** (state equality) |
| r ≠ e, and p is **not landing-textual** (R13Δ), or C's surviving change at p includes a mode change, or p is relevant only by (iv) | **unverifiable** |
| r ≠ e, p landing-textual, and the **target-count guard** fails: some touched line L has Tb(L) ≠ Bu(L) | **unverifiable** |
| r ≠ e, p landing-textual, guard holds, and the **carried-by-unit check** holds | **landed** (count-level) |
| r ≠ e, p landing-textual, guard holds, carried check fails | **not-carried** |

**Carried-by-unit check (Option A), for every line L at p:**
- **Additions:** S_A(L) ≤ max(0, End(L) − Bu(L)).
- **Removals:** min(S_R(L), Bu(L)) ≤ max(0, Bu(L) − End(L)).

**What Option A establishes, and what it cannot [R, UR-16].**
- **Identity I-16.** If UR-16 holds, patch-id equality means S's diff has the same per-file changes, at the same paths, as the unit's diff Bu → End. Applying it to Tb = S^1 changes each line count at p by exactly End(L) − Bu(L): **Tip(L) − Tb(L) = End(L) − Bu(L)**.
- **Guard.** If Tb(L) = Bu(L) for every touched L, then by I-16 **Tip(L) = End(L)** for every touched L: on the lines C's surviving change touches, the integrated state and the branch end hold equal counts. Other lines at p may differ (that is why r ≠ e).
- **Guard cost (R13Δ, R12-03).** The guard also rejects correct integrations. It fails whenever the target, before the squash, changed the count of **any** line that C's surviving change touches, **anywhere in the file** — not only near C's change. Lines that are common in a file trip it easily. Example: C adds `</div>` and `<p>x</p>` to a Blade file; before the squash the target edits a different block of the same file and adds one `</div>`. Then Tb(`</div>`) = Bu(`</div>`) + 1, the guard fails, p is unverifiable and the result is K31, although C's lines are in Tip. The same holds for `}`, `});`, `@endif` and `return;`. **How often this happens is unknown and unmeasured.**
- **Carried.** The unit's own diff changes each touched L by at least C's surviving change. This is an attribution condition: it refuses to credit C when the unit's diff does not itself contain the change.
- **Equivalence (R11-01, stated plainly).** By I-16 the guard is exactly "Tip(L) = End(L) for every touched L", and the carried check is exactly a count test on S's own diff: S_A(L) ≤ max(0, Tip(L) − Tb(L)) and min(S_R(L), Bu(L)) ≤ max(0, Tb(L) − Tip(L)). **Option A's landing evidence is therefore entirely count-level.** Patch identity contributes only (1) the selection of the integration and (2) identity I-16, which lets the counts be read off Bu → End.
- **It cannot establish:** which copy of L is C's (L-4); whether an equal count came from C or from an independent equivalent change on the target (L-5); reorderings or whitespace-only changes on the same path (L-23); anything at all if UR-16 fails.

**Which check catches which case (R12Δ, R11-10 corrected).** Derivations in §11.

| Case | Anchoring | Guard (Option A) | Carried (Option A) | Interim (Option B) |
|---|---|---|---|---|
| R10-01 squash, FX-K31j: C re-adds L that the target removed | trivially true | **catches it**: Tb(L) = 0 ≠ Bu(L) = 1 | catches it: End(L) − Bu(L) = 0 < S_A(L) = 1 | unverifiable (r ≠ e) → K31 |
| **R11-02, FX-K31h:** C removes a branch-local L that the target independently added | trivially true | **catches it**: Tb(L) = 1 ≠ Bu(L) = 0 | **passes vacuously**: min(S_R, Bu(L)) = 0 | unverifiable → K31 |
| R9-01 A, FX-K32b: a back-merge absorbed the target's removal of L; the target later restored L | **catches it** (K32) | catches it: Tb(L) = 1 ≠ Bu(L) = 0 | passes vacuously: min(S_R, Bu(L)) = 0 | K32 (anchoring runs first) |
| R9-01 B, FX-K32d: a back-merge absorbed the target's addition of L; the target later removed it | **catches it** (K32) | catches it: Tb(L) = 0 ≠ Bu(L) = 1 | catches it: End(L) − Bu(L) = 0 < S_A(L) = 1 | K32 |
| Cancel within the unit, FX-K33b: C undoes a predecessor's addition | trivially true | passes: Tb(L) = Bu(L) = 1 | **fails** → not-carried (cost) | unverifiable → K31 |

Under Option A the guard alone catches every unsound case listed; anchoring and the carried check add attribution conservatism at a cost (L-20, L-21). The Revision 11 row "R9-01 A/B: carried check fails to catch it" was wrong for B (R11-10): the carried check catches R9-01 B; only the removal case (R9-01 A, and R11-02) passes it vacuously.

**Result of Step 2** (only if anchored):

| Condition | Row |
|---|---|
| any result-differs | **K30** |
| else any unverifiable | **K31** |
| else any not-carried | **K33** (reachable only under UR-21 Option A) |
| else | landed (continue to events and content) |

The reason token of K31, `merge-content-unverifiable`, is historical; it applies to every mode.

**Unrelated evidence cannot mask a relevant path** (FX-K31l, R13Δ). Landing is decided per relevant path, and a single non-landed path decides K30, K31 or K33 before events and content. A landed path elsewhere (for example the g change that let the integration be found) never offsets it.

**paths_unlanded:**
- numerator = #result-differs + #unverifiable + #not-carried;
- denominator = #relevant paths;
- the four classes are disjoint, and each relevant path has exactly one class;
- **0/0 is permitted.** It means no relevant path, in which case content state 1 or 2 decides (K20 or K21), never MERGED.

**K30's meaning.** The merge result at p differs from the branch end while the target side was unchanged. Possible causes: C's change was dropped (`-s ours`); the merger added a fix-up line (an evil merge); a sibling commit's change at p was dropped. The reason token is `merge-result-differs` (L-19).

**K33's meaning (Option A only).** For squash: the target changed p, the target-count guard holds, and the integration unit's net diff does not carry C's surviving change, for example because C undid a predecessor's change within the same unit (FX-K33b). The reason token is `change-not-carried`.

**Withdrawn.** All count-based landing formulas of Revisions 7–9; the Revision 10 claim that `Bu ⊑ Pre` establishes landing; the Revision 11 squash text rule as **in-force** behaviour (it survives only inside Option A, with the guard added); the Revision 11 claim that the squash rule used "neither counts nor patch identity alone".

#### 1.7.4 Content (current-state) checks

These run after anchoring, landing and events. They compare C's surviving change with Tn. **Net counts, no provenance.**

- **C-text and C-opaque paths:** as defined in §1.7.3 (Pre and Post only). C-opaque paths are compared by entry. Line counts X(L) are taken only on textual states (§1.7.3).
- **C-text path with a non-textual End (R13Δ):** S_A(L) = S_R(L) = 0 for every L by definition (no text change survived). Its A and R count toward superseded.
- **Relevant C-text path with a non-textual Tn (R13Δ, R12-01):** C's surviving lines cannot be counted in the current target, so the content state is **insufficient → K22** (applied in states 3–5). Tn(L) is never computed on a non-textual state.
- **Text path:** drop whitespace-only lines and compare byte-exact. X(L) is the count of L in blob(X, p); ⊥ counts as 0.
- **Mode-only changes and uncounted changes** (§1.7.3 (iv)) contribute nothing to the quantities below. They are checked by landing only. **A reordering after integration is not detected** (L-23).

| Quantity | Definition |
|---|---|
| A, R | max(0, Post − Pre), max(0, Pre − Post) |
| S_A, S_R | min(A, max(0, End − Pre)), min(R, max(0, Pre − End)) |
| superseded | Σ(A − S_A) + Σ(R − S_R) + C-opaque paths with entry(End) ≠ entry(Post) |
| k / K | Σ min(S_A, max(0, Tn − Tb)) / ΣS_A [B-18] |
| j_abs / J | Σ{S_R(L) : Tn(L) = 0} / ΣS_R |
| j_inc / J | Σ min(S_R, max(0, Tn − Tip)) / ΣS_R |
| b / B | B = C-opaque paths with entry(End) = entry(Post); b = members of B with entry(Tn) = entry(Post) |

**Content state** (first match):

| # | Condition | State | content_basis |
|---|---|---|---|
| 1 | ΣA + ΣR + #C-opaque = 0 | unassessable (**K20**) | `-` |
| 2 | K + J + B = 0 | superseded [P-06 · PDB; if rejected → insufficient] (**K21**) | `-` |
| 3 | K > 0 | sufficient iff k = K ∧ b = B (j_abs, j_inc reported, not required [UR-14]) | `added` |
| 4 | K = 0, J > 0 | sufficient iff j_inc = 0 ∧ b = B [P-07 · PDB; if rejected: insufficient] | `removed` |
| 5 | otherwise | sufficient iff b = B | `opaque` |

Insufficient → **K22**. **R13Δ:** in states 3–5 the state is also insufficient if any relevant C-text path has a non-textual Tn.

**Zero relevant paths.** If C has no relevant path, landing is vacuous, and content state 1 (K20) or state 2 (K21) decides. MERGED never results. A C whose only change is a mode change or an uncounted change (including adding an empty file, FX-K20d) reaches state 1 (K20) even when landed.


### 1.8 Integration algorithm

#### 1.8.1 Present C

```
if np(C) ≥ 3:                                  K02   [P-16 · PDB: K02; if rejected: proceed]
P := oldest X ∈ FP with C ⊑ X
if P = C:      I := (ancestry-direct, base=parent0(C), tip=C, end=C, integrating=C, merge=-,
                     seg_base=-, lineage_root=C, landing=by-construction)
elif np(P) ≥ 3:                                K05
elif np(P) = 2:
     require C ⊑ P^2 ∧ C ⋢ P^1                 else raise C12
     I := (ancestry-merge, base=P^1, tip=P, end=P^2, integrating=P, merge=P, seg_base=-,
           lineage_root=C, landing=by-path-entry)
else:          raise C12
→ FINALIZE(I)
```

If P = C and np(C) = 2, C's change is diff(C^1, C).

#### 1.8.2 Absent C

| Row | Condition |
|---|---|
| K03 | np(C) = 2 |
| K04 | np(C) ≤ 1 ∧ paths(C) = ∅ |
| K06 | NB := `merge-base --all C T`; \|NB\| = 0 |
| K07 | \|NB\| > 1 |

**IA1 (endpoints)**
- refs := `for-each-ref --contains C refs/remotes/origin/`, minus `refs/remotes/origin/{development,HEAD}` [P-04 · PDB: remote-tracking refs only; if adopted: plus `refs/heads/`].
- E := `rev-list C <refs…> --not T`.
- ord := rank in a parents-before-children Kahn order on E (smallest OID first among ready nodes), counted from 0.

**Endpoint check.** For each X ∈ E in ascending ord, let n := |`merge-base --all X T`|. The first X with n ≠ 1 decides:
- n = 0 → **K27**;
- n > 1 → **K08** [P-02 · PDB: K08; if rejected: drop X and continue].

Otherwise B_X is that single merge base.

**IA2 (target-side candidates)**
- RANGE := `rev-list T --not NB`.
- SSHAPE := GitLab pairs with M ∈ FP ∩ RANGE.
- SOTHER := non-merge commits of RANGE that are not the S of any SSHAPE pair.
- PMAP_S: pid(parent0(S), S) → pairs, ordered by pos(M).
- PMAP_O: pid → commits, ordered by OID.
- NULL pids are dropped.

**IA3–IA4 (first-integration matches)**
- For X ∈ E: p := pid(B_X, X).
- (S, M) ∈ PMAP_S[p] is kept iff B_X ⊑ S^1 and the pair predicates hold. It is added to V with **seg_base = B_X**.
- Each S′ ∈ PMAP_O[p] gives a **shape hit** (X, B_X, S′).

**IA5 (chaining)**
- For X2 ∈ E in ascending ord, and for each v ∈ V with X_v ⊑ X2 and X_v ≠ X2, in descending (pos(M_v), ord(X_v)): accept (S2, M2) ∈ PMAP_S[pid(X_v, X2)] iff M_v ⊑ S2^1, pos(M2) > pos(M_v), and v is the maximal previous entry.
- An accepted pair is added to V as (X2, **seg_base = X_v**, S2, M2).

**IA6 (covering).** (X, base, …) covers C iff C ⊑ X ∧ C ⋢ base. Here base = seg_base for V entries and B_X for shape hits.

**IA7 (selection)** — R12Δ: the anchoring comparison applies only while anchoring is in scope (UR-19)
1. Cmin := the covering V entries with minimal pos(M).
2. If Cmin has more than one distinct X → **K25** [P-24 · PDB: K25; (a): max brank, then min ord(X), then OIDs; (b): min ord(X), then OIDs; if rejected: K25]. Here brank = 0 if seg_base ∉ E, else 1 + ord(seg_base).
3. If Cmin has one distinct X but more than one seg_base:
   - if anchoring is in scope (UR-19), compute Step-1 anchoring (§1.7.3) for each candidate; otherwise go to the last bullet;
   - if the candidates do not all have the same anchoring result (anchored / K32 / K34) → **K25**;
   - otherwise select the minimum (OID(seg_base), OID(S)).
4. If Cmin has a single entry, select it.
5. I := (squash, base=S^1, tip=M, end=X, integrating=S, merge=M, **seg_base**, lineage_root=S, landing=by-patch-identity).

**No covering V entry**

| Row | Condition |
|---|---|
| K10 | a shape hit covers C |
| K11 | refs = ∅ |
| K12 | cand ≠ ∅ |
| K13 / K14 | otherwise |

cand := `rev-list --no-merges --full-history T --not NB -- paths(C)` ∪ {merges G ∈ RANGE with non-empty `diff-tree --cc --name-only -z` on paths(C)} \ {S_v, M_v : v ∈ V}.

#### 1.8.3 FINALIZE

**Compute first:** AN (Bu, Fk and anchoring), LD (per-path classes; only if anchored), EV (§6), PR, CK.

**Then decide, in this order:**
1. K28, K29 (ancestry-merge Bu count)
2. **K34** (Ht or Fk undetermined)
3. **K32** (not anchored)
4. K30, K31, **K33** (landing)
5. K15, K16, K17, K18, K26 (events)
6. K19
7. K20, K21, K22
8. K23 or K24

**Definitions used here**
- **PR** := #{p ∈ paths(C) : entry(I.base,p) ≠ entry(I.tip,p) ∧ entry(T,p) = entry(I.base,p)}.
- **Diagnostics:**
  - `drift` := #{p ∈ paths(C) : entry(T,p) ≠ entry(End,p)};
  - `later_commits` := `rev-list --count T --not I.tip -- paths(C)`;
  - `c_paths_in_unit` := |paths(C) ∩ paths(IU)|.

Any C row raised during the computations preempts every K row.

#### 1.8.4 Evidence table

| via | base | tip | end | seg_base | Bu | landing | attribution |
|---|---|---|---|---|---|---|---|
| ancestry-direct | parent0(C) | C | C | - | Pre | by-construction | graph |
| ancestry-merge | P^1 | P | P^2 | - | merge-base(P^1, P^2) | by-path-entry | graph |
| squash | S^1 | M | X | B_X or X_v | seg_base | by-patch-identity (integration); landing by state equality, or Option A | content-equivalent |

**UR-21 — may a squash path whose integrated file differs from the branch end be landed by line counts?**

*Context.* For a squash integration, the integrated file (Tip) often differs from the branch-end file (End) because the target also changed the same file (r ≠ e). State equality cannot then show that C's change is present. Revision 11 landed such text paths with the "carried-by-unit" check and described it as "patch identity plus counts, never either alone". The Revision 11 review showed (R11-01) that, under UR-16, the check is algebraically a count test on the squash commit's own diff:

```
Identity I-16 (if UR-16 holds):  Tip(L) − Tb(L) = End(L) − Bu(L)      for every line L at p
Carried check  ⇔  S_A(L) ≤ max(0, Tip(L) − Tb(L))  and  min(S_R(L), Bu(L)) ≤ max(0, Tb(L) − Tip(L))
```

Patch identity only selects the integration and supplies I-16. The landing evidence is net line counts, which carry no provenance (L-4). The review also showed a false MERGED under that rule (R11-02).

*Option A — count-level squash landing.* Keep count-based landing for squash text paths with r ≠ e, with the R11-02 repair:
- **Target-count guard:** every line L that C's surviving change touches must have Tb(L) = Bu(L). By I-16 this gives Tip(L) = End(L) on every touched line.
- **Carried check** (as above), as an attribution condition: the unit's own diff must contain C's change.
- Paths that are not landing-textual (any of Pre, Post, Bu, End, Tb, Tip non-textual), mode changes and uncounted changes with r ≠ e stay unverifiable.
- *What it establishes:* on the lines C touched, the integrated file and the branch end hold equal counts, and the squash diff carries C's net change.
- *What it cannot establish:* that the copy of a line in Tip is C's; that an equal count did not come from an independent equivalent change on the target; reorderings on the same file; anything if UR-16 is disproved (it is load-bearing for Option A only).
- *Cost (R13Δ, R12-03 — complete):* (1) **Guard false blocks: K31 for correct integrations** whenever the target, before the squash, changed the count of any line C touched, anywhere in the file. Common lines make this likely. Example (FX-K31n): C adds `<p>x</p>` and a `</div>` to a Blade file; the target edits another block of the same file and adds one `</div>`; Tb(`</div>`) ≠ Bu(`</div>`), so the guard fails and the result is K31 although C's lines are in Tip. `}`, `});`, `@endif` and `return;` behave the same way. **The frequency is unknown and unmeasured; measuring it on real repositories needs separate authorisation (RT-10).** Option A may therefore rescue far fewer squashes than its description suggests. (2) K33 when the guard holds but the unit's diff does not carry C's change (FX-K33b). (3) Squash becomes more permissive than an ordinary merge, where r ≠ e is never landed (L-18). (4) It cannot be adopted unless UR-16 is verified, including path binding.

*Option B — state equality only (the interim behaviour).* A squash relevant path is landed only if r = e. Otherwise it is **unverifiable → K31**.
- *What it establishes:* the integrated file equals the branch-end file at every relevant path. The same standard as ancestry merges. UR-16 is not needed for landing.
- *Cost:* every squash where the target also changed one of C's files before the squash gives K31 (AMBIGUOUS, recommend=no), including correct integrations (FX-K23aj, FX-K23am). How often this happens in SPSM is **unmeasured**. SPSM [M] uses squash for every measured case, so the cost could be high. K33 becomes unreachable.

## 6. Revert and event-ordering specification

**6.1 Patches**
- u_I = pid(I.base, I.tip); u_C = pid(parent0(C), C); r_I = pid(I.tip, I.base); r_C = pid(C, parent0(C)).
- U = {u_I, u_C} \ {NULL}; Rv = {r_I, r_C} \ {NULL}.
- If U ∪ Rv = ∅ → K15.

**6.2 Records.** For each commit Q ∈ `rev-list T --not I.tip` (≤ 5,000, else C08):
- e = pid(parent0(Q), Q) if np(Q) ≤ 1, else pid(Q^1, Q).
- A NULL e means no record. A pid failure → C11.
- Kind: **revert** if e ∈ Rv (this takes precedence when e is also in U); **reapply** if e ∈ U.

**6.3 Lineage** [P-13 · PDB: as stated; if rejected: ignore out-of-lineage reverts]
- A record qualifies iff I.lineage_root ⊑ Q.
- A revert with I.lineage_root ⋢ Q → K16.

**6.4 Event identity and carrier rules (R10-10)** [P-14 · PDB: no deduplication, so every record is its own event]

If P-14 is adopted, exactly two collapses apply, and nothing else is ever collapsed:
- **CR1 (GitLab-pair carrier).** Records for Q_M and Q_S, where (Q_S, Q_M) is a GitLab pair and both have the same kind and the same e, form one event with representative Q_S.
- **CR2 (`--no-ff` carrier).** A record for a merge Q_M (np = 2) and exactly one record Q_X with Q_X ⊑ Q_M^2, Q_X ⋢ Q_M^1, the same kind and the same e — and no other record of either kind in Q_M^2 \ Q_M^1 — form one event with representative Q_X.

**6.5 Ordering** [P-15 · PDB: total order required]
- e₁ precedes e₂ iff rep(e₁) ⊑ rep(e₂) and rep(e₁) ≠ rep(e₂). Timestamps are never used.
- No total order → K17.
- has_revert := at least one revert event exists.

**6.6 Decision order.** These run after anchoring and landing: K15 → K16 → K17 → K18 → K26 [P-22] → K19.

**6.7 Detection boundary**

| Situation | Result |
|---|---|
| Exact revert | K18 |
| Exact revert then reapply | K26 (PDB) |
| Unrelated change identical to an inverse | revert |
| Partial or drift revert | not an event; backstops are K19, K22, CV2 |
| Semantic revert | not detected |
| Revert outside lineage | K16 |
| No total order | K17 |

Absence of a detected revert never proves that there is none.

### 11.13 Classification and path binding (R11-13; R13Δ after R12-01)

### 11.18 Falsification 3 — a path that changes type during the integration (FX-K31m) — R13Δ
