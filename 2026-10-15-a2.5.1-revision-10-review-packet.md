### 1.2 Inputs

**Argument model.**
- `argv[0]` is the program name and never a positional.
- Elements are scanned left to right.
- `--` ends option parsing.
- A value-taking option consumes the next element verbatim as its value, even if that element begins with `-`.
- Any other element beginning with `-` is an unknown option (A08).
- Everything else is positional.

**Options.**
- `--repo <path>`
- `--now <TS>`
- `--trace-argv <path>`
- `--expect-origin <url>` [P-25 · PDB: not accepted, gives A08; if adopted: accepted, see R10]

**Phase A rows** (evaluated in this order; first match wins):

| Order | Row | Condition | Result |
|---|---|---|---|
| 1 | A08 | Unknown option; a value-taking option as the last element; `--opt=value`; `--now` or `--trace-argv` repeated | bad-input |
| 2 | A06 | `--repo` absent or repeated | bad-input |
| 3 | A07 | Positional count ≠ 1 | bad-input |
| 4 | A01 | C fails `^[0-9a-f]{40}$` | bad-input |
| 5 | A05 | `--now` fails the `TS` syntax, is not a calendar instant (month 13, Feb 30, hour 24, second 60), or lies outside 1970-01-01T00:00:00Z … 9999-12-31T23:59:59Z | bad-input |
| 6 | A02 | `--repo` is not absolute, contains a `.`/`..` component, or ≠ its realpath | bad-input |
| 7 | A03 | `<repo>` or `<repo>/.git` is not a real directory (symlink, `.git` file, linked worktree) | integrity-refused |
| 8 | A04 | `st_uid(.git)` ≠ euid | unsafe-ownership |

**Clocks.** Three kinds of time are kept separate.

1. **Monotonic elapsed time** (`time.monotonic`) is used only for the 60 s per-call limit (C09) and the 300 s total limit (C08).
2. **Wall-clock `now`.** Integer seconds UTC.
   - Without `--now`: floor(`time.time()`), sampled **once, immediately after snap0a completes**.
   - With `--now`: the given value. The system clock is not read for `now`.
3. **Stored timestamps.** Reflog `ts` and FETCH_HEAD mtime, written by other processes' clocks.

**Comparisons.**
- A reflog ts is compared to `now` as an integer.
- FETCH_HEAD is future iff `floor(mtime_ns/10⁹) > now`.
- 24 h means `0 ≤ now − observed_at ≤ 86400`.

**Interpretation.**
- A stored timestamp later than `now` gives CONTRA `future` (fail-closed). **That is not a claim that a race occurred.** Possible causes include a race, a backward clock step, skew between writers, or editing.
- A write after snap0a changes snap1 and is reported as D02.
- Missing timestamps: R1/F01/F09. Malformed: R2/F02/F07. Inconsistent: R3.

**Test-only inputs.** `--now`, `--trace-argv`, and a harness callback interface that exists only as a library import (phase hooks, git-result substitution, `time.time` injection). Observe never passes them.

### 1.4 Preflight

**Configuration source.**
- Read once in preflight with `config --list --show-scope -z`. Records are `scope\0key\nvalue\0`; the key is split from the value at the first `\n`.
- git emits section and key names lowercased. Subsections keep their case.
- Because of `GIT_CONFIG_NOSYSTEM=1` and `GIT_CONFIG_GLOBAL=/dev/null`, **only `local` and `command` scopes are visible**. `command` is the helper's own pins and is excluded from checks.
- `worktree` scope is refused (C04). `include` is refused (C05).
- **Global and system configuration is not read** (L-16).
- The helper never parses config bytes. The snapshot guards `.git/config`.

### 1.5 Snapshot model

**Snapshots.**
- **snap0a**: the first `snap_files()` call, producing S0f.
- **snap0b**: `snap_refs()` inside phase C, producing S0r.
- **snap1**: the final `snap_files()` + `snap_refs()`, producing S1f and S1r.

**File records**: (relpath, kind ∈ {absent, regular, dir}, st_dev, st_ino, size, mtime_ns, ctime_ns, sha256) [P-17 · PDB: include ctime and inode; if rejected: exclude them].
- Opened with `O_NOFOLLOW`; must resolve inside realpath(`.git`); ≤ 4 MiB.
- Symlinks, FIFOs, devices, oversize or unreadable entries → read failure.

**Scope.**
- `config`, `packed-refs`, `FETCH_HEAD`, and the C04 files.
- Recursively: `refs/heads/`, `refs/remotes/origin/`, `refs/replace/`, `logs/refs/remotes/origin/`.

**Ref record.**
- S0r = (T, RAW, H), where RAW = the exact output of `for-each-ref --format='%(objectname) %(refname)' refs/heads/ refs/remotes/origin/` and H = SHA-256(RAW).
- Equality compares (T, H).

**`snapshot=` (the comparison scope)**

| Value | Meaning |
|---|---|
| `full` | File and ref records were compared: equal on D00, different on D02. |
| `files-only` | S0r was never taken, so only file records were compared. |
| `none` | Phase A or B01; no comparison. |
| `final-unreadable` | D01. |

**Invariants.**
- **I-1.** Every classified line is `full`.
- **I-2.** `files-only` lets only a TOOL_FAILURE stand.
- **I-3.** Every non-`full` line carries CV4.

**phaseC.** Returns `(prov, S0r)` and never raises.

**Snapshot value by row**

| Rows | Snapshot |
|---|---|
| C01–C07 | `files-only` |
| C10 from preflight, resolve_target or snap_refs | `files-only` |
| C10 raised later | `full` |
| C08, C09, C13, C14 | by phase |

**What the snapshot detects [R].**
- Torn reads.
- Change-then-restore via ctime [UR-12].

**Residuals.** The object store; anything outside scope; coarse ticks; clock manipulation. No atomicity is claimed.

### 1.6 Freshness model

#### 1.6.1 Inputs

- Bytes and stats from snap0a; S0r.RAW; local-scope configuration.
- TR = `logs/refs/remotes/origin/development`.
- OR = all files under `logs/refs/remotes/origin/`.
- FETCH_HEAD and its mtime.
- `now`.

#### 1.6.2 Reflog grammar

```
^([0-9a-f]{40}) ([0-9a-f]{40}) [^<\n]* <[^>\n]*> ([0-9]+) ([+-][0-9]{4})\t([^\n]*)$
```

- Fields: old, new, ts (integer seconds), tz (ignored).
- cmdline = the message before the first `": "`, or the whole message if there is none.
- File order is write order; the last line is the newest.

#### 1.6.3 R rows (R10Δ: OU rewritten)

**OMS.**
- `remote.origin.fetch` has exactly one value, and it is `+refs/heads/*:refs/remotes/origin/*`.
- No other remote's fetch destination is under `refs/remotes/origin/`.

**RA (accepted reflog cmdline):**

```
RA         = fetch-form / pull-form
fetch-form = "fetch" *(SP fopt) [SP "origin" *(SP (fopt / src))]
pull-form  = "pull"  *(SP popt) [SP "origin" *(SP (popt / src))]
fopt       = "--prune" / "-p"
popt       = "--tags" / "--rebase" / "--no-rebase" / "-r" / "--ff-only"
src        = 1*(ALPHA / DIGIT / "." / "_" / "/" / "-")   ; must not begin with "-" or "."
```

- A bare form (no `origin`) counts only when origin is the only configured remote.
- **Rejected:**
  - any other remote, `.`, or a URL;
  - a `src` containing `:`, `+`, `*`, `^` or `~`;
  - options not listed above;
  - `--all` / `--multiple` [P-12 · PDB: rejected; if adopted: accepted with a single remote];
  - `update by push` [P-20 · PDB: rejected].
- A command line proves nothing about the remote's state.

**OU — origin URL policy (R10Δ).** The steps are evaluated in order, and the first decisive step sets `origin_url_class`. Comparisons are on the raw value u.

| Step | Condition | Outcome |
|---|---|---|
| U0 | `remote.origin.url` absent, or more than one value | FAIL `absent` (takes precedence over every other step) |
| U1 | Any of the following redirection keys in local scope (compared lowercased): `url.*.insteadof`, `url.*.pushinsteadof`, `remote.origin.uploadpack`, `remote.origin.proxy`, `remote.origin.vcs`, `http.proxy`, `http.*.proxy`, `http.curloptresolve`, `http.*.curloptresolve`, `core.gitproxy` | FAIL `rewritten`. **Existence and semantics of each key on 2.43 are UR-18.** Refusing a key that does not exist is harmless; a missing key is a residual (L-16). |
| U2 | u contains `\` | FAIL `malformed` |
| U3 | u matches `^[A-Za-z][A-Za-z0-9+.-]*::` | FAIL `transport-helper` (git's `<helper>::<address>` form). An IPv6 literal inside a scheme URL cannot match, because `scheme://` contains `:/`, not `::`. |
| U4 | u matches `^[A-Za-z][A-Za-z0-9+.-]*://` | scheme URL → S1 |
| U5 | u matches `^(?:[^@/:\[\]]+@)?(\[[^\]]+\]\|[^/:\[\]]+):(.+)$` and its first `:` comes before any `/` | scp form → P1 |
| U6 | otherwise | FAIL `local-path` |

**Scheme URL.**
- **S1.** Lowercase the scheme. It must be one of {https, http, ssh, git}; otherwise FAIL `scheme`.
- **S2.** The authority is the text after `://` up to the **first** `/`, `?` or `#`, or to the end. If it is empty, FAIL `malformed`. Anything after the authority (path, query, fragment) is not examined further.
- **S3.** If the authority contains `@`, the userinfo is everything up to the **last** `@`. Userinfo containing `[` or `]` → FAIL `malformed`. Remove the userinfo.
- **S4.** Host and port.
  - If the remainder begins with `[`: the host literal runs to the first `]`. What follows must be empty or `:` followed by digits. The literal must contain `:`, otherwise FAIL `malformed`. Go to H4.
  - Otherwise, if the remainder contains `:`: the text after the last `:` must be 1–5 digits forming 1–65535, and no other `:` may occur; otherwise FAIL `malformed`. The host is the text before it.
  - An empty host or an empty port → FAIL `malformed`.
  - Go to H1.

**scp form.**
- **P1.** The host is group 1, and the path (group 2) must be non-empty.
  - If the host is bracketed and its content contains `:`: if the content parses as IPv6 (H4 rules), go to H4. Otherwise it must match `^[^:]+:[0-9]{1,5}$` (host:port), and the host part goes to H1. Anything else → FAIL `malformed`.
  - If the host is bracketed and its content has no `:`, strip the brackets and go to H1.
  - Otherwise go to H1.
- **P2.** A one-character host (a drive letter) → FAIL `local-path`.

**Host checks.**
- **H1. Normalise.** Lowercase the host and strip one trailing `.`.
  - **Numeric test:** if every dot-separated label matches `^(0x[0-9a-f]*|[0-9]+)$`, go to H3.
  - Otherwise the host must match the DNS form `^[a-z0-9]([a-z0-9-]*[a-z0-9])?(\.[a-z0-9]([a-z0-9-]*[a-z0-9])?)*$` and be ≤ 253 characters, otherwise FAIL `malformed`. Then go to H5.
- **H3. Numeric IPv4 under inet_aton rules.**
  - 1–4 labels.
  - A label starting `0x` is hex; `0x` alone is FAIL `malformed`.
  - Another label starting with `0`, longer than one digit, is octal; the digits 8 or 9 → FAIL `malformed`.
  - Otherwise the label is decimal.
  - The last label fills the remaining bytes: 1 label = 32 bits; 2 = 8 + 24; 3 = 8 + 8 + 16; 4 = 8 × 4.
  - Overflow → FAIL `malformed`.
  - An address in 127.0.0.0/8 or 0.0.0.0/8 → FAIL `local-host`. Otherwise → **pass** (`network-form`).
  - Examples: `127.1`, `0x7f.1`, `0x7f000001`, `2130706433`, `017700000001` and `0.0.0.0` are all local-host.
- **H4. IPv6 literal.**
  - Parse per RFC 4291, including an embedded dotted IPv4 and `::` compression.
  - Zone identifiers (`%`) and parse failure → FAIL `malformed`.
  - Reject → FAIL `local-host`:
    - `::1`;
    - `::`;
    - `::ffff:a.b.c.d` (mapped) and `::a.b.c.d` (compatible) where a.b.c.d is in 127/8 or 0/8.
  - Otherwise → **pass**.
- **H5. Local names.** `localhost`, or any name ending in `.localhost` → FAIL `local-host`. Otherwise → **pass** (`network-form`).

**Determinism [R].**
- Every u reaches exactly one class: the steps are ordered and each step is a total function of its input.
- Classes: `network-form`, `absent`, `rewritten`, `malformed`, `transport-helper`, `scheme`, `local-path` or `local-host`.

**What OU establishes, and what it does not.**
- Passing OU means only that the **repository-local** configuration names origin with a network-form URL, that the host is not a recognised loopback or local form, and that none of the U1 keys is present locally.
- It does **not** establish:
  - that the host is public, reachable, trustworthy or canonical;
  - how DNS or `/etc/hosts` resolve the name;
  - the effect of global or system configuration;
  - environment variables at fetch time (proxies, `GIT_SSH_COMMAND`, `GIT_PROXY_COMMAND`);
  - SSH host aliases;
  - that the URL was the same when the reflogged fetch ran.

  See L-16.

#### 1.6.4 F rows (FETCH_HEAD)

**Definitions**

### 1.7 Patch identity, anchoring, landing and content — R10Δ

#### 1.7.1 Claims

- **Patch-id equality** means net-diff equivalence under the pinned diff.
- **Entry equality** means identical (mode, type, oid).
- **Line counts** are net per-file counts with **no provenance**.
- **Landing** is established structurally (§1.7.3). It is never established by counts, and it is never a claim about which individual lines in Tn are this commit's.

#### 1.7.2 DIFF and pid

```
DIFF(A,B) := git --attr-source=4b825dc642cb6eb9a060e54bf8d69288fbee4904 diff -U3 --no-relative
             --no-ext-diff --no-textconv --no-color --binary --full-index --diff-algorithm=myers
             --no-renames --ignore-submodules=none --submodule=short --src-prefix=a/ --dst-prefix=b/
             -O/dev/null <A> <B>
pid(A,B)  := DIFF(A,B) | git patch-id --verbatim
```

- 0 output lines → NULL.
- Exactly one line matching `^[0-9a-f]{40} [0-9a-f]{40}$` → its first field.
- Anything else → C11.

#### 1.7.3 Anchoring and landing (R10Δ, R9-01)

**Bu**, the branch-side base of the integration unit:

| Mode | Bu |
|---|---|
| ancestry-direct | Pre |
| squash | **seg_base**, the base of the matched segment: B_X for a first-integration match, X_v for a chained match (§1.8.2) |
| ancestry-merge | the single member of `merge-base --all P^1 P^2`. Zero members → K28; more than one → K29. |

**Anchoring rule (new; closes R9-01).**
- C is **anchored** iff Bu ⊑ Pre, **or** entry(Bu, p) = entry(Pre, p) for every p ∈ paths(C).
- Otherwise → **K32 (base-not-anchored)**.

**Why the rule is needed [R].**
- When Bu ⊑ Pre, the branch-side unit Bu → End contains C itself, so C's change is part of what the unit carries.
- When Bu ⋢ Pre (for example, a back-merge of the target into the branch after C, or a chained base on a side line), the base may already hold content that C changes.
- Requiring Bu to agree with C's own pre-image on C's paths makes the unit's diff on those paths equal to the diff from Pre. That diff begins with C's change.
- If the entries differ, the unit's diff at p no longer shows C's change. That is the R9-01 counterexamples: the back-merged hotfix H already removed or added the line.
- **The design therefore refuses to attribute rather than infer.**

**Entry types.** Entry equality compares mode, type and oid, so a mode change (`+x`), a symlink ↔ file change or a gitlink change counts as a difference.

**Landing by mode** (evaluated only for anchored C):

| Mode | `landing` | Rule |
|---|---|---|
| ancestry-direct | `by-construction` | Always landed: Tip = C. |
| squash | `by-patch-identity` | Landed, given pid(seg_base, X) = pid(S^1, S) and the GitLab-pair predicates [UR-16]. Anchoring makes C's change part of the segment's diff on C's paths, and S applies that diff to S^1. |
| ancestry-merge | `by-path-entry` | Per-path check below. |

**Ancestry-merge per-path check.** For each p ∈ paths(C), take b = entry(Bu, p), t = entry(P^1, p), e = entry(P^2, p), r = entry(P, p).

1. **Unsupported types.** If any of b, t, e, r, entry(Pre, p) or entry(C, p) has type `tree` (a directory/file conflict), p is **unverifiable**.
2. **In scope.** p is in scope iff e ≠ b.
3. **Out of scope.** An out-of-scope p (e = b) contributes no landing evidence. Anchoring makes b's content equal to Pre's, so e = b means the branch end equals C's pre-image at p: C's change at p was undone on the branch. **If C has surviving content at p, p is unverifiable.** Surviving content means S_A + S_R > 0 on p, or a surviving opaque entry (§1.7.4). That case would contradict the definitions, so it fails closed.
4. **In-scope p** (checked in this order):
   - landed iff r = e;
   - **merge-result-differs** iff r ≠ e ∧ t = b;
   - **unverifiable** iff r ≠ e ∧ t ≠ b.
5. **Result:**
   - any merge-result-differs path → **K30**;
   - else any unverifiable path → **K31**;
   - else landed.
6. **The zero-denominator rule (R10Δ).** If #in-scope = 0 and C has any surviving content, the result is **K31** (unverifiable), never landed. If #in-scope = 0 and C has no surviving content, C is superseded (K21 via §1.7.4).

**K30's meaning (R9-08).** K30 reports only that the merge result at p differs from the branch end while the target side was unchanged. That has several possible causes:
- the merge dropped C's change (`-s ours`);
- the merger added a fix-up line (an "evil merge");
- the merger dropped a sibling commit's change at p while keeping C's.

The reason token is therefore `merge-result-differs`, not `not-landed` (L-19).

**Count formulas.** The count-based landing formulas of Revisions 7 and 8 (j_miss and friends) remain **withdrawn**. Each was shown to fail on a sibling or back-merge variant (§9.2).

#### 1.7.4 Content (current-state) checks, after anchoring and landing

These run only after anchoring and landing. They compare C's surviving change with the **current** target Tn. **They are net line counts with no provenance (L-4).**

**States**

| Name | Commit |
|---|---|
| Pre | parent0(C) |
| Post | C |
| End | I.end |
| Tb | I.base |
| Tip | I.tip |
| Tn | T |

**Paths.**
- A path is **opaque** iff, in Pre or Post, it is a symlink (120000), a gitlink (160000), a `tree`, or a blob with a NUL in its first 8000 bytes.
- Opaque paths are compared by entry.
- Text paths: drop whitespace-only lines and compare byte-exact. X(L) is the count of line L in blob(X, p); ⊥ counts as 0.
- **Mode-only changes** (same oid, different mode) contribute nothing here. For merges, landing (§1.7.3) checks them by entry equality.

**Quantities**

| Quantity | Definition |
|---|---|
| A, R | max(0, Post − Pre), max(0, Pre − Post) |
| S_A, S_R | min(A, max(0, End − Pre)), min(R, max(0, Pre − End)) |
| superseded | Σ(A − S_A) + Σ(R − S_R) + opaque paths with entry(End) ≠ entry(Post) |
| k / K | Σ min(S_A, max(0, Tn − Tb)) / ΣS_A (B-18) |
| j_abs / J | Σ{S_R(L) : Tn(L) = 0} / ΣS_R |
| j_inc / J | Σ min(S_R, max(0, Tn − Tip)) / ΣS_R |
| b / B | B = opaque paths with entry(End) = entry(Post); b = members of B with entry(Tn) = entry(Post) |

**Content state** (first match wins):

| # | Condition | State | content_basis |
|---|---|---|---|
| 1 | ΣA + ΣR + #opaque = 0 | unassessable (K20) | `-` |
| 2 | K + J + B = 0 | superseded [P-06 · PDB; if rejected → insufficient] (K21) | `-` |
| 3 | K > 0 | sufficient iff k = K ∧ b = B. j_abs and j_inc are reported but not required [UR-14]. | `added` |
| 4 | K = 0, J > 0 | sufficient iff j_inc = 0 ∧ b = B [P-07 · PDB; if rejected: always insufficient] | `removed` |
| 5 | otherwise | sufficient iff b = B | `opaque` |

Insufficient → K22.

### 1.8 Integration algorithm

#### 1.8.1 Present C

```
if np(C) ≥ 3:                                  K02   [P-16 · PDB: K02; if rejected: proceed]
P := oldest X ∈ FP with C ⊑ X                  (binary search; monotone along FP)
if P = C:      I := (ancestry-direct, base=parent0(C), tip=C, end=C, integrating=C, merge=-,
                     seg_base=-, anchor=C, landing=by-construction)
elif np(P) ≥ 3:                                K05
elif np(P) = 2:
     require C ⊑ P^2 ∧ C ⋢ P^1                 else raise C12
     I := (ancestry-merge, base=P^1, tip=P, end=P^2, integrating=P, merge=P, seg_base=-,
           anchor=C, landing=by-path-entry)
else:          raise C12
→ FINALIZE(I)
```

When P = C and C is a merge commit (np = 2), C's change is diff(C^1, C) (N-19).

#### 1.8.2 Absent C

| Row | Condition | Result |
|---|---|---|
| K03 | np(C) = 2 | unsupported-merge-input |
| K04 | np(C) ≤ 1 ∧ paths(C) = ∅ | empty-commit |
| K06 | NB := `merge-base --all C T`; \|NB\| = 0 | no-common-history |
| K07 | \|NB\| > 1 | multiple-merge-bases |

**M1. Endpoints.**
- refs = `for-each-ref --contains C refs/remotes/origin/`, minus `refs/remotes/origin/{development,HEAD}` [P-04 · PDB: remote-tracking only; if adopted: plus `refs/heads/`].
- E = `rev-list C <refs…> --not T`.
- ord = the rank in a parents-before-children Kahn order on E (smallest OID first among ready nodes), counted from 0.

**Endpoint check.**
- For each X ∈ E, in ascending ord: n = |`merge-base --all X T`|. The first X with n ≠ 1 decides.
- n = 0 → **K27** (no-common-history).
- n > 1 → **K08** (multiple-merge-bases) [P-02 · PDB: K08; if rejected: drop X and continue].
- If every X has n = 1, B_X is that single base.

**M2. Target candidates.**
- RANGE = `rev-list T --not NB`.
- SSHAPE = GitLab pairs with M ∈ FP ∩ RANGE.
- SOTHER = the non-merge commits of RANGE, minus the S of each SSHAPE pair.
- PMAP_S maps pid(parent0(S), S) → pairs by pos(M). PMAP_O maps pid → commits by OID. NULL pids are dropped.

**M3–M4. First-integration matches.**
- For X ∈ E: p = pid(B_X, X).
- A pair (S, M) ∈ PMAP_S[p] is kept iff B_X ⊑ S^1 and the pair predicates hold. It becomes a V entry with **seg_base = B_X**.
- A commit S′ ∈ PMAP_O[p] gives a shape hit (X, B_X, S′).

**M5. Chaining.**
- For X2 ∈ E in ascending ord, and for each v ∈ V with X_v ⊑ X2, X_v ≠ X2, in descending (pos(M_v), ord(X_v)):
  - accept (S2, M2) ∈ PMAP_S[pid(X_v, X2)] iff M_v ⊑ S2^1, pos(M2) > pos(M_v), and v is the maximal previous entry.
  - An accepted pair becomes a V entry (X2, **seg_base = X_v**, S2, M2).

**M6. Covering.** (X, base, …) covers C iff C ⊑ X ∧ C ⋢ base. Here "base" is seg_base for V entries and B_X for shape hits.

**M7. Selection.**
- Cmin = the covering V entries with minimal pos(M).
- If Cmin contains one distinct X, select by (OID(seg_base), OID(S)).
- If it contains more than one distinct X → **K25** [P-24 · PDB: K25; (a): max brank, then min ord(X), then OIDs; (b): min ord(X), then OIDs; if rejected: K25].
  - brank = 0 if seg_base ∉ E, else 1 + ord(seg_base).
- I := (squash, base=S^1, tip=M, end=X, integrating=S, merge=M, **seg_base**, anchor=S, landing=by-patch-identity).

**No covering V entry:**

| Row | Condition |
|---|---|
| K10 | a covering shape hit |
| K11 | refs = ∅ |
| K12 | cand ≠ ∅ |
| K13 / K14 | otherwise |

cand = `rev-list --no-merges --full-history T --not NB -- paths(C)` ∪ {merges G ∈ RANGE with non-empty `diff-tree --cc --name-only -z` on paths(C)} \ {S_v, M_v : v ∈ V}.

#### 1.8.3 FINALIZE (R10Δ)

1. Compute AN (anchoring), LD (landing), EV (§6), PR and CK.
2. Decide in this order:
   - (a) K28, K29 (ancestry-merge Bu count);
   - (b) **K32** (not anchored);
   - (c) K30, K31 (ancestry-merge landing);
   - (d) K15, K16, K17, K18, K26 (events);
   - (e) K19;
   - (f) K20, K21, K22;
   - (g) K23 or K24.

**PR** = the paths p ∈ paths(C) with entry(I.base, p) ≠ entry(I.tip, p) and entry(T, p) = entry(I.base, p).

**Diagnostics:**
- `drift` = paths with entry(T) ≠ entry(End);
- `later_commits` = `rev-list --count T --not I.tip -- paths(C)`;
- `c_paths_in_unit` = |paths(C) ∩ paths(IU)| / |paths(C)|.

Any C row raised while computing preempts every K row.

**REFID construction.**
1. Strip `refs/remotes/origin/`. Under P-04, `refs/heads/` is stripped and replaced by the prefix `local/`.
2. Replace every character outside `[A-Za-z0-9._/-]` with `?`.
3. If the result is ≤ 24 characters and unique among the refs listed, use it. Otherwise use the first 7 characters, then `~`, then the first 16 hex characters of SHA-256(full refname).

This is collision-resistant, not collision-free.

```
      final := TF(snapshot-unreadable-final, D01, provisional=prov.trace, snapshot=final-unreadable)
  else:
      if S1f ≠ S0f or (S0r ≠ NONE and (S1r.T, S1r.H) ≠ (S0r.T, S0r.H)):
          final := TF(snapshot-changed, D02, provisional=prov.trace, snapshot=scope)
      else:
          final := prov with snapshot=scope                                # D00
  final.caveats := caveats(final); final.recommend := recommend(final)
  emit(final); exit (2 if final is TF else 0)

phaseC(S0f, now) -> (prov, S0r):
  S0r := NONE
  try:
      CFG := preflight()                               # config --list --show-scope -z; C01–C05
      T := resolve_target()                            # C06, C07
      S0r := snap_refs()                               # snap0b
      FR := freshness(S0f, S0r, CFG, T, now, GF=CLOSED)
      return (decide(C, T, FR), S0r)
  except HelperFailure as f:  return (TF(f.code, f.trace), S0r)
  except BaseException:       return (TF(internal, C14), S0r)

decide(C, T, FR):
  if not cat-file -e C:              return K01
  if cat-file -t C ≠ commit:         raise C15
  if np(C) ≥ 3:                      return K02
  if C ⊑ T:
      P := oldest_fp_container(C)
      if P = C:                      I := direct(C)
      elif np(P) ≥ 3:                return K05
      elif np(P) = 2:
          if not (C ⊑ P^2 and C ⋢ P^1): raise C12          # site 1
          I := via_merge(P)
      else:                          raise C12               # site 2
      return finalize(I, FR)
  if np(C) = 2:                      return K03
  if paths(C) = ∅:                   return K04
  NB := merge-base --all C T
  if |NB| = 0:                       return K06
  if |NB| > 1:                       return K07
  refs, E := M1(C, T)
  for X in E (ascending ord):
      n := |merge-base --all X T|
      if n = 0:                      return K27
      if n > 1:                      return K08
  M2(); V, hits := M3_M4(E); V := M5(E, V)
  covering := { v ∈ V : covers(v, C) }
  if covering ≠ ∅:
      Cmin := argmin_pos(covering)
      if |distinct X in Cmin| > 1:   return K25
      return finalize(select(Cmin), FR)
  if ∃ h ∈ hits : covers(h, C):      return K10
  if refs = ∅:                       return K11
  if cand(C, NB, V) ≠ ∅:             return K12
  if FR.fresh = yes:                 return K13
  return K14

finalize(I, FR):
  AN := anchoring(I)       # §1.7.3: BU_NONE | BU_MULTI | ANCHORED | NOT_ANCHORED
  LD := landing(I)         # computed only if ANCHORED; merge per-path classes
  EV := events(I); PR := paths_reverted(I); CK := content(I)
  if AN = BU_NONE:                   return K28
  if AN = BU_MULTI:                  return K29
  if AN = NOT_ANCHORED:              return K32
  if LD.differs > 0:                 return K30
  if LD.unverifiable > 0:            return K31
  if EV = UNDETERMINABLE:            return K15
  if EV = UNORDERED:                 return K16
  if EV = INCOMPARABLE:              return K17
  if EV.kind_final = revert:         return K18
  if EV.has_revert:                  return K26
  if PR > 0:                         return K19
  if CK = unassessable:              return K20
  if CK = superseded:                return K21
  if CK = insufficient:              return K22
  if FR.fresh = yes:                 return K23
  return K24
```

**Mapping.**
- Every return or raise site maps to exactly one §3 row.
- Every terminal row has at least one site.
- C12 has two raise sites; the git-derived C rows have many.
- AN, LD, EV, PR and CK are all computed before any decision, and a C row raised in any of them preempts the K rows.
- For direct and squash, AN never returns BU_NONE or BU_MULTI: Bu is Pre, or a single seg_base.

## 6. Revert and event-ordering specification

**6.1 Patches.**
- u_I = pid(I.base, I.tip); u_C = pid(parent0(C), C).
- r_I = pid(I.tip, I.base); r_C = pid(C, parent0(C)).
- U = {u_I, u_C} \ {NULL}; Rv = {r_I, r_C} \ {NULL}.
- If U ∪ Rv = ∅ → K15.

**6.2 Records.**
- For each E ∈ `rev-list T --not I.tip` (≤ 5,000, else C08): e = pid(parent0(E), E) if np(E) ≤ 1, otherwise pid(E^1, E).
- NULL means no record. A failure gives C11.
- Kind: **revert** if e ∈ Rv (this takes precedence when e is also in U); **reapply** if e ∈ U.

**6.3 Lineage** [P-13 · PDB: as stated; if rejected: ignore out-of-lineage reverts].
- A record qualifies iff I.anchor ⊑ E.
- A revert with anchor ⋢ E → K16.

**6.4 Identity.** Each record is its own event [P-14 · PDB: no dedup].
- If P-14 is adopted, D1 (GitLab pair carrier) and D2 (`--no-ff` carrier) collapse records.

**6.5 Ordering** [P-15 · PDB: total order required].
- Order is by the ancestry of representatives. Timestamps are never used.
- If the order is not total → K17.
- has_revert = at least one revert event exists.

**6.6 Decision order.** These run only after anchoring and landing have passed: K15 → K16 → K17 → K18 → K26 [P-22] → K19.

**6.7 Detection boundary**

| Situation | Result |
|---|---|
| Exact revert | K18 |
| Exact revert, then reapply | K26 under the PDB |
| Unrelated change identical to the inverse | treated as a revert |
| Partial or drift revert | not an event; the backstops are K19, K22 (current-state counts) and CV2 |
| Semantic revert | not detected |
| Revert outside lineage | K16 |
| No total order | K17 |

The absence of a detected revert never proves that no revert happened.
