## 2. Findings

### R16-01: MEDIUM. CV1 clause A (a) still claims anchoring on files outside AS
- **Section:** §1.10 CV1; §11.38; PV-28.
- **Evidence:** clause A reads "…agrees with this commit's fork point on every file where this commit's change survives to the branch end". The note beneath it says "Under (a) those files are exactly AS".
- **Counterexample.** This is a different case from §11.38's superseded-g case.
  - F0 holds f and g. On br, C adds L1 to f and swaps two adjacent lines of g (a pure reorder: A = R = 0 on g).
  - Target commit Hb edits a different line of g. After C, the branch back-merges Hb: X = merge(C, Hb), so End(g) = Hb's edit plus C's swap.
  - The integration is a squash onto Tb ⊒ Hb, with no further target change to f or g. The unit Hb → X = f + g swap, so the pids are equal. A `--no-ff` merge works the same way, with Bu = Hb.
  - Relevance:
    - f is relevant by (i).
    - g has no touched line, and (iv) needs entry(End, g) = entry(Post, g), which fails (Hb's edit is present). So g is not relevant (L-23), and AS = {f}.
  - Ht = Hb, Fk = merge-base(Hb, Pre) = F0. entry(Hb, f) = entry(F0, f), so C is anchored. f has r = e and lands. Content state 3 has k = K.
  - Result: **MERGED, basis=added, CV1 (a)**. C's reorder does survive to the branch end in g, so clause A asserts that the absorbed target state agrees with the fork point at g. In fact entry(Hb, g) ≠ entry(F0, g).
- **Impact:** a compiled interim text (a) × B states an attribution check that was not made and is false here. §11.38's "exactly AS" is wrong, and PV-28 fails. The outcome itself is not a state-level false MERGED.
- **Smallest correction:** tie clause A to the relevant-path definition, for example "…on every file where this commit's counted, mode or binary change survives to the branch end, or which is unchanged since this commit". Alternatively, add "(a reordering or whitespace-only change later edited on the branch is not included)". Add this case to §11.38.
